# AX 기업 업무사례 확장 적용 · v2.4 expansion.1

기준일: 2026-10-26. 기존 동결 v2.3 84개를 그대로 포함하고, AI가 1차 출처의 개별 업무 근거를 확인한 24개를 추가한 **108개 검색용 연구 코퍼스**다. 새 버전은 동결되지 않았으며 인간 Ground Truth나 최종 논문 데이터셋 승인을 의미하지 않는다.

## 적용 결과와 검토 범위

수집된 **8,430개 기록**(기업 페이지 1,800개, 사례포털 페이지 678개, 공공기관 활용 목록 5,952개)에 포함 기준을 적용한 1차 판정표를 저장했다. 이 숫자는 고유 사례 수가 아니다. 모든 기록의 본문을 상세 검토했다는 뜻도 아니다.

| 출처 기록 판정 | 기록 수 | 의미 |
|---|---:|---|
| 검토한 개별 업무 포함 | 19 | 19개 출처에서 24개 업무를 포함. 한 페이지의 모든 기능을 승인한 것은 아님 |
| 연구용 코퍼스에서 제외 | 6,143 | 모집단 밖 6,106개, 중복 출처 32개, 일반 목록 페이지 3개, 개별 검토 제외 2개 |
| 보류·검색에서 제외 | 2,268 | 상세 원문 검토 대기 1,558개, 접근 미해결 275개, 본문 부족 419개, 원문 검토 후 보류 16개 |

37개 출처를 AI가 원문 대조했다. 보류 자료를 쓸 수 없는 사례로 확정하거나 폐기하지 않았다. 특히 **1,558개는 원문 상세 검토가 남아 있다. 전체 사례의 정밀 검토 완료를 주장할 수 없다.** 수집 원본은 그대로 보존하고 활성 코퍼스에서만 제외했다. 발견만 하고 처리하지 않은 추가 기업 출처 3,208개는 이번 판정 범위 밖이다.

## 포함 기준

기준 문서는 [기업 실제 운영 범위](../../docs/v2-production-scope.md), [v2.3 동결 정의](../v2_3/README.md), [스키마](../schema.md), [연구계획](../../docs/research-plan.md)다.

1. 식별 가능한 기업이 수행하는 실제 업무 또는 기업 고객서비스 운영이어야 한다.
2. 해당 업무의 실제 운영을 1차 출처에서 확인한다. 제품 출시·납품·성능 소개만으로 개별 운영을 확정하지 않는다. 파일럿·계획·데모·운영 단계 미상은 포함하지 않는다.
3. 업무 문제, 대상 업무, 맥락과 실제 AI 구현을 구분할 수 있어야 한다. 단순 클라우드 이전·데이터 통합·규칙형 RPA를 AI로 간주하지 않는다.
4. 기존 F01~F11과 S1~S7에 근거를 갖고 매핑할 수 있어야 한다. 맞추기 어려우면 범주를 임의 확장하지 않고 보류한다.
5. 예상효과·시험 성과·정성 보고·운영 보고를 구분한다. 성과 부재 자체는 운영 사례의 배제 이유가 아니며, 다른 기능의 성과를 옮기지 않는다.

공공기관 자료는 실제 AI 활용 여부와 별개로 현재 기업 모집단에서 제외했다. 다른 모집단의 후속 연구에 활용할 가능성은 남아 있다. 개별 출처는 공급사 발표에 의존하므로 사실·성과의 독립 검증과 구분한다.

## 적용된 실행 경로

바탕화면 AX나침반 실행파일은 이 작업 폴더의 `run_prototype.py`를 사용하므로 재설치 없이 다음 실행부터 108개를 사용한다. 기본 Dense는 기존 BGE-M3 1024차원의 Problem / Task / Context 벡터를 각각 비교한 뒤 평균한다. 기존 84개 벡터는 그대로 보존하고 신규 24개 벡터만 별도로 계산했다. 관점별 독립 Top-K와 선택 사례 기반 전략 설명을 유지한다.

```powershell
.\.venv\Scripts\python.exe run_prototype.py
```

기존 84개 기준의 프로토타입이 필요하면 `--corpus frozen`을 사용한다. 이미 실행 중인 다른 서버가 있으면 종료 후 재실행해야 데이터셋을 바꿀 수 있다. QCI 비교 옵션은 **기존 84개 실험 재생**으로만 유지하며, 새 사례의 QCI 점수를 만들어내지 않는다. 화면과 평가 내보내기에는 실행한 자료 버전이 표시된다.

연구용 로더에서 바로 읽기:

```python
from ax_research.data import load_cases
cases = load_cases("data/v2_4/main_cases_v2_4.csv")
```

키 없는 재현 명령(프로젝트 루트, `PYTHONPATH=src;.` 설정):

```powershell
$env:PYTHONPATH='src;.'
.\.venv\Scripts\python.exe -m scripts.build_ax_expansion_release
.\.venv\Scripts\python.exe -m scripts.index_ax_expansion_release
.\.venv\Scripts\python.exe -m scripts.run_v24_retrieval --top-k 10
.\.venv\Scripts\python.exe -m scripts.validate_ax_expansion_release
```

빌드는 저장된 AI 검토·출처 감사 정보를 사용한다. 새로운 출처를 포함하려면 먼저 실제 원문을 읽고 검토 기록을 추가해야 한다. 검토한 근거 문단이 바뀌면 재검토 없이 빌드하지 않는다. 인덱스 생성은 이 PC의 `.local/models/bge-m3`가 필요하고, 자료가 바뀌면 인덱스도 재생성해야 한다. 기존 연구 스크립트의 하드코딩된 v1/v2.3 경로는 변경하지 않았다.

## 연구 해석 제한

- [새 연구 실행 결과](../../experiments/v24_expansion/run_manifest.json)는 저장된 동적 관점 97개에 대해 각 버전의 관점별 Top-10 970행을 생성한 기록이다. **관련도 정답이 없어 Recall 개선을 계산하지 않았다.** 동적 관점별 새 평가표도 10,476칸 전부 미판정이다.
- 신규 Factor·Strategy는 AI의 출처 검토 라벨이다. Problem View에 근거한 이유를 남겼으나 독립적인 Blind RCA를 수행한 것으로 주장하지 않는다. 신규 사례는 확인적 Wald 분석에 자동 포함하지 않는다.
- 기존 Dev 쿼리는 이미 사용한 개발 자료다. 독립 Test가 아니며 확장 사례를 검토·검증하면서 생긴 선택편향도 존재한다.
- 기존 사례는 영어·한국어가 혼재하고 신규 사례는 한국어이므로 언어 표현 차이가 검색 순위에 영향을 줄 수 있다. 표본 확장의 효과와 모델 자체의 개선을 분리해야 한다.
- 같은 조직의 여러 업무는 관련 표본이다. 24개를 독립 기업 24개로 세지 않는다. S5 신규 사례는 근거 부족으로 보류되어 이번 추가분은 전략 6종만 포함한다.
- 자료·평가 기록을 외부 AI에 일괄 전송하지 않았으며 이번 작업의 유료 API 호출은 0회다. 앱의 실시간 모드에서는 종전과 같이 선택된 상위 사례만 사용한다.
