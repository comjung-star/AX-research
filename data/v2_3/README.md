- F08은 보안·망분리·규제의 **사전 준수 제약**으로 기술 적용이 어려운 사례를 포함하되, 실제 법규위반 사건이 있었다는 의미가 아님.
- 동일 워크플로에서 출처로 확인되는 **다중 원인 허용**(6건); 기존 추천기술·배경 시스템까지 새로운 해결전략으로 잘못 세지 않도록 수정해 최종 다중 전략 사례는 **0건**.
- 출처 인용만으로 분류 정확도에 관한 통계적 100%를 주장하지 않음. 사용자 요청으로 **연구용 자료 버전 동결**을 실시하였으나 논문의 검색 관련도 Ground Truth 검증과는 다름.

### 특히 중요한 9건 수정
1. **BPC**: AI가 상담원 대신 전자동으로 응대한 사례가 아니라, 상담원이 문의를 입력하고 AI 답변을 검토해 고객에게 전달하는 **반복 검토/응답 부담**으로 Problem 명확화. F01/S1 유지.
2. **Kohl's**: 정보가 여러 저장소에 분산된 F02로 단정하지 않고, 표준 보고 후 추가 질문을 받기 어려운 F11로 수정.
3. **Lowe's Mylow**: 기존 URL이 점포 상담원용 *Mylow Companion* 출처였던 오류를 확인. 2025-03-05 소비자용 *Mylow* 공식 자료로 추가/교정하고 고객 프로젝트가 복잡하여 맥락형 조언과 상품연계를 얻기 어렵다는 F11 적용.
4. **Indeed**: 이미 있던 AI 매칭 알고리즘(S5)을 신규 생성형 AI 도입전략에 중복 포함하지 않고, **개인화 추천 근거 설명 생성(S7)**만 주 전략에 기록.
5. **Starling Help Center**: 고객이 키워드 검색으로 필요한 답을 찾기 어렵다는 구체 문제. F02 아닌 **F11**.
6. **Hong Leong Bank Marina**: 공식 원문에 있는 개발자 수동 KB 색인/갱신과 정적 응답 문제를 Problem View에 기록, 기존 F01/F11 복수 라벨 근거를 복원.
7. **Walmart Sparky**: 리뷰를 비교하고 상황별 제품을 선택하는 복잡한 쇼핑 맥락. 기업 사일로 F02 아닌 **F11**.
8. **Toyota Industries**: 거의 400개 변수를 분석해 도장불량 관련 요인을 좁히는 원인분석/의사결정 지원. 자동 결함 탐지 S4로 과장하지 않고 **S5**.
9. **제주은행**: 실제 내부문서 RAG 운영 S1 유지. 보안·망분리 규제 때문에 외부 GenAI를 직접 적용하기 어렵다는 F08 근거는 실제 규정위반 사례와 명시적으로 구별.
