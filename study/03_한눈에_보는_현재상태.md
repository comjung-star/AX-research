## 지금까지 확정된 사실

### 1. Multi-Perspective

- Single Dense가 못 찾던 새로운 Gold를 실제로 찾음
- 하지만 같은 Top-K에서 기존 Gold를 더 많이 잃어 총 Recall은 개선되지 않음

### 2. Multi-view Equal

- Problem / Task / Context를 분리하면 ranking은 달라짐
- 1/3 동일가중만으로는 의미 있는 Recall 개선 없음

### 3. Gated Fusion v1

- Query/Perspective별 가중치는 달라짐
- 평균: Problem 0.5998 / Task 0.0026 / Context 0.3976
- Task가 거의 0으로 collapse
- Equal Fusion보다 낮아서 v1 미채택

### 4. Hybrid Retrieval v1

- Dense와 BM25의 결과 겹침이 낮아 서로 다른 후보를 가져옴
- BM25가 새로운 Gold를 추가하기도 함
- 그러나 50:50 slot 배분에서는 same-slot Dense-only보다 평균 Candidate Recall이 낮음

### 5. Query-Case Interaction v1

- 교수 제안 [q,c,q⊙c,|q-c|] → MLP 구조를 실제 구현
- 같은 Hybrid Candidate Pool의 RRF보다 성능이 낮음
- 현재 v1 미채택

## 중요한 연구 원칙

- 교수 제안 아키텍처의 구성요소와 **현재 구현 v1의 채택 여부를 구분**한다.
- 효과가 없었던 실험도 삭제하지 않고 ablation 결과로 남긴다.
- 같은 Dev 결과를 보고 바로 가중치나 하이퍼파라미터를 맞춰 성능을 끌어올리지 않는다.
- GTQ001~GTQ010은 Dev/Pilot이며 최종 Held-out Test가 아니다.
- Ground Truth를 결과에 맞춰 수정하지 않는다.
