# 새 Validation 20문항: 사전 등록 및 현재 실행 상태

2026-11-07

## 목표
기존 Dev 8문항으로 선택한 E(기준), I2(E75%+C25%), I3(E75%+A25%)를 **새로운 20문항**에서 같은 112개 사례로 비교한다.

## 입력 고정
- 20개 업무 문제는 `questions.jsonl`에 동결한다. 기존 8문항과 텍스트 정확 중복 0건.
- 기존 사례 112개를 유지하며, 20 × 112 = 2,240개 질문·사례 관련성 판정이 필요하다.
- 기존 Test15는 열지 않고 변경하지 않는다.
- 문제는 AI 연구자가 작성했으므로 외부 독립 작성이라고 주장하지 않는다.

## 반드시 필요한 실제 작업
1. 새 문제 20개에 대해 BGE-M3·기존 검색코어로 **A/C/E의 112개 전체 순위**를 각각 새로 실행한다. E/C의 원문+고정 관점 처리, 동일 규칙, 동일 반복 3회를 적용한다.
2. 추천 방식·순위·점수를 숨긴 상태에서 20×112 관련성 판정(0~3점, 미확정 보류)을 수행한다. 두 AI가 독립 판정하고, 원문 Task/Context 근거가 맞는지 확인한다. 판정이 다른 쌍을 임의 확정하지 않는다.
3. 모든 판정·순위가 준비된 경우에만 `scripts/validation20_compare.py`로 E/I2/I3를 비교한다.
4. 각 모델 F1@5·nDCG@10·반복 안정성, 질문별 차이, 보류 영향을 분석한다. 새로운 20문항에서 더 좋은 모델을 고르면 **해당 Validation 결과로 최종 독립 Test 성능을 주장하지 않는다**.

## 현재 확인 결과
- **새로운 20문항 구성: 완료**
- **기존 개발 질문과 정확 중복 확인: 통과**
- **새 질문에 대한 BGE-M3/관점 생성 및 A/C/E 순위 산출: 미실행**
- **독립 AI 관련도 판정 2,240쌍: 미실행**
- **모델별 새 Validation 성능: 계산 불가 (입력 미생성)**

기존 실험은 Windows PC의 `../AX-prototype/.local/models/bge-m3` 로컬 가중치를 사용했다. 현재 연결된 GitHub만으로는 그 PC의 모델과 실행 환경을 사용하거나 유료 LLM 평가를 직접 호출할 수 없기 때문에, 이전 8문항 순위를 재사용해 가짜 새 Validation 점수를 만들지 않았다.

## 보존 및 재현성
- `protocol.json`: 실험 전 동결한 규칙
- `questions.jsonl`: 새 Validation 질문
- `scripts/validation20_compare.py`: 새 순위와 블라인드 qrels가 준비되면 평가를 계산할 오프라인 스크립트

## 성과 구분
이번 작업은 **20문항 검증 자료 준비 및 실험 절차 사전 등록**이지, 20문항 실측 성능 검증 완료가 아니다.
