# 성능 개선 반복 검증 원장

2026-11-08. 유료 호출0, Test15 접근0, 기존 정답/검색코어/모델 변경0. GitHub 업로드나 커밋은 하지 않았다. 아래는 저장된 실제 검색·매핑 증거를 사용한 개발 분석이다. 새 임베딩 또는 관점 생성 실험으로 표현하지 않는다.

## 이번에 수행한 것

1. 순위 점수의 요소를 하나씩 제거했다. 원래 E 순위60개 질문·반복 조합을 정확히 재현한 뒤, 규칙 제거/원문 규칙만/관점 의미 제거/관점 평균의4변형과 Dense를 비교했다.
2. 후보 수집을 Dense20 및 Dense/Sparse교대20으로 통제하고 같은 후보 내 E와 원문규칙 방식으로 순위를 매겼다. 원문 핵심 기능을 공유하는 관점만 허용하는2정책도 검증했다. 최종 출력은 모두 Top5, nDCG 이상 분모는112사례 전체다.
3. 기존 한영 기능·도메인 규칙으로 공통 토큰을 만들어 단어 검색에 추가했다. 원문/다중관점 각각에서 추가 전후를 비교했다. 새 번역이나 단어를 결과에 맞춰 추가하지 않았다.
4. 고정50:50 대신 점수 결합을 학습하는 선형 쌍대 순위 모형을 비교했다. 질문20개를 해시로5등분하고16개 학습/4개 평가하여 각 질문의 순위는 그 질문을 학습하지 않은 모형이 계산했다.3회 반복은 질문·사례별로 평균한 후 학습했다. 원문3특성 모형과 관점12특성 모형을 모두 보고했다. 이는 전체 신경망의 완성이 아닌 학습형 결합의 통제 진단이다.

## 고정 작업용 정답 기준 요약

아래 F1/nDCG는 관련 사례가 있는16질문 기준, P@5는20질문이다. 다른 정답 버전의 평균과 전후 개선률로 비교하지 않는다.

따라서 일부 개발 점수 상승은 확인했지만 사전 설정한 강건한 개선 조건은 아직 통과하지 못했다. 신뢰구간은 반복 탐색을 보정한 최종 검정이 아니다. 질문을 나눠 학습했어도 이미 반복 검토한20질문이며 사례112개는 학습/평가에서 공유하므로 외부 독립 Test라고 부르지 않는다.

## 확인된 다음 원인

- 원질문20개 중10개에서 기존18기능 규칙이 기능을 하나도 인식하지 못했다.
- 질문·반복60조합 중30개는 원문의 인식 기능과 겹치는 관점이 없었다. 기존 규칙으로 핵심 보존 관점만 제한하면 많은 질문이 원문으로 되돌아간다. 이는 실제 기능이 없다는 뜻이 아니라 현재 문법이 표현하지 못한다는 뜻이다.
- 단순히 관점 규칙을 빼거나 후보를 제한하면 일부 점수는 좋아지지만 정답 정책 변화에 취약하다.
- 언어 공통 토큰은 단어 검색에 작은 도움을 줬지만 Dense를 이기지 못했다.

다음 반복은 원문 Dense가 제공하는 신호를 지키면서, 근거가 있는 관점 신호만 학습하여 더하는 방식과 원문/관점의 의미 충실성을 원문 기반으로 진단하는 방식에 집중한다. 결과에 맞춘 무한 가중치 탐색이나 정답 변경은 하지 않는다. 독립 검증 자료가 없는 한 논문 수준의 우위 확정은 남겨 둔다.

## 확인 및 재현

### 최종 로컬 반복검증 정리

cycle12의 정답 비노출 질문 선택기는 새20질문의 nDCG를 깎아 채택하지 않았다. 후보10은 재사용 모듈 src/ax_research/token_interaction.py로 별도 정리했고, 두 자료의84개 질문·반복 순위를 모두 재현했다.18개 관련 검사가 통과했다. 요청한 네 우선순위의 로컬 분석·반복 비교·관측 개선 후보 구현과 재현을 마쳤으며, 최종 수치·근거·논문에 남은 독립 검증 조건은 improvement-results-final.ko.md에 통합했다. 독립 일반화 성능이나 논문 우위 확정으로 표시하지 않는다.

### 후속 cycle11: 구성 고정 후 기존 다른 질문으로 이전

후보10을 변경 없이 기존 CPD개발8질문에 적용했다.29건 미판정이 있는2질문을 지표에서 제외한6질문에서 F1 38.38%, nDCG65.69%로 Dense30.67%/57.75%보다 높았으나 E50.05%/78.06%보다 낮았다. 원문/관점80경로의 원래 Dense점수, 캐시 토큰 점수 및48개 새 후보 순위와전체 지표를 재현했다. 개선의 적용 범위가 질문에 따라 달라 일괄 교체는 보류하고, 질문 특성에 따른 선택 가능성을 다음 가설로 남겼다. 자세한 근거는 improvement-transfer11.ko.md다.

### 후속 cycle8~10: 처음 확인한 강건한 평균 개선 후보

의견 일치44쌍만 사용하는 학습과 실제[q,c,q*c,abs(q-c)] 벡터 신경망 모두 강건한 개선에 실패했다. 이어서 기존 로컬 BGE-M3의 단어 단위 표현을 새로 계산해 원문/관점 Dense와 결합한10차 후보에서 세 정답 버전 모두의 F1/nDCG 평균이 E와 Dense보다 높아졌다. 작업용 정답 기준 F1 26.07%, nDCG51.35%다.240개 후보 순위와3버전 지표의 캐시 재계산이 모두 일치했다. 다만 모든 해당 차이의95% 구간이0을 포함하므로 통계적·독립 검증은 남아 있다. 자세한 조건·수치·한계는 improvement-candidate10.ko.md에 기록했다. 목표 완료로 판정하지 않고 다른 기존 개발 질문 묶음에서 구성 고정 검증을 이어간다.

### 후속 cycle5~7

Dense 점수에 최대0.05만 더하거나 빼는 제한 학습도 실패했다. 작업용 정답에서 관점 포함 모형의 F1은22.45%, nDCG40.95%였다. 단순히 순위 변동 폭을 줄이는 것만으로 해결되지 않았다.

원문20질문과 E관점180개의 Dense cosine을 저장된1024차원 벡터에서 다시 계산해 원래 점수와 오차1e-6 이내 일치를 확인했다. 사례 Problem/Task/Context 벡터를 분리해 검색하고, 원문과 의미가 가까운 관점에 더 높은 가중치를 주는 비교를 했다. 관점 충실도 가중 Task검색은 최초 정답에서 F1 26.01%, nDCG49.69%로 Dense25.81%/46.94%보다 높았으며,464쌍 합의 반영에서도20.72%/42.85%로 Dense20.26%/42.09%보다 높았다. 그러나 주 기준인 작업용 전이 정답에서는22.48%/47.15%로 Dense23.20%/50.55%보다 낮았다. 따라서 정답 기준을 바꾸어 성공이라고 선언하지 않았다. 합의 반영에서 Dense 대비 차이95% 구간도 F1[-7.77,+8.80]%p, nDCG[-6.86,+8.22]%p로0을 포함한다.

작은 신경망의 헷갈리는 오답만 사용하는 학습은 작업용 정답에서 F1이0이었다. 학습 손실이 줄어도 검색 성능이 좋아진다는 보장이 없음을 확인했다. 학습쌍 표본을 점검하니16양성질문 중10개에서 양성의 평균 Dense cosine이 학습용 상위 오답의 평균보다 낮았고, 전체 평균은0.5374 대0.5438이었다. 따라서 일반 오답을 보여주지 않는 학습이 유사도 역방향을 학습할 가능성이 있었다. 동일 신경망·학습 횟수·질문 분할을 유지하고 오답을112사례 전체에서 선택한 cycle7에서 관점 신경망 F1은17.53%로 복구됐지만 기존 E나 Dense보다 낮았다. 이는 표본 편향 가설에 부합하나 그 원인이 유일하게 증명된 것은 아니다.

새 검사7개와 기존6개, 총13개가 통과했다. 원래6차 실험도 삭제하지 않고 별도 원본 결과와 소스를 남겼다. 현재까지 고정 기준에 강건한 개선은 미확정이며 목표는 계속 진행 중이다. 다음 가설은 다른 정답 버전에서도 관련/무관 판단이 일치한 학습쌍만 사용해 불확실한 전이 사례가 학습을 왜곡하는지 확인하는 것이다. 평가 정답은 그대로 유지하고 학습 표본만 조절하며, 평가할 질문의 라벨은 학습 표본 선정에도 사용하지 않는다.

새 검사5개와 기존 후보/매핑 검사6개, 총11개가 통과했다. 한영 공통 기능 인식, 부정문 실행 제외, 상수 점수 처리, 전체 정답 분모, 질문 분할 재현성, 평가 질문의 학습쌍 제외를 검사했다. 기존 추론 원본·정답은 변경하지 않았다.

각 cycle의 protocol과 results 파일을 함께 읽는다. results에는 전체 순위, 질문별 지표, 정답 버전별 비교가 있다. cycle4에는 학습/평가 질문ID, 변환 통계, 계수와 입력 해시가 있다. 스크립트는 기존 결과가 있으면 덮어쓰기를 거부한다. 동일 재실행은 별도 복사본에서 결과 경로만 바꿔 비교한다.

실행 환경은 기존AX-prototype의 Python이다. PYTHONPATH=src;. 설정 후 tests.test_improvement_cycles, tests.test_trial2_precision_evaluation, tests.test_trial2_mapping_handoff를 unittest로 실행한다. 원본 런타임 증거는 .work-new20-runtime에 남아 있어야 한다. 유료 API를 재호출할 필요는 없다.
