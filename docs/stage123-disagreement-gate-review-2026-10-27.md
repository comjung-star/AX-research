## 권장 변경 순서 (기존 Stage 결과/원본을 수정하지 않음)

1. 새 파생 실행 설정과 prompt v3 생성: 혼합 질문 배치 금지, 항목마다 query 원문, reference 원문 직접 포함. 영어 이유 상한20으로 통일. 다중 항목 중 첫 항목/중간/마지막 항목 테스트, 순서 셔플 시 등급 안정성 검사.
2. **동일한 기존 40쌍**을 모델당 같은 조건으로 다시 평가(변경 전후 비교), 필요하면 직접 관련 후보를 포함한 층화 검증 표본 추가. 바뀐 비용은 입력·출력 API usage로 재산정. 원시 v2 파일럿 원본 보존.
3. 수정 후 모델별 0~4 등급·양성률·경계 이견·모델쌍 일치율 분석. 12건 전부에 대해 재발 방지 여부 확인. 결정이 어려운 점수는 불확실 표시, 조용한 자동 승인 금지.
4. 새 버전 3모델 평가 정책·30개 reference·112개 사례 출처 검토의 게이트를 판정한 뒤, 원질문1,120쌍×3모델(3,360개 점수) 먼저 구축. 전체 reference 3,360쌍×3모델(10,080점)은 Reference Coverage를 주요 지표로 쓸 경우 검증된 reference를 대상으로 별도 진행.
5. 완결된 동일한 Query×Case Silver를 동결한 후 새 Stage2(단일 Dense/3-View/BM25)→Stage3(원질문 vs 동적 다중관점 2×2)를 실행. Stage4 독립 Test는 계속 봉인.

**완료 범위:** 위 12건 원문-평가 이유 분석, 기존 코드의 혼합질문 입력 구조와 데이터 스키마/그룹 현황 확인, 수행 전 게이트·재실행 기준 문서화. **미완료 범위:** 소스 코드 수정·실행, 새로운 비용 집계, 전수 관련도 평가, 새 Stage2·3 및 Test. 본 문서를 코드 수정 완료나 Stage 종료 증명으로 사용하지 말 것.
