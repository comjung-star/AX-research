# AX 나침반 · 사례에서 우리 업무의 전략까지

## 수정이에게 보여줄 결과

이 프로그램의 목적은 비슷한 기업 사례를 나열하는 데서 끝나지 않습니다. **업무의 어려움을 여러 관점으로 나눈 뒤, 실제 기업의 해결 방식을 근거로 우리 업무에 어떤 전략을 어떻게 적용해 볼지 설명하는 것**입니다.

바탕화면의 **AX나침반.exe**를 실행하거나 실행 중인 [AX 나침반](http://127.0.0.1:8765)을 엽니다. 기존 실행파일을 그대로 사용합니다. 현재 PC의 프로젝트·Python 환경을 연결하는 실행기이므로 exe만 다른 PC로 복사하는 배포본은 아닙니다.

### 5분 시연 순서

1. **문서 심사** 예시를 선택하고 **새 문제 분석 · 실시간 AI**인지 확인합니다.
2. **AX 전략과 사례 보기**를 누릅니다. 첫 실행은 로컬 모델 로딩 때문에 약 1분 이상 걸릴 수 있습니다.
3. 가장 위에서 **우리 업무의 추천 방향과 먼저 해볼 일**을 봅니다.
4. 각 문제 관점의 **적용 전략 → 실행 순서 → 준비할 것 → 적용 전 확인할 점**을 읽습니다.
5. **왜 이 전략인가요?**의 기업 링크를 눌러 실제 사례로 이동합니다. **이 기업은 이렇게 해결했어요**와 **출처에서 보고한 변화**는 사례 사실이고, 위의 실행 순서는 우리 업무에 대한 제안입니다.
6. **전략 보고서 내려받기**로 결과 문서(Markdown)를 받습니다. 저장 동의 후 **유용함 / 부분적 / 무관**과 자유의견도 기록하고 CSV·JSON으로 내보낼 수 있습니다.

## 실제 생성한 출력 예

입력: “심사와 검증 업무에서 여러 형식의 문서를 사람이 읽고 필수 항목과 규정 준수 여부를 일일이 확인해야 해서 처리시간이 길고 누락이나 오류 위험도 높다.”

실제 API 검증에서는 **3개 문제 관점과 6개 적용 전략**을 생성했고, 추천 전략은 **4개 근거 사례**에 연결되었습니다. 해당 실행의 관점 생성·로컬 Dense 검색·전략 작성 총 소요시간은 **96.41초**였습니다. 요청마다 관점·전략·시간은 달라질 수 있으며 성능 벤치마크가 아닙니다.

최종 방향: 문서의 필요한 항목을 추출해 기준별 확인을 돕고, 반복 가능한 후속 처리는 자동화하되 예외와 최종 판단은 사람이 검토하도록 제안했습니다.

첫 행동: 최근 심사 건 몇 건에서 문서 종류·필수 항목·적용 규정·검토 결과를 표로 정리해 자동 확인과 사람 판단의 경계를 구분합니다.

## 연결한 처리 흐름

```text
자연어 업무문제
→ 실제 LLM의 동적 문제 관점 분해
→ 기존 BGE-M3 Problem / Task / Context별 Dense 점수 평균
→ 관점별 독립 Top-K 사례
→ 각 관점의 상위 3개 이내 사례 근거 선택
→ 허용된 frozen 전략 분류 안에서 LLM이 적용 전략 작성
→ 실행 순서·준비사항·한계·근거 사례·원문 출처
→ 전략 보고서 / 사례 평가 / 자유의견 저장·내보내기
```

관점별 순위와 가지를 유지합니다. 기본 검색은 Dense이며 학습형 256d QCI는 기존 예시 실험 결과의 선택적 재생으로만 남았습니다. 검색 시 Solution View로 관련도를 계산하지 않고, 검색을 마친 뒤 선택된 사례의 구현·성과를 전략 설명에 사용합니다.

출력 검증은 관점 ID, 동일 관점 안의 인용 사례, 인용 사례가 실제로 가진 전략 분류, 선택 사례 요약의 일치 여부를 검사합니다. 검증에 실패하거나 API가 응답하지 않으면 사례 검색을 보존하고 **사례 기반 시연 설명**으로 명확히 표시합니다. AI 작성이 성공한 것처럼 보이지 않습니다. 이 검증은 출력 구조와 근거 ID의 일관성을 확인하며, 설명 문장 전체의 사실성을 보증하는 별도 인간 평가가 아닙니다.

## 키가 없거나 네트워크가 안 될 때

**분석 방식 → 키 없이 체험 · 데모**를 선택합니다. 제공된 예시는 저장된 LLM 관점과 실제 Dense 점수 계산을 사용합니다. 적용 전략은 frozen 전략 라벨과 미리 정한 안내 틀로 제시하며 **사례 기반 시연 설명**이라고 표시합니다. 외부 API를 호출하지 않습니다. 자유 입력은 준비된 로컬 모델의 Dense 탐색으로 동작합니다.

## 검증·자료 보존·보안

- 전체 **201개 테스트 통과**: 프로토타입 40개 + 기존 연구 161개. 기존 Torch 경고 1건은 그대로 남겼습니다.
- 전략 근거의 관점 간 혼합, 없는 사례·전략 인용, API 실패 대체 표시, 선택 사례만 전송, 키 비노출, 일본어 문장 혼입 차단 등을 검증했습니다.
- 실제 OpenAI API의 관점 생성부터 Dense 검색, 전략 생성과 보고서 저장까지 성공했습니다. 결과 JSON의 `strategy_report.api_evidence`에 모델·응답 ID·토큰 사용·`store=False` 실행 증거를 남겼으며 키 값은 포함하지 않았습니다.
- 브라우저용 전략 보고서 생성 함수도 실제 결과로 실행해 전략·실행 순서·사례 해결 방식·출처·방식 안내·키 비노출을 확인했습니다.
- frozen 84개 원본과 기존 연구·실험 파일 1,496개를 변경하지 않았습니다. 한국어 설명과 추천 코드는 별도 `prototype/`에 있습니다.
- 승인받은 **선택 사례만** OpenAI API로 전송합니다. 전체 데이터셋이나 평가 기록을 보내지 않습니다. API키는 인증에만 사용하고 프롬프트·결과·평가에 넣지 않습니다. 로컬 `.env`는 Git 제외 상태입니다.
- GitHub의 기존 결과를 보존했습니다. 이번 구현은 로컬 작업본이며 요청 없이 commit/push하지 않았습니다.

이번 결과는 **교수님 아키텍처가 지향하는 최종 출력 형태를 체험하는 실행 프로토타입**입니다. 학습형 Factor Anchor·Evidence Fusion·Wald 통계 판단까지 검증한 완성 연구모델이라는 뜻은 아닙니다. 우선순위는 검토 순서이며 성공 확률이 아닙니다. 외부 기업의 성과는 출처의 보고 내용이지 사용자 업무에 대한 효과 보장이 아닙니다.
