# 새 독립 검증 사전 계획

후속 변경: 사용자가 사람 검토 없이 Claude 질문 생성과 AI 검증을 요청했다. 아래는 원래 사람 기반 계획이며, 현재 실행은 AI_PILOT_AMENDMENT.ko.md와 ai_pilot/의 원본·영수증·결과를 따른다. 사람 작성·검토를 수행한 것으로 표시하지 않는다.

상태: 모델·비교 코드의 해시 고정 및 표본 수 계획 완료. 새 독립 질문0개, 사람 관련성 판정0개, 새 성능 결과0개. 정답이나 질문을 이 연구를 수행한 AI가 작성하고 독립 자료라고 표시하지 않는다.

## 고정 비교와 판정

원문 Dense, 기존 E, 후보10 원문 토큰 Hybrid, 후보10 원문+관점 토큰 Hybrid를 같은112사례·Top5출력으로 비교한다. 관점은 기존 고정 프롬프트와 모델 정책으로3회 생성하고 질문별 평균 후 질문 단위로 분석한다. 런타임 관점과 평가용 참조 관점을 섞지 않는다. 기존 Test15는 사용하지 않는다. 토큰 비교의 추가 실행 비용과 관점 생성 비용도 별도 기록한다.

공동 주요 지표는 F1@5와 nDCG@10이다. 후보의 Dense/E/원문토큰 대비3비교×2지표=6개 대비를 사전에 고정한다. 확정 우위는 각 대비의 질문별 차이에 대해 양측 Bonferroni 보정 구간(각99.1667%, 가족오류율5%) 하한>0일 때만 선언한다. 전체 모델 우위는 Dense와 E 대비4대비 모두 통과해야 하며, 다중관점 기여는 원문토큰 대비2대비도 통과해야 한다. 특정 대비만 통과하면 그 범위로 주장한다. 실용적 효과 크기와 불확실성도 함께 보고한다. 여러 생성 반복을 독립 질문으로 세지 않는다.

F1/nDCG는 전수 판정된 질문 중 관련 사례가 있는 공통 집합에서 계산한다. 보류나 미판정이 남은 질문은 두 지표의 공통 집합에서 제외하며 제외 수와 이유를 모두 공개한다. 관련0개 질문은 P@5와 부적절 추천 비율을 별도 보고하고 F1/nDCG를 임의0점으로 채우지 않는다. 전112사례의 이상 이득을 nDCG분모로 사용한다. 자동으로 낮은 성능 질문을 빼거나 다른 질문으로 대체하지 않는다.

## 필요한 질문 수와 현실적인 순서

sample_size_planning.json은 기존16~18개 질문의 대응 표준편차로 계산한 정규근사 참고값이다.80%검정력은 각 대비의 가정이지6대비 동시 통과 확률80%가 아니다. 참 효과를 F1+5%p·nDCG+3%p로 놓으면 Dense 대비 약73~208개 양성·완전판정 질문, E 대비 최대1104개까지 나온다. 이는 작은·반복 검토된 개발 자료의 변동성 추정에 매우 민감하며,1104개가 확정 필요 수라는 뜻은 아니다. 효과 크기1/3/5/10%p별 민감도도 저장했다. 원리는 NIST 정규근사 표본 수 식을 대응 차이에 적용한 것이다: https://itl.nist.gov/div898/handbook/prc/section2/prc222.htm

따라서40개로 최종 입증을 보장하지 않는다. 첫40개는 독립 작성·판정 기준·실행 가능성을 점검하는 예비 검증으로 분리한다.40개×112사례=4480쌍을 두 검토자가 독립 판정하도록 빈 서식을 준비했다. 예비 결과를 보고 방법을 수정하면 그40개는 개발 자료가 된다. 방법을 수정하지 않아도 최종 Test와 섞어 확정 표본이라고 부르지 않는다. 별도 최종 Test의 표본 수와 모형 해시는 예비 단계 뒤 다시 사전 고정한다.

## 독립 작성·검토 절차

질문 작성자는 모델별 결과·이전 연구 대화·사례 목록을 받지 않고 실제 업무문제를 자연스럽게 작성한다. 산업이름만 바꾼 중복 질문, 특정 사례를 정답으로 유도한 질문은 받지 않는다. 검토자는 질문과 사례 Problem/Task/Context 및 근거 식별자만 받는다. 추천 모델명·순위·점수·기존 정답·전략 가설을 제공하지 않는다. 원천의 수행 여부가 불명확하면 보류한다.

두 검토자는 서로의 점수를 보기 전에 판정을 봉인한다. 이견은 원문 근거와 아래 기준으로 조정하고, 해결되지 않으면 보류한다. 사람 검토가 없으면 AI-Silver로 표시하고 Human-Gold라고 쓰지 않는다. 작성·검토자의 실제 독립성은 선언만으로 입증되는 것이 아니므로 역할·노출 이력·시간과 근거를 남긴다.

0=실제 처리 동작이 다름;1=기술/목적/보조 작업만 유사;2=질문의 핵심 처리 동작을 사례 Task의 구체적 근거로 전이할 수 있음;3=입력·대상·출력까지 직접 일치. 양성은2이상이다. 현재 감지와 미래 예측, 문서 개인정보와 영상 사람 익명화, 차량 경로와 티켓 배정을 이름만 비슷하다는 이유로 같은 작업으로 인정하지 않는다. Problem에 필요한 작업이 적혀 있어도 Task가 실제 수행했다고 추정하지 않는다.

## 현재 실행 경계

새 독립 작성자와 검토자는 아직 지정되지 않았다. author/와review/의 파일은 빈 제출 서식이며 실제 질문/정답이 아니다. 고정된 기존 LLM으로 새 관점을 생성하는 단계도 아직 실행하지 않았다. 기존의 새 유료 API 금지 조건을 유지하며, 이 계획 승인이 비용 지출 승인으로 바뀌지 않는다. 사람이 쓴 관점을 기존 LLM 관점이라고 바꿔 표시하지 않는다. 관련성 정책·실험 규모·생성 실행 조건을 확정한 뒤 실제 입력을 받아야 추론을 진행할 수 있다.
