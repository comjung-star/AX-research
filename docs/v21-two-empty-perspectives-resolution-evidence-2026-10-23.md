# AX v2.1 | 두 개의 '관련 사례 0건' 관점 — 보완 근거 확보 및 평가 처리 기록

**작성일:** 2026-10-23 (KST)  
**작업 브랜치:** `audit/main-dataset-v1-case-unit-review` (Draft PR #3)  
**분류:** SOURCE-COVERAGE AUDIT / EXTERNAL CANDIDATE SCREEN — **새 Ground Truth나 동결 코퍼스 변경 아님**

## 1. 현재 확인된 문제

- v2.1 연구 코퍼스는 원천 적격 운영 업무 사례 **91건**으로 동결. 보류 7건은 기존 ledger에 유지.
- 10 Dev 질문 × 3 초안 Reference Perspectives × 91건 = 2,730개 **AI 예비 관련도** 점수. 인간 독립 adjudication은 0건.
- 예비 Gold 기준 3~4점 사례가 없는 관점은 정확히 두 개:
  - `V21D006 / P1_CATALOG_ENRICHMENT_BURDEN` (상품 속성 분류·태깅)
  - `V21D009 / P1_AI_SECURITY_COMPLIANCE_CONSTRAINT` (외부 AI의 정보보안·규제 제약)
- 각각 예비 2점 사례 3개, 7개가 있으나 단순한 주제 유사성만으로 강한 관련성으로 승격하지 않음.
- 이 상태는 **코퍼스 내 AI 예비양성 사례 미발견**이며, 논문에서 '현실에 그런 AX 사례가 없다' 또는 '검색기가 실패했다'라는 사실로 해석하지 않는다.

기존 내부 감사: [두 무정답 관점 원인 분석](v21-two-empty-perspectives-source-audit-2026-10-23.md)

## 2. 문제 1 — V21D006 / P1 (상품 카탈로그 태깅)

**원인:** 기존 v1 `AX0079` Wayfair의 직접 관련 사례가 v2.1의 91건에는 없으며, 현재 2점 후보 3건은 다른 업무(교육, 자동차 부품 라벨 검사, 보험 문서 분류)다.

**새로 확보한 외부 보완 후보:** Wayfair, [Google Cloud 사례](https://cloud.google.com/customers/wayfair-ai).

- **Problem:** 신규 상품의 색상·스타일 속성을 사람이 태깅하고 제품 등록/수정을 수행하는 부담.
- **Task:** Gemini 기반 상품 속성 자동 분류·카탈로그 정보 보강.
- **Context:** 3,000만 개 이상의 상품을 취급하는 전자상거래 카탈로그.
- **Outcome (출처의 보고):** 상품 목록의 신규 등록/수정에 필요한 정보 정리 시간 약 67% 단축. **공급사 제공 자료의 성과 주장**으로 제한하며 독립적 효과 검증이라고 쓰지 않는다.
- **평가:** 문제 관점과의 명시적인 업무 대응 근거가 존재하는 *source-screened 외부 후보*. 현재 91건에는 불포함, 현재 GT 점수 없음. 과거 v1 판단을 가져오지 않는다.

**처리:** 현행 91건에서 강제 Gold 추가 금지. 이후 새 코퍼스 버전을 연구자가 별도로 승인하는 경우에만 원천 검수와 독립 Blind Problem-View 평가를 거쳐 포함 검토.

## 3. 문제 2 — V21D009 / P1 (외부 AI 보안 제약)

**원인:** v2.1의 BPC 사례 `AXV2H_0071_01`는 공식 AWS 원문의 규제/데이터 보호 맥락이 존재하지만, 동결된 Problem/Task/Context의 주업무는 **기술지원 답변과 모델 비용**이다. 해당 사례가 '외부 상용 AI를 사용할 수 없어 온프레미스로 전환했다'는 증거는 아니며, **AWS Bedrock = 온프레미스**도 아니다.

**새로 확보한 외부 보완 후보 A:** 제주은행, [Plateer AI Labs 구축사례](https://labs.plateer.com/en/customers/case/jeju-bank-genai-platform).

- **Problem:** 은행의 규제, 엄격한 망분리·보안 조건으로 외부 생성형 AI를 그대로 업무에 적용하기 어려움.
- **Task:** 은행 내부 인프라에 자체 생성형 AI 플랫폼을 구축하고 임직원용 에이전트를 운영.
- **Context:** 은행의 망분리 온프레미스 환경, 준법감시·감사·소비자 보호 등 업무 적용.
- **Deployment (출처의 보고):** XGEN 기반 내부 온프레미스 운영, 내부 문서 지식베이스 및 업무시스템 API 연동.
- **주의:** 구축사의 고객사례이며 은행의 독립 검증 문서나 정량적 성능감사는 이번 screening에 포함되지 않음. 그래도 **'온프레미스 실제 운영'을 명시**하므로 BPC보다 질문의 보안/설치 맥락에 직접적.

**새로 확보한 외부 보완 후보 B:** Home Credit Bank, [Google Cloud 사례](https://cloud.google.com/customers/homecreditbank).

- **Problem:** 직원의 비승인 외부 AI 사용, 데이터 유출 위험, 금융권 고객정보 보호 규제.
- **Task:** 관리·보호되는 Gemini Enterprise 환경에 업무용 AI 에이전트 배치.
- **Context:** 금융권 데이터 규제 및 고객정보 관리.
- **주의:** 보안 제약 해결에는 관련되지만 **온프레미스 도입 사례는 아님**. '보안 제약'과 '온프레미스 의무'를 별개 조건으로 판단해야 한다.

**현재 91건 BPC 판정:** 원문과 Problem View 불일치를 별도 기록하며, 추가 점수·문구 수정은 **하지 않음**. 독립 평가자가 원문-업무단위 일치 여부를 판정하기 전 자동 관련도 2→3 승격 금지.

## 4. 본 작업에서 실제로 반영한 조치

1. **외부 후보 3건**을 [별도 CSV 원장](../data/v2_1/qa/external_coverage_gap_candidates_2026-10-23.csv)에 저장. 2개 평가 관점에 대한 source URL, 정확한 Problem/Task/Context, 배포 형태, 근거 위치, 제한점을 분리 기입.
2. **v2.1 기존 데이터·manifest·2,730개 AI 예비평점·91개 사례·보류 7개는 일절 변경하지 않음.**
3. `scripts/v21_evaluate.py`에는 이미 최종 인간 adjudication 완료 뒤에만 **진짜 Gold 0인 Perspective를 별도 노출하고 Coverage 분모에서 제외**하는 정책이 있으며, `tests/test_v21_unanswerable_policy.py`에 synthetic 검증이 기록되어 있음. 이것은 성능 개선이나 무정답 탐지 실력 증명이 아님.
4. 현행 코퍼스로의 테스트 성능은 **여전히 NOT READY**. 추가 후보가 있다고 유효한 데이터셋 Recall@K가 새로 계산되지는 않음.

## 5. 최종 처리 원칙 / 별도 버전으로 보완할 경우

| 연구 선택 | 처리 | 논문 해석 |
|---|---|---|
| **현재 동결 91건 유지** | 두 관점의 0-Gold 가능성을 인간 독립 평가로 확인; 확정 시 unanswerable로 분리 보고 | 코퍼스가 커버하지 못한 문제범위이며 검색기 실패와 구별 |
| **새 사례를 추가하는 보완 데이터 버전 제안** | Wayfair·제주은행·Home Credit 후보를 별도 원천검증하고 변경 이력/ID/버전/Case단위/샘플링 군집 검토; 새 Dataset 명시 | **새 코퍼스는 다른 실험 조건**. 기존 91건의 결과와 동일시하지 않음 |
| **평가 질문을 바꾸는 신규 벤치마크** | 현재 10 Dev 질문 보존; 새 질의·문제관점은 모델 결과를 보지 않고 독립적으로 선등록 | 성능에 유리한 사후 질의 교체 금지 |

**중요한 selection-bias 주의:** 이미 '정답이 비어 있다'는 Dev 결과를 본 뒤 특정 기업을 찾아서 같은 Dev의 Gold와 모델 성능을 끌어올리면 편향될 수 있다. 외부 사례를 후속 코퍼스에 넣더라도 새 평가 데이터 및 비교 범위를 명확히 구분하고, 모델 설정과 질의 선정 기준을 사전에 동결해야 한다.

## 6. 검수 체크

- 기존 사례 JSON/CSV와 manifest의 Git blob SHA를 건드리지 않았음.
- 원래 예비 0개라는 사실을 숨기거나 점수를 바꾸지 않았음.
- 제주은행은 **온프레미스 구축 근거가 있음**, Home Credit은 **규제형 관리 클라우드**, BPC는 **AWS 클라우드**로 구분함.
- 최종 인간 Ground Truth 승인·새 Recall@K·Strategy Coverage·Held-out 성능은 **없음**.
- **후속 단계의 주 결정:** 동결 91건으로 진행하며 커버리지 한계를 명시할지, 별도 버전의 실제 운영 사례 보완을 승인할지. 둘을 혼합하지 않음.

**최종 판단:** 두 '빈 관점'의 원인을 식별하고 각 관점에 정확한 외부 실제 운영 후보를 확보한 **원천 증거 단계의 해결**이다. 현재 91건 벤치마크 내부의 Gold 0을 인위적으로 해소한 것으로 기술하지 않는다.
