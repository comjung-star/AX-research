# AX v2.3 Stage 1 — Multi-Perspective 고유 관련사례 회수 재분석

날짜: 2026-10-24
분석 유형: **이미 실행·동결된 Stage 1의 검색순위/AI-Silver 라벨에 대한 사후 진단**. 새 모델 실행, 정답 수정, 원래 Stage 1 결과 변경은 없음.
원본 릴리스: `release/ax-v2.3-stage1-to4-dev-20261023`; 2026-10-23 Stage 1 성공 실행 `39952604227`.
기준: 84건 AX 업무사례, 개발 문제 10개, LLM 실행 3회(질문별), 참조 관점 각 3개, AI-Silver relevance >=3, BGE-M3, Top K={5,10,20}.
반복 실행 30쌍은 **독립된 30개 질문이 아니며**, 각 질문의 단일 Dense run 0 순위와 해당 질문의 다중 관점 run 1/2/3을 각각 비교한다.

## 1. 사전에 고정했던 Stage 1 목적과 본 진단의 위치

RQ1의 사전 정의에는 Single Dense 대비 관련사례 `Recall@K`, `Perspective Coverage@K` 및 단일 검색이 놓친 새로운 관련사례 회수(`Unique Gold Recovery`) 확인이 함께 포함된다. **새로운 사례를 무조건 많이 반환하는 것**은 목적이 아니다. 서로 다른 문제관점과 **실질적으로 관련된** 사례를 찾는지를 확인해야 한다.
이 재분석은 독립적 Test 및 인간 Gold 판정이 아닌 **개발용 사후 진단**이며, 원래 Primary metric을 결과에 맞춰 변경하거나 통계적 우월성을 새로 주장하지 않는다.

## 3. 방법

질문 `q`마다 단일 Dense `run_id=0`의 Top-K 집합을 `S(q,K)`, 다중 관점 Dense `run_id=1..3` 각각의 Top-K를 `M(q,r,K)`, AI-Silver 양성 사례의 합집합을 `G(q)`라 한다.

- **다른 검색 사례**: `M \\ S` (단일 Dense Top-K에 없는 사례; 관련성 무관)
- **신규 관련사례 회수**: `(M \\ S) ∩ G` — MP-only Relevant
- **기존 관련사례 누락**: `(S \\ M) ∩ G` — Single-only Relevant
- **순 관련사례 증감**: 위 두 값의 차이
- **참조 관점 고유 사례**: 양성으로 판정된 질문의 참조 관점이 정확히 한 개뿐인 사례; 'LLM이 새롭게 발명한 관점'이라는 의미는 아님

상위 K의 출력 예산을 Single/MP 동일하게 통제한다. 반면 개별 MP branch의 local Top10 **합집합은 평균 22.13개**여서, 이 집합은 후보 잠재력 진단에만 사용하고 단일 Dense Top10과 공정한 최종 출력 성능으로 직접 비교하지 않는다.

3. **V21D004 → Cashfree Payments `AXV2C_0074_02`**: 가맹점 온보딩 규정·위험 검토; P2 컴플라이언스 관점 4점, P3 반복 검증 3점. 두 실행 MP-only.
4. **주의할 예: V21D002 → Stripe `AXV2N_0134`**: 원문 문제는 이메일 스레드 요약이지만 이 사례는 상점 웹사이트 요약. P3 평가 3/2/3으로 양성 경계 변동이 있는 사례.
5. **주의할 예: V21D009 → Oscar Health `AXV2N_0137`**: 내부정보 접근 관점 3/3/3이지만 질문의 핵심 보안·전사 AI 확산과의 일치 정도는 별도 확인 필요.

19개 Silver 양성 출현 중 **7개 출현**은 하나 이상의 양성 참조 관점에서 3점 경계를 넘나드는 3회 AI 판정이 있었음(`threshold_flip=1`). 이 중 4개 출현은 그 사례의 모든 양성 참조 관점이 경계 변동. 반복 출현을 독립 평가의 수로 오해하면 안 된다.

## 5. 관점별 후보 발굴과 최종 Top10 병합 효과

저장된 `branch_rankings.csv`로 관점별 local 순위를 순환하며, 이미 선택한 사례를 건너뛰는 `branch-balanced unique` 알고리즘을 재현했다. **30개 MP 실행의 전체 Top10과 위치까지 30/30 완전 일치**. 따라서 현재 진단의 최종 선택 방식 해석은 실제 저장된 출력과 일치한다.

개별 관점의 local Top10을 **합집합**으로 만든 후 기존 Single Top10과 비교(30회 합산)하면:

- branch 후보 합집합 크기: 실행당 **평균 22.13개** (최종 출력 예산 Top10보다 큼).
- branch 후보군에는 Single Dense Top10에 없는 Silver 양성 사례가 **76회 출현**했다.
- 이 중 **19회 출현**만 최종 MP Top10에 남았고, **57회 출현**은 최종 Top10에서 선택되지 않았다.
- 기존 Single Top10의 Silver 양성 중 **24회 출현**은 branch local Top10 후보군에도 있었으나 최종 MP Top10에서 선택되지 않았다.
- 참고: 최종 MP-only Silver 양성 19개의 선택 branch 귀속은 P1=4/P2=8/P3=6/P4=1(30회 전체 합산). 이는 LLM 생성 관점의 품질을 판정한 수치가 아님.

**해석:** 관점별 검색 branch 자체가 새 관련사례 후보를 찾아내는 사례는 존재한다. 최종 Top10으로 제한하는 과정에서 그 후보 중 일부만 유지된다. 이것이 특정 결합법의 본질적 결함 또는 최적 대안의 우월성을 증명하지는 않는다. 후보군 크기와 Top10 예산이 달라 '76 vs 19'를 시스템 대 시스템 성능 비교로 쓰면 안 된다.

## 6. 결론과 다음 검증 가설

**지지되는 관찰:** v2.3의 MP Dense는 단일 Dense가 놓친 AI-Silver 양성 AX 사례를 실제로 새로 회수했다. 따라서 단순한 전체 Recall 하락을 근거로 '다른 관점의 새 사례를 전혀 찾지 못한다'고 할 수 없다.

**동시에 드러난 한계:** Top10에서 신규 양성 19회 출현보다 누락 양성 39회 출현이 더 많다. 기존 Coverage 및 Recall이 개선된 것은 아니다. '새로운 관련사례'는 3개 사전 참조 관점 중 하나 이상에서 AI-Silver 양성인 경우를 뜻하며, **참조에 없는 완전히 새로운 유효 관점 발견**까지 입증하는 것은 아니다.

**가설/차기 실험:**
1. 검색 입력: v2.3 본실험은 제목만, v1 본실험은 관점 제목+설명. 둘의 평가자료 및 코퍼스가 다르므로 버전 간 수치를 직접 인과 비교할 수 없다. 이미 완료된 v2.3 입력 진단을 참고하고 새 변경은 사전등록.
2. 병합법: 관련 사례를 별도 후보군에서 얼마나 보존하면서 새로운 관점 고유 사례를 포함하는지, **동일한 최종 TopK·동일 모델/라벨**로 대안 결합법을 독립 비교.
3. 관점의 실질적 새로움: 생성 관점의 질의 근거성·중복도·사례의 외부 유용성을 블라인드 평가하도록 개발 기준과 held-out Test 기준을 구분. 정답 라벨을 결과에 맞춰 바꾸거나 사후 진단을 확증 성능으로 승격하지 않음.
4. 교수 제안 아키텍처의 branch 보존 및 Multi-view/Gated Fusion 목적 유지. **RRF를 제안 아키텍처의 필수 구성요소로 오인하지 않음**.

**평가 제약:** AI-Silver 2,520개는 인간/독립 Test Gold가 아니며 v2.3 코퍼스는 이전 Dev 탐색에 영향을 받은 선택편향을 포함한다. 동일 질문의 3회 반복은 독립 표본 N=30이 아니다. 명세 변경 없이, 과거 Stage1~4 및 Frozen corpus/GT는 그대로 보존한다.
