# 기능 비교 전 점검 — 아직 매칭 점수 생성 전

질문 없이 추출한18사례×3종의 실제 행동 문구와 원문을 대조했다. 짧은 추출·요약·문의답변·검증 등의 실제 작업은 대부분 보존됐으나, 보조 family 분류명에는 오류가 있었다. 예를 들어 실제 행동 문자열은 ‘adjust production schedules’인데 ANSWER로 분류하거나, 광고 이미지 생성을 INTEGRATE로 분류했다. 분류명을 그대로 채점 기준으로 쓰면 오히려 실제 기능을 잘못 판단할 수 있다.

따라서 사용자 원칙대로 분류 체크박스를 점수 근거로 사용하지 않는다. 이는 매칭 점수나 검색 결과를 보고 점수를 맞춘 변경이 아니다. 아직 질문별 매칭/파일럿 계산 점수는 생성하지 않았다. 원래 추출 응답과 보조 분류 오류는 전부 보존한다. 매칭 입력에서 분류명을 가리고 실제 행동·대상·산출물·Task/Context 원문을 보여준다. 기능 비교 이유와 원문 의미를 파일럿에서 검증한다.

점수3은 원문에 연결된 실제 작업, 기능적 A/O/O 동등성 및 비교 이유를 요구한다.4는 기존처럼 추가로 서로 다른 원문 작업/핵심 과업 또는 사전 원문 확인한 문제 조건을 요구한다. 분류명 일치 개수나 단어 겹침으로 점수를 주지 않는다. 내부 점수규칙 버전은 functional-evidence-v14다. 모델이 추출한 축약 문구의 부정확성도 원문과 대조하고, 실제 없는 작업을 매칭 단계에서 새로 만들지 못하게 한다. 같은 모델의 근거만 매칭에 사용하며 타 모델 판단은 공유하지 않는다.

Gemini의 닫는 배열 괄호 누락은 문자열·숫자·ID·키를 하나도 추가/수정하지 않고 닫는 괄호만 보완한 뒤 전체 구조와 원문 연결을 재검사했다. 원문 응답, 최초 실패, 삽입 위치를 별도로 보존한다. 잘린 문자열·누락 필드·누락 ID는 이 방식으로 만들지 않는다. 이 기술 보정으로 의미 판단이 올바르다고 주장하지 않는다.
