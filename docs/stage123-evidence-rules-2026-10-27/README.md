# 근거 추출·규칙 계산 재시험 결과 — 신뢰성 문제로 중단

기준 커밋: `2449542a6ae3b5488556c848687088fadf466fac`.
저장 브랜치: `research/stage123-evidence-rules-20261027`.

## 무엇을 했나

AI가 직접 점수를 쓰는 대신 실제 행동·대상·산출물·원문 근거를 찾고 프로그램이 0~4점을 계산하도록 만들었다. 3점 이상이 관련 사례다. 전체 문제와 개별 관점의 평가 범위를 분리했다. 업종이 달라도 같은 기능이면 인정한다. 사람 정답은 만들지 않았다.

처음에는 질문을 함께 주고 근거를 찾게 했으나 질문에 있는 일을 사례가 수행한 일처럼 인용했다. 원문 검사로 거부했다. 그래서 질문과 사례 Problem을 숨기고 Task·Context만으로 먼저 실제 수행 목록을 만들었다. 이후 같은 모델이 자신의 목록과 질문을 비교했다. 다른 모델의 응답과 기대 점수는 제공하지 않았다.

Claude의 복잡한 JSON Schema는 없애고 작은 JSON과 로컬 검사를 사용했다. 모델마다 1·2·4개 사례를 넣는 수행 목록 추출 시험과 관련성 연결 시험을 실시했다. 현재 버전에서 각각 9개 응답을 확보했다. 일부 응답은 이전 버전의 이미 수신된 응답을 출처와 함께 재사용했으며 새 호출로 세지 않았다. 누락된 닫는 괄호만 보충한 응답은 변경 위치를 기록했다. 값·ID·문장·누락 항목은 만들어 넣지 않았다.

수행 목록의 분류명이 실제 행동과 어긋나는 경우를 발견해, 관련성 연결 시험 전에 분류명을 점수 조건에서 제외했다. 이 변경은 `query-blind-v13/pre-match-rule-review.md`에 기록했다. 최종 점수 함수 버전은 `functional-evidence-v14`다. 분류명이나 체크 수로 실제 기능을 대신하지 않는다. 초기 v11의 다른 규칙과 실패 기록도 보존했다.

## 왜 멈췄나

GPT가 `AXV2C_0093_01`의 “Analyze production quality defects”라는 실제 문장을 찾았지만, 이를 **데이터 통합** 요구에 직접 관련된 일로 연결했다. 설명은 결함·원인 분석일 뿐 통합을 뒷받침하지 않았다. 프로그램은 이 잘못된 연결을 믿어 4점을 계산했다.

원문에 문장이 있다는 것과 그 문장이 해당 기능을 증명한다는 것은 다르다. ID·JSON 검사가 맞아도 의미가 틀릴 수 있다. 이 사례는 원인 분석 관점으로 관련될 수 있으므로 ‘이 사례 자체가 무관하다’고 판정한 것이 아니다. **잘못 연결한 경로를 승인할 수 없다는 문제**다. 정상적인 모델 간 의견 차이와 구분해 중단했다.

같은 GPT 사례는 배치 크기 1·2·4에서 각각 2·4·4점이었다. 첫 응답은 원인 분석을 뒷받침하지 않는다고 설명하고 다음 응답은 원인 분석을 데이터 통합에 연결했다. 안정적인 정답으로 사용할 수 없다. Claude는 실제 원인 분석 사례를 보조 작업으로 낮추는 응답도 있어 추가 의미 검토가 필요하다.

## 해결 방향과 연구 한계

다음 버전에서는 숫자 위치 대신 명시적 요구 ID를 출력하고, 연결마다 질문의 요구 문장과 사례의 수행 문장을 나란히 보존해야 한다. 그다음 별도의 의미 검토로 ‘분석→통합’ 같은 잘못된 기능 연결을 탐지하는지 먼저 검증해야 한다. 독립 검토도 AI라면 사람 Gold라고 부를 수 없다. 사람 검토가 가능하면 기능 연결의 타당성을 확인하는 데 도움이 된다. 단순히 다수결하거나 이번 결과에 맞춰 점수표를 수정해서는 안 된다.

4점 추가 조건에 사용한 사전 원문 주석 8개는 공통 주석 편향과 불완전성의 한계가 있다. 원문 검사 자체도 원출처의 진위를 새로 검증한 것은 아니다. 교수님 피드백의 독립 평가·공정 비교·실제 기능 근거 요구는 설계에 반영했지만, 신뢰할 정답과 검색 성능 검증은 충족하지 못했다. 다중관점 검색과 다른 업종의 응용 가능성이라는 연구 목적은 유지했다.

## 재현과 기록

API를 호출하지 않고 `python -m scripts.evidence_closeout`으로 비용·중단 상태를 다시 집계할 수 있다. 자동 검사는 `python -m pytest tests/test_evidence_rules.py tests/test_evidence_split.py -q`다. `PYTHONPATH=src;.`가 필요하다. 생성 실행기는 활성 `halt.json`을 확인하여 후속 호출을 막는다. 중단 파일을 삭제해 검증을 우회하면 안 된다.

`final_status.json`에 모델별 비용·토큰·실제 완료 수와 오류 출처를 저장했다. `query-blind-v13/results/openai/match_probe_0001.json`에 문제 응답이 있다. 요청·입력 버전·응답 모델·원문·예약·실패는 각 버전의 `attempts`, `results`, `counts`에 남겼다. 기존 데이터 및 이전 결과 파일은 변경하지 않았다.
