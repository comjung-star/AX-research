## AI와 프로그램 역할

AI에게 점수를 요청하지 않는다. 실제 Task/운영상 Context에서 수행 작업의 행동·대상·산출물과 정확한 인용을 추출하고, 질문의 핵심 작업과 기능상 같은지/지원인지/넓은 유사인지 판단하게 한다. 필요한 작업이 Problem에 있다는 것만으로 수행 능력을 만들지 못한다. 각 판단에는 기능 비교 이유를 남긴다. 업종·직원/고객 역할·채널은 기능이 같으면 전이 가능하다.

프로그램은 원문 인용·ID·구조를 검증한 후0~4점을 계산한다.3점은 실제 작업 근거, 기능적 행동/대상/산출물 모두의 동등성, 호환 작업군을 함께 요구한다. 요약을 후속조치 식별로, 존재 탐지를 원인 진단으로 승격시키지 않는다. 단어의 겹침이나 표시 개수만으로3점을 만들지 않는다. 기능적 동등성 자체는 AI 판단이므로 파일럿에서 원문과 의미를 대조해야 한다. OTHER 작업의 고득점 주장은 검토 보류한다.

4점은3점에 더해 서로 다른 실제 작업 인용으로 서로 다른 추가 핵심 과업까지 맞거나, 사전에 원문을 대조한 범위별 주요 문제조건이 있는 경우다. 모델의 임의 SUPPORTED 표시를 받지 않는다. 조건 근거는 별도 설정의 정확한 원문·사례·질문·범위와 연결한다. 이 조건 목록은 에이전트가 검토한 공통 보조 주석으로 사람 Gold가 아니며 완전한4점 목록도 아니다. 근거가 추가 확인되지 않으면3점에 남기되 관련 판정은 유지한다. 이 공통 주석의 편향과 보수적 등급 한계를 보고한다.

전체 질문은 핵심 작업 합집합, 관점은 지정 작업만 사용한다. 예를 들어 이메일 요약은 전체 질문에 직접 관련될 수 있어도 ‘후속조치 식별’ 관점에서는 보조 작업이다. 품질 원인 관점에 일정조정의 관련도를 빌려오지 않는다. 기존30개 참조관점을 확정 정답/런타임 범주로 사용하지 않는다.

## 실제 검증 순서

이전 schema-safe-v10/plan.json의36개 조합을 정확히 그대로 사용한다(직접/부분/무관 각12, 전체24/관점12). 사전 기대구간은 사람 정답이나 모델 입력이 아니다. 세 모델은 독립적으로108개 근거와 계산 점수를 만든다. 과거 점수는 별도 열에 출처와 유효성 표시를 붙여 비교만 하고 새로운 점수에 섞지 않는다.

복잡한 네이티브 JSON Schema를 보내지 않는다. 단순 JSON만 요청하고 로컬에서 누락·중복·대상 연결·원문 근거·배열 유형·기능 연결을 검증한다. 최대 배치는 같은 질문/범위의4사례다. 별도1/2/4사례 실제 생성 검증을 먼저 한다. 프로브 점수는 파일럿108점에 섞지 않는다. 형식 오류는 원본을 보존하고1회 교정 재요청하며, 응답/청구 불명 생성 요청은 자동 재호출하지 않는다.

파일럿 통과에는108점 완전 수집, 사례/질문 혼동0, 근거 없는 수행 기능·효과/고득점0, 기능 판단과 원문 대조, 교차 업종 유용 사례 및 전체/관점 대조가 필요하다. 정상적인1/2 또는 경계 이견은 별도로 분석하고 다수결로 승인하지 않는다. 프로그램이4점을 막는 것만으로 AI 의미 판단까지 정확해졌다고 주장하지 않는다.

통과 후112×10×3=3,360개 새 평가를 한다. 원점수/새 계산/적용 규칙/불일치·보류를 분리하고, 원문 근거와 불일치 검토가 충분하지 않으면 검색으로 넘어가지 않는다. 사람 검증이 없으면 AI Silver다. 동일 검색 결과를 평가자별 완전한 Silver에서 각각 평가하고 삼자 합의의 불확실성도 공개한다. 미판정 합의를0으로 만들지 않는다.
