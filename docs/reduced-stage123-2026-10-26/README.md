실제 30회 중 1개 반환 16회, 2개 반환 8회, 3개 반환 6회였다. 동일 과거 출력에 고정 3 분모를 적용한 사후 진단값은 **53.33%**다. 이는 기존 97.78% 계산이 잘못됐다는 뜻이 아니라 지표 이름과 분모를 구분해야 한다는 뜻이며, 신규 검색 성능으로 사용하지 않는다.

`historical_ranking_metrics_recomputed.csv`는 과거 Stage1/2의 저장 순위를 독립적으로 다시 읽어 Recall·Reference Coverage·Strategy Coverage와 분모를 대조한 감사 산출물이다. 원래 없던 Precision/F1도 동일 과거 순위에서 사후 계산하되 `POSTHOC_AUDIT_NOT_NEW_STAGE_RESULT`로 표시했다. 신규 성능 평가로 사용하지 않는다.

## 4. 확인된 방법론 문제

1. **반복과 모델 다양성:** 2,520쌍의 세 번 판정은 모두 `gpt-6-luna`다. 완전 일치 1,747/2,520=69.33%, 관련성 경계 전환 90/2,520=3.57%는 동일 모델 반복 일치율이다. runtime 8,148쌍도 같은 모델 두 번이며 등급 일치 6,382/8,148=78.33%, 경계 전환 169/8,148=2.07%다. 외부 정확도나 세 LLM 간 일치율이 아니다.
2. **판정/생성 모델 공유:** GPT-only와 동적 관점 생성 및 과거 판정이 같은 모델이어서 자기 선호·공유 편향 가능성이 있다. GPT-only의 높은 수치로 독립 우수성을 확정하지 않는다.
3. **평가 단위 변경:** 53.32%는 질문별 reference 양성 합집합의 global Top10, 70.85%는 관점별 Top10 합집합, 47.64%는 runtime 관점별 Recall의 질문 평균이다. 서로 빼서 개선·악화를 계산하면 안 된다. 반복 30회를 독립 질문 30개로 취급하지 않는다.
4. **양성 없는 관점:** 과거 reference 1/30과 runtime 18/97은 양성이 없다. 기존 Coverage/Recall은 answerable 관점만 분모에 쓰는 경우가 있으므로 전체 관점 수·제외 수를 같이 기록해야 한다. 높은 Coverage가 개별 관점의 정밀도나 신규 관점 발견의 증거는 아니다.
5. **정답 범위:** reference 양성 합집합만 쓰면 목록 밖의 타당한 새 관점에 해당하는 관련 사례가 빠질 수 있다. 신규 프로토콜은 원질문×사례 전체 관련도와 reference×사례 적합도를 분리한다. runtime P1과 reference P1을 번호로 매칭하지 않는다.
6. **입력/예산 차이:** v2.5의 기존 `single_query_dense.csv`는 이름과 달리 단일 벡터 Dense가 아니라 **단일 질의의 3-view cosine 평균**이다. 신규 단일 텍스트 Dense 대조군으로 재사용하면 안 된다. 전체 9,416 인덱스의 혼합 텍스트/인코딩과 통제용 112 인덱스도 혼합하지 않는다.
7. **언어·정보량:** 한국어 질문과 주로 영어 사례의 BM25는 교차언어 어휘 불일치가 있다. 3-view에 전체 384토큰을 주고 단일 문서에 128만 주면 내용 보존량도 달라진다. 신규 프로토콜에 토큰량·절단율과 실제 고유 후보 수·분기 수·점수화 횟수 기록을 포함했다.
8. **Dev 선정/전수검증:** 기존 Dev를 보고 사례를 추가·선정한 이력과 반복적인 실험이 있다. 112건은 원문 근거가 있는 서술적 Dev이며 사람 Gold·전수 독립 사실확인·전체 9,416개 대표 표본이 아니다. 의미 유사 중복 검토도 남아 있다. 해시 일치와 HTTP 성공은 사실검증을 대신하지 못한다.

## 6. 재개 조건과 필요한 판단량

상세 설계는 [신규 프로토콜](protocol.md), 기계 판독 설정은 `configs/reduced_stage123_20261026.json`이다. 미실행 설계이며 교수 확정안이나 독립 Test 사전등록으로 포장하지 않는다.

- 서로 다른 LLM 최소 3종의 구체적인 모델 ID/실제 접근과 독립 실행 경로를 준비한다. 형제 snapshot이나 같은 모델 반복으로 조건을 채우지 않는다. 현재 설정에서는 검증된 모델 목록을 비워 두었다.
- 기존 reference 문구를 검색결과 없이 독립 점검하고 사례의 Problem/Task/Context 원문 근거와 의미 유사 중복을 검토한다. 기존 11,766개 전체 사실검증을 112개 Dev의 실행 조건과 혼동하지 않되, 112개에 대한 검토 범위는 명시해야 한다.
- reference×사례는 30×112=3,360쌍, 세 LLM이면 **10,080점**이다. 신규 전체 관련도 Q×C는 추가 10×112=1,120쌍이다. 둘 다 구축하면 (3,360+1,120)×3=**13,440점**이다. 이것은 라벨 수이고 API 요청 수가 아니다.
- 아직 평가 모델과 batch/token 사용량이 정해지지 않아 비용을 숫자로 추정하지 않았다. 실제 요율·토큰 상한·비용 상한을 정한 뒤 소규모 형식 점검과 전체 실행을 진행해야 한다. 이번 비용 발생 요청은 0회다.
- 사람 검증은 가능할 때 불일치 표본과 일치 대조 표본을 구분해 수행한다. 수행 전에는 `human_approved=false`를 유지한다. 과거 v2.2 사람 평가 50개를 변경된 v2.5 Gold로 이식하지 않는다.

이 조건이 충족되기 전에는 Stage2/3 지표가 **미측정(null)**이다. 0점이나 과거 결과로 채우지 않는다.

## 7. 재현과 증거

저장소 루트에서 기존 개발환경 Python을 지정한다. 현재 PC의 기존 가상환경은 인접한 `AX-prototype/.venv`다. 감사 코드에 네트워크/API 호출 기능은 없다.

```powershell
$env:PYTHONPATH='src;.'
$env:PYTHONIOENCODING='utf-8'
& ..\AX-prototype\.venv\Scripts\python.exe -m scripts.audit_reduced_stage123 --credential-root ..\AX-prototype
& ..\AX-prototype\.venv\Scripts\python.exe -m pytest tests/test_reduced_stage123_audit.py -q
```

감사 명령의 **종료코드 2는 실행조건 미충족에 따른 예상 중단**이다. 입력 해시나 과거 지표 대조가 실패하면 별도 예외로 종료한다. 자격증명 경로를 생략하면 해당 dotenv는 확인하지 않는다. 새 환경에서는 Python 3.11 이상과 테스트용 pytest가 필요하며 Windows에서 시간대 데이터가 없으면 `tzdata`를 설치한다.
