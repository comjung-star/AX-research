# 축소 범위의 신규 Stage 1~3 Dev 프로토콜

2026-10-26. 상태: **실행 전 조건부 설계, Stage1 접근/라벨 gate에서 중단**.
기존 연구를 감사한 후 작성한 후속 Dev 설계다. 이미 본 과거 Dev 결과에 대해 소급 사전등록 또는 독립 평가라고 주장하지 않는다. 본 문서의 세부 수치는 교수 지정값이 아닌 기록된 실험 선택이다.

## 연구 질문과 범위

1. 같은 업무 문제와 같은 후보 예산에서 Problem/Task/Context 분리 표현이 단일 텍스트 Dense보다 유효한가?
2. LLM 동적 관점을 보존한 검색이 원질의 검색보다 유효하며, 그 효과가 사례 표현에 따라 달라지는가?
3. 서로 다른 LLM이 생성하는 관점·검색어가 어떻게 달라지고 어떤 관련 사례의 획득·손실과 연결되는가?

Query2doc, CSQE, HyDE와 새 검색기술은 도입하지 않는다. QCI 학습, learned Gate, Factor/Wald, 전략 추천의 추가 효과는 이번 논문의 필수 검증에서 제외한다. 기존 구현·결과는 보존한다.

## Stage1: 독립 평가 기준

입력 후보는 기존 source-supported Dev 112사례의 `problem`, `task`, `context`와 기존 10질문이다. 구현·성과·전략·원인·검색결과·검색점수·기존 Silver는 판정 입력에서 숨긴다. 동일 source/기관/의미 중복과 원문 근거 검토의 범위를 명시하고 미해결 기록은 이유와 함께 분리한다. corpus 변경이 생기면 새 입력 해시와 전체 분모를 다시 기록한다. 본 단계는 코퍼스의 도입성과/인과관계를 검증하는 단계가 아니다.

질문과 참조관점은 기존 Dev 자료다. 최소 세 종류 LLM이 서로의 답을 보지 않는 새 문맥에서 판정한다. 요청 모델 ID, 실제 응답 모델 ID, 모델 계열/버전, provider, 응답 ID, 프롬프트 해시, 입력 해시, 실행 시각, 토큰/지연/실패/재시도/비용을 저장한다. 같은 모델 세 번은 세 평가자로 계산하지 않는다. 구체 모델 ID가 없는 현재 `judges=[]`이며 API 호출을 시작할 수 없다.

판정 작업은 두 종류로 분리한다.

| 작업 | 입력 | 112/10 조건의 분모 | 역할 |
|---|---|---:|---|
| 전체 Query×Case | 원질문과 사례의 세 필드 | 1,120쌍×3모델 | reference 목록 밖 관련 사례도 포함하는 P/R/F1 기준 |
| Reference×Case | 원질문·검증된 reference 문구와 사례 세 필드 | 3,360쌍×3모델 | Reference Coverage 기준 |

기존 reference 30개는 검색 생성기에 제공하지 않는다. 검색결과를 보기 전에 질문 근거성·중복·해결책 혼입 여부를 세 LLM이 독립 점검하고, 미해결 문구는 상태/이유와 함께 보류한다. reference 변경 시 개수·판정 양식·비용 분모를 갱신한다. 원질문 판정은 reference 작업과 다른 호출 문맥에서 실행해 기준 목록의 영향을 줄인다.

0=무관, 1=맥락만 약하게 관련, 2=부분 관련, 3=주요 문제/업무가 직접 관련, 4=문제·업무·맥락이 강하게 일치. 양성은 >=3. 세 LLM의 중앙값을 사전 지정 **AI consensus Silver**로 삼는다. 이것은 인간 Gold가 아니다. 3개 중 2개 양성인 경계도 숨기지 않고 원점수·이유·모델별 판단을 보존한다. 미응답/형식오류/누락은 미판정이며 0이 아니다. 한 모델만의 판정이나 불완전 쌍으로 full-corpus Recall을 계산하지 않는다.

일치도는 전체 등급 일치(세 값 동일)/완료 쌍 수, 양성/음성 완전일치/완료 쌍 수, 모델쌍별 일치율과 5×5 혼동표, ordinal Krippendorff alpha 및 binary Fleiss kappa를 보고한다. 분산이 0이어서 chance-corrected 지표가 정의되지 않으면 NA로 표시한다. 유병률과 양성 일치/음성 일치도 같이 보여 높은 음성 비중이 일치율을 부풀릴 가능성을 확인한다. 지표 구현은 실제 라벨 수집 전에 검증해야 하며 이번 감사 코드는 이 신규 지표를 구현·실행한 것이 아니다.

불일치는 경계 2↔3, 정보부족, 문제/과업/맥락 해석차, 표현·언어 차이, reference 모호성 등으로 이유를 기록한다. 사람 검증이 가능하면 전체 threshold-flip과 일치 표본을 층화해 검토하고, 선택확률·표본수·미검토 수·원점수를 보존한다. 고의견차 표본의 오류율을 전체 정확도로 일반화하지 않는다. 사람 검증 미실시인 경우 해당 수는 0이고 표시는 false다. 합의/조정 결과는 ranking 실행 전에 버전 고정한다. 인간 Gold/독립 Test 효과 주장은 보류한다.

## Stage2: 사례 표현과 BM25

Stage1 전체 관련도와 reference 라벨이 완료·검증되고 입력 버전이 고정된 뒤 실행한다.

- **Single Dense:** 문제/과업/맥락을 고정된 순서와 구분자로 합친 한 문서를 한 벡터로 인코딩한다.
- **3-View Dense:** 같은 세 필드를 각각 인코딩한 후 cosine 세 점수의 동일가중 평균으로 비교한다. learned Gate를 섞지 않는다.
- **BM25:** 같은 세 필드의 같은 보존 텍스트와 고정 Kiwi tokenizer로 비교한다. 한국어 질문/주로 영어 사례 조건과 양수 lexical score 여부를 별도로 기록한다.

BGE-M3의 같은 가중치/토크나이저를 사용하고 정규화한다. 사례별 각 필드를 먼저 최대 126개 내용 토큰으로 동일 절단하고, 그 보존 내용을 두 표현 모두에 사용한다. query/각 view는 special token 포함 최대 128, single document는 최대 384다. 구분자와 special token으로 실제 길이가 초과하지 않는지 실행 전에 검사한다. 필드별 원래/보존 토큰 수, 총 인코딩량, 결측/절단율을 저장한다. 기존 112개 3-view 인덱스는 이 내용 보존 통제와 단일 텍스트 인덱스를 갖추지 않았으므로 그대로 신규 2×2에 섞지 않는다.

후보 예산 B=20 고유 사례/원질문, K=5/10/20, seed=20261026. 전체 112개를 같은 코퍼스로 유지한다. 같은 B는 동일 계산비용을 뜻하지 않으므로 인코딩 수·score 계산 수·시간·메모리를 함께 보고한다. BM25의 동점/0점은 고정 case ID 순서로 처리하며 lexical positive 수를 별도로 표시한다. 번역이나 새 확장은 현재 비교에 추가하지 않는다. 교차언어 BM25의 한계가 남으므로 BM25 대비 향상만으로 다중관점의 우수성을 결론내리지 않는다.

## Stage3: 2×2와 LLM별 관점·용어

|  | 단일 문서 Dense | Problem/Task/Context Dense |
|---|---|---|
| 원질문 하나 | A | B |
| LLM 동적 관점 | C | D |

A↔B, C↔D로 표현 효과를, A↔C, B↔D로 관점 효과를 본다. 차이의 차이 `(D-B)-(C-A)`도 질문별로 기록한다. 같은 질문에서 한 번 생성한 관점을 C/D 및 BM25에 그대로 재생한다. 생성 LLM별로 이 표를 각각 만든다. single-query BM25와 multi-perspective BM25는 별도 어휘 기준선이다. GPT-only를 수행하지 않은 경우 과거 값으로 새 표를 채우지 않는다.

최소 세 종류 LLM에 동일 원질문만 제공한다. 참조관점, 정답, 코퍼스, 검색결과를 넣지 않는다. 각 LLM당 질문당 3회, 회차당 2~5개의 가변 관점을 생성한다. 이는 이번 비교의 상·하한이지 보편적으로 3관점을 고정하는 규칙이 아니다. 제목/설명/Problem·Task·Context 해당 근거/검색어를 구조화하고, 해결책 제안을 관점으로 취급하지 않는다. 검색용 문자열은 제목+설명을 고정 순서로 이어 사용한다. 단일질의는 원문을 그대로 사용하며 세 view에 같은 질의 벡터를 적용해 별도 질의 파서 효과를 섞지 않는다.

분기별 전체 점수/순위와 provenance를 보존한다. 평가용으로만 관점을 반환 순서대로 순환하며 미선택 사례를 하나씩 골라 B=20 고유 사례를 채운다. 중복은 다시 세지 않으며 빈 분기는 건너뛴다. 동일 사례의 여러 분기 연결은 보존한다. 이 목록의 처음 K개로 주 지표를 계산한다. 조기 글로벌 학습순위나 RRF를 제안모델로 추가하지 않는다. 관점별 TopK 합집합 결과는 별도 보조표에 실제 N을 명시하고 Single Dense@N과 맞춘다. 분기 점수 계산 횟수와 중복 탐색 횟수는 별도 비용 장부에 남긴다. **같은 후보 수로 통제하는 비교와 같은 계산량 비교를 구분한다.**

관점/용어 비교 표에는 모델·질문·회차·branch ID·제목·설명·실제 검색 문자열·입력 근거 구간·정규화 용어·후보 ID·local rank·채택 순번을 연결한다. Kiwi 기반 정규화 용어 집합의 Jaccard, 관점 수, 중복률, 모델별 공통/고유 용어, 회수 관련 사례의 획득·손실·겹침을 질문 단위로 기록한다. 용어 유사도만으로 의미적 동일성을 판정하지 않는다. 사람/독립 평가를 수행하지 못한 novel perspective는 미검증으로 남긴다.

## 지표와 집계

질문 q의 독립 Query×Case 양성 집합을 Rq, 정확히 K개 고유 출력 집합을 TqK라고 한다.

- Precision@K = `|TqK∩Rq| / K`. K보다 적은 출력은 실행실패로 별도 기록하고 분모를 몰래 실제 반환수로 바꾸지 않는다.
- Recall@K = `|TqK∩Rq| / |Rq|`. 양성 0개 질문은 NA, 해당 질문 수와 전체 분모를 함께 보고한다.
- F1@K = 질문별 `2PR/(P+R)`. 양성이 있고 hit=0이면 0, Recall이 NA면 F1도 NA. 먼저 전체 P/R을 평균한 뒤 F1을 계산하지 않는다.
- Reference Coverage@K = 양성이 있는 검증 reference 중 TopK에 관련 사례가 1개 이상 있는 비율. 양성 없는 reference를 제외한 수와 전체 reference 수를 같이 기록한다.
- Reference Coverage-all@K = 위 covered reference 수 / 전체 검증 reference 수. 무정답 관점을 분모에 포함한 보조값이다. Reference는 전체 가능한 관점의 닫힌 목록이 아니다.
- Judged@K, 전체 라벨 완결률, 회수 hit 수, Rq 크기, K/N/B, 실제 후보 고유 수를 매 행 보존한다. 신규 관점에 대한 runtime 관점 적합성 지표는 별도 블라인드 라벨 없이 계산하지 않는다.

생성 3회 평균을 먼저 원질문별로 계산하고, 10개 원질문을 단위로 macro 평균을 낸다. 단일질의의 결정적 결과를 독립 30개로 복제하지 않는다. 질문별 paired 차이와 개선/악화/동률 개수, 질문 단위 bootstrap 95% 구간을 보조 보고한다. Dev 10문항과 모델/조건 다중 비교로 확인적 유의성·일반화를 주장하지 않는다. 검색/판정/사람 검증 비용·실패·재시도를 모두 저장한다.

## 중단·재개와 Test 봉인

세 종류 LLM 접근, 원문/중복 검토범위, 검증된 reference, 완전한 독립 라벨, 오류/비용 제한이 준비되기 전 새 평가를 시작하지 않는다. 현재 감사 코드의 종료코드 2가 이 상태다. 모델 접근을 확인하는 것은 API 키 존재 여부와 구분한다. 실제 실행 후에도 모델 대체·예산 변경·실패 선택제거를 조용히 하지 말고 새 실행 ID와 변경 이유를 남긴다.

최종 독립 Test인 Stage4는 본 프로토콜로 생성·실행하지 않는다. 기존 미래 예약 그룹의 콘텐츠를 질문 작성이나 튜닝에 사용하지 않으며, 이번에는 이미 저장된 분할 메타데이터만 누수 감사에 사용한다. Dev 작업을 완료한 뒤에도 모델/프롬프트/평가규칙 동결과 별도 사용자 요청 없이 Test를 실행하지 않는다.
