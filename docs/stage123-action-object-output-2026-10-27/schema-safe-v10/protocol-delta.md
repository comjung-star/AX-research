# v10 사전 보완 — 원본 v9 보존

v9의 Claude 생성 HTTP400을 별도 출력16토큰 상한 진단 요청으로 확인했다. 키를 가린 오류 필드만 저장했으며 메시지는 `Schema is too complex.`였다. 인증 오류가 아니었다. 원본 두 요청 및 진단 요청의 비용은 무료로 단정하지 않고 예약 전액$0.032854를 유지한다. 기존 v9 halt와 실패 응답을 덮어쓰지 않는다.

v10은 사례별 ID·근거 연결을 그대로 고정하면서, 네 가지 상태의 행동/대상/산출물 열거 세 개를 같은 세 요소의 일치 여부 비트3자리(match_mask)로 표현한다. 111은 세 요소 모두 직접 일치, 0은 해당 요소의 지원/차이/미기재다. 지원인지 무관인지는 relation과 세 구절 이유에 남긴다. API 정규식 제약은 빼고 로컬에서 세 구절/35단어를 검증한다. 이는 높은 문법 조합 수를 줄이는 형식 수정이며 다른 모델 판단을 주입하지 않는다.

별도로 4점의 ‘주요 과업 대부분’ 조건을 검사할 수 있도록 실제 수행한 과업 목록 matched_tasks를 받는다. 두 핵심이면 둘, 세 핵심이면 최소둘을 명시해야4점을 허용한다. 사례 Problem의 원하는 결과·부담은 Task가 실제 수행하는 작업/산출물의 증거가 아님을 명확히 했다. 근거 발췌는 해당 사례 Task로 한정한다. 3점은 여전히 기능적으로 같은 행동·대상·산출물 하나로 가능하며 업종 전이를 허용한다.

전체 질문과 단일 관점은 서로 다른 평가 대상이다. 쇼핑 QA의4점 상한 진단은 ‘업무 과부하 조건까지 포함한 전체 질문’에 적용한다. QA 자체만을 묻는 단일 관점의4점은 별도 평가하므로 자동 위반으로 판정하지 않는다. 단일 관점의 점수를 전체 질문에 가져오지도 않는다.

같은36쌍 균형(각12개) 규모에서 v10은 가장 복잡한8사례/3과업 출력 형태도 미리 검증하도록 제조 질문의 직접3·부분3·무관2를 사용하고, 문서 검증 질문은 직접1·부분1·무관2로 조정했다. 전체 질문24(각8), 개별 관점12(각4) 구조는 같다. 정확한 사전 목록은 plan.json에 기록하며 기대구간은 모델 입력에 없다. v9/v10 점수 통계는 섞지 않는다. 모든 누적 비용은 합친다.

v10을 새로 토큰 계산하고 예산을 통과한 후36쌍 전부를 세 모델에서 독립적으로 다시 호출한다. v9에서 받은 GPT/Gemini 점수나 이유를 전달하지 않는다. v10도 기준 위반/질문 혼동을 해결하지 못하면 전수 평가와 검색 실험으로 넘어가지 않는다.
