# 5단계 결과: 선택한 관점에서 근거가 있는 사례를 보여주기

5단계 시범 구현과 기능 검사를 완료했다. 질문에 맞는 관점을 선택한 다음, 연결된 사례의 자료·대상·수행 업무·명시 조건을 다시 확인해 참고 후보를 보여준다. 추천 정확도 향상은 아직 입증하지 않았다. 기존 방법과 비교하는 6단계 실험은 수행하지 않았다.

## 이번에 구현한 동작

- 앞서 검토한 4개 관점, 승인된 연결 18개, 고유 사례 17개만 사용한다. 전체 112개 사례를 모두 추천 대상으로 확장한 것이 아니다.
- 같은 유형의 작업 후보와 다른 대상·맥락에 응용할 후보를 구별한다. 두 유형 모두 정답 확정을 뜻하지 않는다.
- 질문과 사례의 근거 문장, 연결 관점, 적용 조건, 확인하지 못한 항목을 남긴다.
- PDF·야간·음성과 같은 명시 조건이 사례 요약에서 확인되지 않으면 추천 목록 대신 조건 확인 대기에 둔다. 근거가 없다는 것은 불가능하다는 뜻이 아니다.
- 후보는 최대 20개, 최종 출력은 최대 5개다. 조건을 충족하는 사례가 적으면 빈자리를 채우지 않는다.
- 여러 관점이 선택되면 가능한 범위에서 각 관점의 후보를 먼저 배정한다. 같은 사례는 한 번만 보여주고 연결 관점과 근거는 모두 보존한다.
- 조건과 작업 유형을 확인한 뒤, 같은 유형 안의 순서에는 기존 로컬 BGE의 작업 문장 유사도를 보조적으로 사용한다. 이 값은 정답 확률이나 검증된 신뢰도가 아니다.

## 실제 로컬 실행 예시

아래 질문은 구현 동작을 확인하려고 작성한 합성 예시다. 독립적인 성능 평가용 정답 데이터가 아니다. 후보 수에는 다른 대상·맥락의 응용 검토 후보도 포함된다.

| 질문의 요지 | 출력 | 해석 |
|---|---:|---|
| 사내 규정의 근거·절차 검색 | 3개 | 문서 검색 후보를 제시 |
| 보험 청구서 PDF에서 가입자 정보 추출 | 2개 | 보험 사례와 대출 문서 응용 후보를 구별 |
| 운송 청구서 금액을 계약 요율과 대조 | 5개 | 운송 청구서·요율 대조 사례를 첫 후보로 제시 |
| 야간 고객 문의 응대 | 2개 | 야간 조건이 확인되는 사례만 제시 |
| 음성 고객 문의 응답 | 1개 | 음성 조건이 확인되는 사례만 제시 |
| 야간이면서 음성인 문의 응대 | 0개 | 두 조건을 함께 확인할 근거가 부족 |
| 읽기 전용으로 청구서 대조 | 0개 | 요약만으로 구현 권한 조건을 확인할 수 없음 |
| 상품 수요 예측 | 0개 | 현재 4개 관점의 범위 밖 |

보험 PDF 첫 후보는 `AXV24_bc6444cc1b61`, 운송 청구서 대조 첫 후보는 `AXV2P2_0011_01`이다. 의뢰 자료 구조화와 필수 항목 검사를 함께 요청한 예시에서는 `AXALL_US_OMB_2025_01754`를 한 번만 표시하고 P02·P03 연결을 함께 남겼다.

PDF 추출과 야간 응대를 별도 문장으로 요청한 예시도 확인했다. PDF 조건을 야간 응대 사례에 잘못 적용하지 않도록 작업별 조건을 분리한다. 자동 수정 요청이 있으면 대조에 참고할 사례는 제시할 수 있지만, 자동 수정까지 지원한다고 표시하거나 실행하지 않는다.

## 검사 결과와 한계

관련 기능 검사 25개가 통과했다. 실제 로컬 유사도를 사용한 합성 예시 14개를 저장했고, 저장된 벡터로 다시 실행했을 때 14개 결과가 모두 동일했다. 17개 사례 메타데이터의 원문 연결, 승인된 연결만 사용하는지, 인용의 문자 일치, 출력 상한, 중복 제거와 관점 보존도 검사했다. 앞선 관점 선택기의 동결 소스는 변경하지 않았다.

이는 프로그램이 정한 규칙대로 작동한다는 검사다. 사례 해석이 독립 전문가에게 검증됐다는 뜻은 아니다. 메타데이터는 같은 assistant가 기존 Problem/Task/Context 요약을 읽고 작성했다. 모든 원 출판물을 새로 감사한 것도 아니다. 특히 구체적인 출력 항목, 새 환경의 적용 성공, 실제 권한 설정은 요약만으로 확정할 수 없다.

현재 질문 해석은 한국어 표현 규칙에 의존하는 시범 방식이다. 하나의 긴 문장에 여러 작업과 조건이 섞이면 조건의 적용 범위를 완전히 해석하지 못할 수 있다. 현재 예시를 통과했다는 사실을 일반 사용자 질문의 정확도로 확대할 수 없다.

유료 API 호출은 0회이며 새 학습·새 정답 채점·기존 정답 데이터 기반 성능 비교는 수행하지 않았다. 다음 6단계에서 별도로 고정한 평가 질문과 동일한 후보·출력 예산으로 기존 방법 대비 이득을 검증해야 한다. 이번 결과만으로 성능 개선이나 논문 가치를 확정하지 않는다.
