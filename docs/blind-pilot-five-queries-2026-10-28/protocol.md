# 새 업무 질문 5개 블라인드 파일럿 사전 계획

사용자가 제공한 Q11~Q15 원문과 configs/blind_pilot_five_20261028.json을 실행 전에 동결한다. 최종 독립 Test가 아니며, 기존 미인식 업무를 의도적으로 포함한 목적 표본이다. 질문을 기존 Task의 복사본이나 무작위 새 표본이라고 주장하지 않는다.

## 기존 질문과의 겹침: 실행 전 질적 점검

|새 질문|가까운 기존 문제|공통점과 차이|
|---|---|---|
|Q11 휴가 신청·등록|Q9 사내 시스템 활용, Q3 직원 업무|내부 시스템 환경은 겹치지만 Q9의 보안·배포 및 Q3의 지식 검색과 달리 신청 처리·등록 업무다.|
|Q12 반품 사진 확인|Q4 심사·검증, Q6 상품|확인·상품이라는 공통 영역은 있으나 사진 기반 반품 접수와 환불 지원 업무가 새 초점이다.|
|Q13 숙박 서류 재발급|Q1 고객 요청, Q4 서류 확인|고객 대응·서류는 겹치지만 질문응답이나 준수검토 대신 기존 송장/영수증 재발급 처리다.|
|Q14 고장 예측|Q8 미래 값 예측, Q10 제조 품질·설비|예측·제조 환경이 상당히 겹친다. 고장 위험·사전 정비 알림을 묻는 구체적 변형이며 독립 주제라고 주장하지 않는다.|
|Q15 지급 안내 오류 수정|Q4 문서 검증|입력정보 오류 확인이 겹치며, 지급 안내의 누락 보완·수정 지원으로 범위를 구체화했다.|

문자열 동일 여부도 기록하되 의미 중복 부재의 증거로 삼지 않는다. 기존 Task가 새 질문의 부분 문자열인지도 점검한다. 질문 작성자는 사용자이며 사례를 알고 선택한 목적 표본이다.

## 동결과 추천

- 기준715c4050의 functional_mapping.py, semantic_mapping.py 및 두 config를 수정하지 않는다. A 기존 원질문 규칙 정렬, B 기존 필드별 가중 의미점수, C 기존50:50 결합을 함수 호출로 그대로 재사용한다.
- BGE-M3 로컬 파일·패키지·CLS/L2/CPU/float32/batch8/threads4/seed/max4096 설정을 기존 사전등록과 대조한다. 112사례 벡터와 의미 필드 벡터를 재사용한다. 새로운 질문 원문·필드 벡터만 계산한다.
- A의 동일 점수 처리에 필요한 새 원질문 검색점수는 기존 Single Dense 벡터와 BM25 corpus 통계를 재사용해 RRF60·각0.5로 계산한다. BM25는 기존Kiwi 토큰화·기존 corpus 통계의 BM25 공식을 재생한다. 임의 대체 점수나 가중치 변경은 없다.
- 원질문 O_SINGLE만 주 비교한다. 과거 동적관점은 OpenAI 유료 생성30회 절차였다. 새5질문에 동일3회 생성을 하려면15요청이 필요하고 이번에 비용을 승인받지 않았으므로 생성하지 않는다. 기존 실비는 새 질문의 정확한 견적이 아니며 새 요금·토큰·예산 확인이 별도로 필요하다.
- 전체112순위와점수·매핑구성요소·실제Task·규칙인식·근거를 보존한다. 결과를 보고 가중치나 규칙을 고치지 않는다.

## 블라인드와 향후 분석

질문별 A/B/C Top10의 합집합을 빠짐없이 포함한다. 추가로 미인식33개 중 합집합 밖 B순위가 가장 높은 최대2개를 추가한다. 이는 채점 대상을 고르는 고정 정책이며 예상 정답이 아니다. 출처정보는 기존카탈로그 중112개 사례ID만 연결하며 새 웹 검증은 하지 않는다.

평가자용에는 고정8개 필드만 제공하고 임의ID·고정시드순서로 섞는다. 점수/의견은 공란이다. 원래 사례ID·추천방식·순위·점수·Silver·추가표본여부·예상 관련 이유는 별도 analyst 폴더에만 둔다. 공개된 GitHub 비공개 저장소 내부 파일분리는 접근차단이 아니므로, 평가자는 먼저 evaluator 파일만 받고 analyst/모델별보고서는 채점 전 열지 않도록 안내한다. 전체보고서/대화에 실제 알고리즘별사례를 펼치면 눈가림이 깨지므로 비교표는 analyst에 둔다.

사람0~3점(>=2관련)·보류만 읽는 분석기를 준비한다. 미평가/보류는0으로 채우지 않는다. P@5/10은TopK모두채점된때만계산하고, nDCG는질문별평가풀전체가채점된때그풀의IDCG를사용한다. 이는 전체112정답기반nDCG가아니다. 무관련풀은IDCG0으로nDCG미정이다. 전체Recall은계산하지않는다. 미평가가남은Macro는정식5질문지표로발표하지않는다. 합성점수테스트는tmp에서만실행하고실제평가파일에는넣지않는다.

신규 브랜치의 질문/코드해시/출력/테스트/재현기록을 저장하고 commit·push 후 GitHub 원격 blob 내용을 읽어 대조한다. 사람 평가 이전에는 모델 성능 개선 결론을 내리지 않는다. 기존112사례·10질문·정답·실험·프로토타입·독립Test는 보존한다.
