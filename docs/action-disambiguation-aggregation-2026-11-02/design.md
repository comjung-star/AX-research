# 구현 전 설계 고정

2026-11-02. 이 문서·설정은 C1/C2 구현 전에 별도 커밋한다. 원문 분석을 위한 audit 코드는 기존 값을 읽는 진단 도구이며 C1/C2 구현이 아니다. 기존 Dev와 대표 오류를 이미 알고 있으므로 완전한 맹검·일반화 검증이라고 주장하지 않는다.

## 가설

- C1: ‘문서 검토’만으로 검증 수행을 인정하지 않고 목적·입력/출력 역할을 확인하면 기능 오탐을 줄일 수 있다. 보수적으로 실제 관련 사례도 낮출 위험이 있다.
- C2: 원질문·관점·사례의 실제Task가 공유하는 기능이 있을 때만 관점 점수를 사용하면, 원질문을 벗어난 관점 최고점의 과잉 승격을 줄일 수 있다. 원문 규칙이 불완전하면 유용한 관점도 차단할 수 있다.
- C3: 두 변경을 함께 적용한다. 더 좋아진다고 가정하지 않으며 C0~C3 전부 보고한다.

## C1: 새 기능을 늘리지 않는 목적 확인

기존18기능의 원문 인용을 그대로 입력받는다. 수정은 신규 모듈에만 둔다. 새 사전의 동의어 확장, 사례ID 조건, 정답 기반 예외를 만들지 않는다.

1. `validate_record`: 기존 후보를 인정하려면 같은 프로필 원문에 명시된 검증/준수/누락·오류/적격·신원·증빙/위험 평가 등의 목적 근거가 있어야 한다. 정확한 패턴은 새config에 고정했다. 일반적인 review/검토/읽기만 있으면 이 기능을 보류하고 다른 요약·추출 기능은 유지한다. 근거 없음을 무관 정답으로 바꾸지 않는다.
2. 실제Task에서는 심사용·검토용처럼 ‘용’으로 끝나는 기능명, 명시된 for/in order to/to support 이후에만 나오는 기능명이 그 작업의 실제수행 근거가 되지 않게 한다. 실제 Review 동작이 앞에 있고 for compliance처럼 목적을 한정한 경우와, Extract for validation처럼 검증을 후속목적으로만 둔 경우를 구분한다. 후보 동작 위치와 목적 근거를 저장한다. 이 간단한 범위 규칙의 오인 가능성도 기록한다.
3. `generate_content`: 생성 대상으로 매칭된 명사가 from/using/based on 등의 명시적 입력 표지 뒤에만 있으면 생성 출력으로 인정하지 않는다. 예: Create CRM contacts from customer emails에서 이메일은 입력이며 연락처가 출력이다. 출처 없는 새 Output은 UNKNOWN이다.
4. 나머지16기능은 동작·대상 후보를 바꾸지 않는다. 조회와 분석, 분류와 승인, 안내와 실행, 예측과 탐지를 임의로 같은 기능으로 합치지 않는다. 명시 근거 없는 승인·실행을 새로 추정하지 않는다.

Problem/Context가 실제Task 기능을 대신하지 못하는 기존 compare 정책은 유지한다. profile의 기능 목록과 action_family_hits에서 보류된 기능을 제거한 뒤 원래 compare 함수를 재사용한다. B의 Task/Action/Object/Output/Context cosine은 그대로다. 따라서 C1의 변화는 기능 구분 성분에 한정한다.

## C2: 원문 기능에 근거한 관점 허용(단 하나의 새 집계)

원질문과 관점을 별도 검색/매핑하는 기존 구조를 유지하며 문자열을 합치지 않는다. 원질문 기능 집합 F0, 관점 Fp, 실제Task Fc에 대해:

`allowed(p,c) = bool(F0 ∩ Fp ∩ Fc)`

각 후보별로 허용된 관점의 목록을 따로 보존한다. C2는 기존 프로필, C3는 C1 필터 후 프로필을 사용한다. 규칙을 못 읽으면 임의로 원문을 관점에 복제하지 않고 해당 관점의 최종 점수 기여를 보류한다. 원질문 점수는 항상 남긴다.

기존 규칙 점수 g0/gp(0~4), 의미점수 b0/bp(-1~1)와 기존 C 수식을 재사용한다.

- C0/C1: `r=max(g0,max_all(gp)); b=(b0+max_all(bp))/2`, 관점이 없으면 r=g0,b=b0.
- C2/C3: 위 식의 all을 allowed로만 바꾼다. 허용 관점이 없으면 r=g0,b=b0.
- 모두 최종 `C=0.5*(r/4)+0.5*((b+1)/2)`.
- 최고 규칙 관점과 최고 의미 관점이 다를 수 있는 기존 정책은 유지한다. 허용 목록은 같고 각 성분의 실제 승자도 저장한다.
- 동일 후보112개·전체 순위·동점은 기존 final_retrieval_score 후 case_id 그대로다. 후보를 제거하지 않는다. C2로 새 가중치를 찾지 않는다.

원질문만 쓰는 O에서는 C2=C0, C3=C1이어야 한다. D는 기존3회 관점, Single/3View80풀 모두 저장한다. 동일한 관점의 반복이 최고점에 추가 보너스를 주지 않아야 한다.

## 임베딩 기여를 확인하는 고정 진단

주실험4개 외 C1_NO_EMBEDDING/C3_NO_EMBEDDING은 동일 규칙·관점허용·동점조건에서 정규화된 의미성분만 모든사례0.5로 고정한다. 임베딩 성분을 제거했을 때의 순위/지표 변화로 현재 점수항의 조건부 기여를 확인한다. 별도 모델선정·새 집계 후보가 아니며 좋은 진단만 고르지 않는다. 다른 임베딩 모델보다 BGE-M3가 우수하다거나 임베딩이 기능을 정확히 이해한다고 주장할 수 없다.
