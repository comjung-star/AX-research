연구 질문은 ‘업무문제를 여러 관점으로 보존하면 단일 질의보다 유용한 AX 사례와 전략을 더 잘 발견하는가’입니다. 현재 구현은 검색·매핑의 개발 검증 단계입니다.

|구분|검토 내용|
|---|---|
|입력|한국어 업무문제 → 실시간 LLM 문제 관점 1~6개|

|후보|검토 이력이 있는 112사례; Task·Problem·Context와 출처 연결|
|A|18개 기능 규칙. Task의 긍정 실행 구절에 근거하며 33사례 기능 미인식|
|B|BGE-M3 1024차원. Task .4 / Action .2 / Object .2 / Output .1 / Context .1; 양쪽 가용 필드만 가중평균|

|검증|실제 로컬 추론과 과거 실시간 API 시연 기록, 독립 실행기 108 tests pass. 테스트 통과는 추천 정확도 증명이 아님|

## 시연 시 확인할 사항

1. 자연어 문제에 근거한 관점이며 해결책을 미리 제시하지 않는가?
2. 관점별 Top5가 보존되고 최종 Top5의 Task·Action·Object 근거와 출처를 추적할 수 있는가?
3. 단어만 같은 후보와 수행 기능이 같은 후보를 구분하는가? 미인식·약한 근거 표시를 확인한다.
4. 관점 추가의 이득과 규칙/필드 매핑의 이득을 어떤 통제 실험으로 분리할 것인가?
5. 사람 검토와 독립 질문/판정 절차를 어느 범위까지 보완한 뒤 Test를 실행할 것인가?

## FAQ

**원문도 참고하는가?** 관점 생성에는 사용자 원문을 제공한다. 검색에는 원문 경로와 각 관점 경로를 따로 유지한다. 정밀 매핑 결과의 점수를 마지막에 결합한다.

**원문은 원 출판물 전체인가?** 이 검색 설명의 원문은 사용자 업무문제다. 사례는 저장된 Problem/Task/Context 요약으로 비교한다. 원 출판물 링크를 매 검색마다 새로 읽거나 사실을 재검증하지 않는다.

**신경망 전체가 완성됐는가?** 현재 A/B/C는 검증용 매핑 구현이다. 목표 아키텍처의 학습형 상호작용, 근거 결합, 전략 추천 전체의 완성·효과를 뜻하지 않는다.

**47.58%는 실제 정확도인가?** Dev AI-Silver 기준의 Macro F1@5다. 질문별 양성 수가 희소하고 평가자 독립성과 일반화 검증이 부족하다.

**GitHub 링크만 열면 시연 가능한가?** 공개 저장소이므로 로그인·초대 없이 문서와 코드를 검토할 수 있다. 앱은 Python 환경·로컬 모델·API 키를 준비해 실행하며 검색마다 API 요금이 발생한다.
