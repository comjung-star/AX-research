## 별도 AI 검토를 실제로 어떻게 했는가

1. 최초 Problem/Task/Context 묶음에서 문맥에 제품·해결 정보가 보일 수 있다는 지적이 나왔다. **그 탐색 결과는 최종 요인 라벨에 사용하지 않았다.**
2. 새 대화 문맥의 별도 AI 검토자 3명에게 식별 ID와 **업무 문제 문장만** 전달했다. 기업명·원문·Task·Context·구현·성과·작성자 라벨·전략은 전달하지 않았고, 외부 조회도 금지했다. 이 보수적 설계 때문에 근거 부족 시 보류를 허용했다.
3. 다른 검토자들은 Task/Implementation만 보고 7개 전략 또는 보류를 골랐다. 한 응답은 예시 스키마를 S1만 허용하는 것으로 오독해 전체 51개를 같은 입력으로 재검토했다. 기존 작성자 라벨을 보여주어 교정하지 않았다.
4. 원문 대조로 달라진 문제 3개와 구현/업무 7개는 별도 새 문맥에서 재검토했다. 입력이 바뀌었는데 옛 검토를 재사용하면 검증기가 실패한다.
5. 두 분류가 모두 있는 72개만 다시 다른 검토자에게 직접 적용 관계를 확인시켰다. 4개 관계는 근거가 충분하지 않아 뺐다. 요인과 전략 이름표가 둘 다 있다고 관계를 자동 생성하지 않았다.

유효 검토 세션 9개의 실제 ID, 전달 프롬프트, 입력, 응답을 남겼다. 이는 **서로 문맥이 분리된 AI 검토**이며 인간 합의, 외부 학자의 검증, 서로 다른 모델 계열의 재현성 검증은 아니다. 검토자에게 숨긴 정보와 공개된 정보를 혼동하지 않는다.

## ‘보류’가 남았는데 왜 스냅샷을 확정하는가

이제 보류는 **검토하지 않은 빈칸이 아니라 검토 결과로 정한 값**이다. 충분한 분류 근거가 없으면 원문에 확인된 운영 사례를 유지하되 그 라벨을 비워 둔다. 학습·통계에서 해당 라벨이 필요한 행은 제외한다. 보류를 다수결이나 작성자의 직감으로 채우지 않는다.

- 요인 25개에는 기존 세 사례뿐 아니라, 실제 Blind RCA에서 과도한 기존 분류가 드러난 사례가 포함된다. 개인화·접근성·설명 필요를 전문가 의존이나 예측 복잡성으로 자동 치환하지 않는다.
- 전략 2개는 BNY 거래문의 처리와 Cashfree 지원 이메일 작성이다. 실제 운영은 확인되지만 현재 7분류 중 어떤 구현 전략이 우선인지 공급 자료만으로 자신 있게 고르지 못했다.
- 두 라벨이 있는 72개 중 Danone 주문가격 검증, Cashfree 온보딩 웹 검토, Suzhou 일정 조정, Relativity 문서검토의 4개 직접 관계는 보류다. 원문 문제가 더 넓거나 구현 설명이 해당 요인을 직접 해결한다고 단정하기 부족하다.
- `null` 및 빈 CSV 라벨은 명시적 보류다. 누락 데이터와 구분되는 검토 사유가 JSON에 있다. Cartesian 요인×전략 조합은 없다.

따라서 데이터와 AI 주석의 버전은 확정할 수 있지만 **사람이 검증한 Ground Truth, 최종 모델 성능 평가셋 또는 인과효과 데이터가 완성됐다는 뜻은 아니다.** 이 구분은 제한을 숨기려는 명칭 변경이 아니라, 사용자가 허용한 AI 검토를 실제 수행한 뒤 산출물의 검증 수준을 명시하는 것이다.

## 파일·재현·변경 방지

최종 진입점은 [data/v2/README.md](../data/v2/README.md)다. `main_cases_v2.json`과 `main_cases_v2.csv`에 같은 98개를 제공하고, `release_manifest_v2.json`은 JSON 구조를 정규화한 SHA-256과 입력 해시를 기록한다. 이는 파일 바이트 해시와 구분되며 운영체제 줄바꿈에 흔들리지 않는다. 별도 `strategy_taxonomy_v2_frozen.csv`에 AI 검토된 7분류를 고정하고 기존 작업 사전과 v1은 그대로 둔다.

```text
python scripts/build_v2_final_release.py --check
python scripts/validate_v2_release.py --freeze
python scripts/validate_v2_evidence.py --check-immutable
python -m unittest discover -s tests -p "test_v2*.py" -v
```

로컬 v2 테스트 **72개 통과**, 최종 동결 검증 통과, 원본 데이터·과거 실험 **97개 파일 보존 검사 통과**. 생성 파일·CSV·manifest 변조, 검토 입력 변경, 블라인드 입력의 해결정보 혼입, 검토 누락, 보류 강제 채우기, 잘못된 계보, 군집 분리, 관계 곱집합 및 인간 GT 자칭을 검사한다. 프로그램은 공급사 주장 자체가 사실인지 자동으로 증명하지 않는다.

원래 staging 검증기들은 역사적 94부모/101후보를 검증하므로 여전히 승인 0과 동결 금지를 출력한다. 역사적 판정을 덮어써 숫자를 맞추지 않았다. **최종 산출물 동결은 새 release 검증기가 담당한다.**

## 연구 사용 한계

목적·편의 표집이며 동일 기업·원천·부모 사례가 연결돼 있다. 98개를 모두 독립 통계 표본으로 계산하지 않는다. 새 실험 전 67개 `sampling_group_id` 단위로 분할하고, 라벨별 표본 부족 및 보류 제외 규칙을 사전에 정해야 한다. S7의 반복 근거 4개는 이미지/콘텐츠 분류 경계 확인을 위한 목적 표집이다. 산업·전략 비율은 모집단 비율이 아니다.

기존 v1·Ground Truth·Stage 1~3 실험은 역사적 산출물로 보존했다. 새 v2 검색, 관련성 GT, Wald 분석과 main 병합은 수행하지 않았다. 이는 이번 데이터셋 구축 작업의 미완료 항목이 아니라 별도의 후속 연구 단계다.
