# 후속 검색 단계 대조: 후보 발견과 최종 승격을 분리

행동·대상 근거를 함께 요구해도 개발F1이 감소했고, 관점은 후보Recall만 개선했다. 따라서 해당 최종 승격기는 채택하지 않는다. 최종DenseTop10은 그대로 두고 후보Top20만 보완하는 검색 단계 대조를 한다. 이 설계는 F1@5와nDCG@10을 Dense와 같게 유지하도록 만든 것이며, 두 지표의 향상으로 제시하지 않는다.

다음 네 검색 조건을 한 번만 비교한다: Dense20, 원문TokenHybridTop20의 후보 보완, 수정된 원문BM25Top20의 후보 보완, 각 E관점DenseTop20의 후보 보완. 모든 조건은 Dense20에서 시작해DenseTop10을 유지하며, 나머지10개 교체에는 앞선 원문Hybrid/행동/대상3값 엄격 우위 조건을 그대로 쓴다. 각 검색 경로는Top20까지만 후보를 제안한다. 모든112위치를 순회했던 앞선 대조가 관점 고유 이득의 증거로 오해되지 않도록 강한 원문 대조와 검색 깊이를 고정한다.

원문Token은 이미 계산한112개 원문 토큰 점수를 사용한다. BM25는 기존SL/SN복구 tokenizer를 사용하고 같은Problem/Task/Context 문서를 색인한다. 후속 후보20·최종5예산은 같지만, 실제 원문 토큰 점수112개 및 관점별 검색의 추가 계산량을20개 정밀 계산 비용으로 축소해서 보고하지 않는다. 후보 보완 뒤 원래Dense순서로 정렬해 Top10불변을 확인한다.

핵심 지표는 후보Recall@20, Dense20밖 새 양성 사례, 이탈한 양성 사례, 원문Token/원문Sparse 대비 관점의 추가 발견이다. 세 고정 개발 정답에서 각각 보고한다. 새40질문·새API·정답 변경·가중치 탐색은 없다. 결과가 좋아도 검색 단계의 관측 개선이며 최종 추천 개선 또는 전략/관점Gold coverage입증으로 표시하지 않는다.
