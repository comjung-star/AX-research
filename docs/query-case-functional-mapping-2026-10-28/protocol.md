## 결과를 보기 전 고정할 사항

- functional_mapping_20261028.json의 이중언어 기능 문법, 원문 위치, 점수 정의와 최종 정렬식을 고정한다. 이는 사람이 정한 실험 규칙이지 사람 Gold가 아니다.
- 18종의 행동-대상-산출물 기능 생산규칙을 사용한다. Task의 긍정 구절에서 행동과 대상이 120자 이내에 함께 확인될 때만 실제 기능을 인정한다. 산출물은 동사의 통상적 기능 유형으로 표시하며, 원문에 별도의 산출물 명시가 없으면 별도 확인되지 않았다고 기록한다. 성과·보안·효과를 만들어내지 않는다.
- Problem/Context의 공통성은 설명에 쓰되 Task에 없는 수행 기능을 승격하지 않는다. 명시 부정·미래·필요·제안 구절은 보수적으로 보류한다. Context만으로 새 기능을 인정하지 않는 제한도 보고한다.
- 한국어/영어 동의표현을 일반적 작업 분류로 정규화한다. 문법의 범위 밖이거나 뜻이 애매하면 UNKNOWN으로 표시한다. 0은 무관 정답이 아니다. 작업명에 쓰인 명사형도 규칙 범위 내에서 해석한다.
- 점수 0~4는 규칙 근거 강도이며 Silver 관련도/확률이 아니다. 공유 기능의 비율과 누락 기능을 별도로 남겨, 일부 기능 일치를 전체 문제 해결로 포장하지 않는다.
- 원질문과 108개 관점을 각각 매핑한다. 관점에 기능이 없으면 원질문을 몰래 덧붙이지 않고 보류한다. 최종 단계에서 원질문 점수와 관점 최고점수를 함께 사용한다. 관점점수를 더하지 않는다.
- 모든 경로에서112개 후보 유지. 매핑 입력은 라벨이 없는 이전 여섯 자료와 검색 점수뿐이다. 알고리즘에 case/query ID 기반 조건, Silver, 이전 관련 사례 목록을 넣지 않는다. ID는 조인/동점 정렬만 한다.
- 전체/관점 최고 근거, 전체 문제 근거, 관점 최고 근거, 기존 하이브리드 점수, 사례ID 순으로 정렬한다. M_D_SINGLE을 주 추천 조건으로 고정, original-only 및 3View는 보조 비교다. 새 RRF/비중 탐색 없음.
- Stage2 매핑과 Stage3 순위를 먼저 별도 저장·커밋한다. Stage4 Dev 평가에서만 Silver를 읽는다. 사용자가 이미 필수 사례와 과거 결과를 제공했으므로 연구 설계자에게 완전 눈가림된 실험이라고 주장하지 않는다.
- 원질문 Single/3View, RR, RRF, 원질문+관점 RRF, 하이브리드의 기존 전체 순위를 그대로 비교한다. 같은 최종 K, 같은112 사례. 동적 결과는3회→질문별평균→Macro; 원질문은1회.
