# 결과 해석: 의미 단독은 하락, 결합은 Q1에서만 제한적 개선

2026-10-28 KST. 기준 `be64f9c1f742ecaa6410eeaab97da11ebc6e7f13`.

사전 고정한 BGE-M3 의미 단독은 기존 규칙 기반 정밀 매핑을 능가하지 못했다. 규칙+임베딩 결합은 F1@5와 F1@10에서 각각 약 1.481%p, 1.667%p 높았고 F1@20은 같았다. 개선은 고객문의 Q1에 집중되며, 다른 양성5질문의 성능은 규칙과 같다. 따라서 의미 매핑 전반의 우월성이나 일반화가 확인됐다는 결론은 내리지 않는다.

## 같은 Dev·같은 Silver·같은 후보에서의 결과

원질문과 기존 동적관점을 유지한 Single 조건이다. 수치는 %이며 3회→질문별 평균→Macro 순서다. P는10문항, R/F1은 양성6문항을 사용한다. 무양성4문항의 R/F1은 결측이며 0으로 채우지 않는다.

규칙 대비 의미 단독은 F1@5/10/20에서 모두 낮다. 결합은 작은 K에서 관련 사례의 위치를 바꾸었으며, K20의 기존18양성쌍 회복 범위를 넓히지 않았다. Macro F1은 질문별 F1 평균이므로 Macro P/R을 다시 조화평균한 값과 다를 수 있다.

기존 검색14조건과 규칙4조건을 그대로 재계산해 과거 수치와 정확히 일치함을 확인했다. 의미4조건·결합4조건을 추가해 총26조건을 비교했다. 새 순위는 8조건 합계160개 질문/회차별 전체112순위다. 사전 계획의 '8조건80회차별'은 두 변형이 공유하는80개 후보 풀을 뜻하며, 저장한 새 순위 수는160개가 정확하다. 원질문/관점·Single/3View 전체 P/R/F1과 질문별 변동은 `evaluation/`에 있다.

Single/3View의 새 의미 순위가 같은 것은 정상이다. 이 실험은 동일한 필드 임베딩과 점수식을 두 기존 후보 풀에 적용하고 기존 검색점수는 동점 처리에만 쓴다. 새 3View 신경망을 훈련하거나 검색 인덱스를 바꾼 실험으로 해석하면 안 된다.

의미 단독의 명확한 손실은 Q3 `AXV2N_0110`이다. 실제 Task는 `Retrieve internal knowledge for financial advisors`인데 규칙3/3/2위가 의미22/26/24위로 내려가 모든 K에서 놓쳤다. 결합은3/3/3위로 유지했다. 문서·내부지식 검색 기능이 유사해도 짧은 Task와 금융 자문 맥락이 문장 유사도 순위에서 충분히 높아지지 않은 사례다. 이를 모델이 금융이라는 단어 때문에 틀렸다고 인과적으로 단정할 수는 없다.

Q8 `AXV2C_0050_01`의 실제 Task는 `Forecast daily store-item demand`다. 규칙5/5/5위가 의미6/6/4위가 되어 두 회차 Top5에서 빠졌으며 결합은5/5/5위다. 의미 단독은 Q1 일부 사례를 끌어올리는 동시에 다른 질문의 관련 사례를 내렸다. 원문과 전체 비교는 `evaluation/rank_changes.csv`, 회차별 신규/유지/손실과 새 Silver 음성 진입은 `evaluation/related_changes.json`에 저장했다.

## 규칙 미인식 33사례: 비교 범위는 넓혔지만 회복 효과는 측정 불가

기존 규칙이 기능을 인식하지 못한33사례 전부에 Task 임베딩을 만들었다. Action은17사례, Object 잔여 구절은33사례, Context는33사례, 명시 Output은1사례에서 얻었다. Action을 못 읽은16사례도 Task 전체 의미 비교를 수행했고 후보에서 제외하지 않았다.

그러나 기존 Silver에서 이33사례의 양성 질문-사례쌍은 **0개**다. 따라서 '33사례를 의미 방식으로 살려 Recall을 개선했다'는 주장은 성립하지 않는다. 이 실험이 확인한 것은 비교 가능한 표현의 범위를 넓혔다는 점이다. 실제 관련 사례가 있는데 Silver가 놓친 것인지, 이10질문에는 실제로 관련이 없는지는 새 독립 라벨 없이 판정할 수 없다. 상위 진입도 기존 Silver 기준으로는 음성이며 의미 이해 성공으로 세지 않았다.

개별33사례의 Task·필드·미확인 목록은 `mapping/unknown33.json`, 전체 관련도·규칙/의미/결합 순위는 `evaluation/unknown33_ranks.csv`와 `unknown33_analysis.json`에 있다.

## 다섯 필드를 설계한 것과 다섯 필드를 실제 검증한 것은 다르다

사례112개에서 Task112, Action88, Object112, Context112, Output1개가 존재한다. 질문/관점118경로에서는 Task118, Action83, Object118, Context13, Output0개다. 따라서13,216쌍 중 실제 점수에 사용된 구성은 Task13,216쌍·Object13,216쌍·Action7,304쌍·Context1,456쌍이며 **Output 비교는 0쌍**이다.

산출물을 임의 생성하지 않은 결과이며, 이번 데이터로 Output 분리 비교의 효과는 검증하지 못했다. 구현은 다섯 필드를 지원하지만 실제 평가는 부분 필드 가용성 아래 이루어졌다. Object가 모든 경로에 존재한다는 것도 모두 정확한 의미역을 얻었다는 뜻이 아니다. Action을 제거한 잔여 원문이어서 동작 주체나 수식어가 남을 수 있다. Context 추출은 질문13경로에만 존재해 사례와 비대칭이며, 누락 때 분모를 바꾸는 방식도 순위의 한계다. 이 제약을 숨기고 '실제 Task/Action/Object/Output/Context를 모두 정확히 이해했다'고 결론내리지 않는다.

## 보존·누수 방지·재현

고정112사례·10질문·108관점·기존 후보와 검색랭킹·18규칙·Silver를 수정하지 않았다. 기존 tracked 파일 변경은0개다. 독립 Stage4 Test는 열람·실행하지 않았으며 새 유료 API·새 관련도 라벨·파인튜닝은0이다.

`preregistration.json`의 설정/코드/모델/입력 해시를 추론 전에 고정했다. 별도 추론 프로세스는 Silver를 읽지 않고13,216쌍 매핑과 전 예측을 만든 뒤 `prediction_receipt.json`을 저장했다. 평가 프로세스는 두 봉인을 확인한 후 Silver를 읽었다. 알고리즘은 결과 후 수정하지 않았다. 저장 임베딩으로 전체 cosine·점수·순위를 재생하고 평가값도 다시 계산하는 테스트를 추가했다. 후속 분석 문서와 검증 테스트는 평가 뒤 작성한 산출물이며 사전등록 코드로 위장하지 않는다.

설계자가 이전 Dev 예시를 이미 아는 제한이 남고, 로컬 해시는 독립 타임스탬프 공증도 아니다. BGE-M3 모델은 기존 로컬 파일의 정규화 CLS를 사용했으며 다운로드하지 않았다. 설정·버전·모델 해시·원문 조각·전체순위·지표·변경사례를 저장해 재현 경로를 남겼다.

현 단계에서는 기존 규칙을 유지하고 결합 방식은 제한적 Dev 개선 후보로 보관한다. 의미 단독으로 교체할 근거는 얻지 못했다. 독립 Test 개봉이나 새 설정 탐색은 이번 작업에 포함하지 않는다.
