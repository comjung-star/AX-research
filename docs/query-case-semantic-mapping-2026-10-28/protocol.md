## 의미 매핑 입력과 분리

원질문과 각 관점은 각각 처리한다. 관점에 원질문을 덧붙이지 않는다. 사례 Task는 기존 구조화 Task 문자열의 긍정·실행 구절만 사용하고 기존 보수적 부정/미래 가드를 유지한다. 사례 Problem은 추적 설명에만 사용하고 점수에 넣지 않는다. Context가 Task 실행을 대신 증명하지 않는다. 구현·전략·성과·Silver·ID는 임베딩 입력이 아니다. 원 출판물 사실성을 새로 검증하지 않는다.

Task 전체, Action, Object, Output, Context를 별도로 임베딩하고 같은 필드끼리 cosine을 비교한다. Action은 18개 업무 유형과 무관한 넓은 이중언어 표면 패턴이며, Object는 Action을 제외한 연속 원문 조각이다. 이는 정확한 의미역 분석기가 아니다. 명사구·수식 범위를 오인할 수 있으며 불명확한 조각도 기록한다. 어떤 Action을 못 읽어도 긍정 Task 전체는 의미 비교할 수 있다. Output은 `outputs/produces/returns/results in` 또는 `산출물/출력/결과물:` 뒤의 원문만 인정한다. 동사만 보고 산출물을 만들어내지 않는다. 원질문의 Context는 명시 범위/행위자 구절만 사용한다. 사례 Context와 다른 추출 품질이라는 제한을 보고한다. `UNKNOWN`은 무관 정답이 아니다.

가중치는 Task .4, Action .2, Object .2, Output .1, Context .1. 양쪽에 존재하는 필드만 분모에 넣는다. Task가 없으면 UNKNOWN_TASK(-1)이며 Context로 구제하지 않는다. 부분 필드 누락으로 항목별 분모가 달라지는 한계를 기록한다. 원문 조각·시작/끝 위치·개별 cosine·가용 가중치·전체/관점점수를 저장한다. CLS 1024차원, L2 정규화, CPU float32, max_tokens4096, 실제 토큰길이 검사로 잘림 금지, batch8, seed20261028, threads4. 모델은 eval 추론만 수행한다.

## 세 방식과 정렬식

규칙 단독: 기존 `M_O_SINGLE/M_D_SINGLE/M_O_THREE/M_D_THREE` 저장 순위를 그대로 사용한다.

의미 단독 SEM: 원질문만 쓰는 O는 whole score. 관점 유지 D는 `(whole score + max(branch score))/2`. 관점 중복은 가산하지 않는다. 결합 COMB는 `0.5*(max(whole_rule,best_branch_rule)/4) + 0.5*((SEM+1)/2)`. 두 방식 모두 점수 내림차순→기존 풀 검색점수 내림차순→case ID 오름차순. 주 조건 `SEM_D_SINGLE`, 규칙 및 결합 D_SINGLE이 핵심 비교. O 및 3View는 사전 지정 보조조건이다. 과거 검색 14조건도 기존 결과를 참조한다. RRF를 새 제안 모델로 도입하지 않는다.

가중치·혼합비·임계값 탐색 없음. 합성 단위 테스트는 코드 계약 확인이며 실제 의미 정확도 라벨이 아니다. 성능 결과를 본 후 설정·사전·랭킹 코드를 수정하지 않는다. 필요할 경우 다음 실험으로 별도 기록한다.

## 실행 순서와 평가

설정/추론 코드/평가기/테스트/본 문서의 hash 및 모델·보존 입력 hash를 preregistration.json에 먼저 저장한다. 다음 라벨을 읽지 않는 추론 프로세스가 전13216쌍 매핑·8조건80회차별순위·프로필·임베딩을 저장하고 prediction_receipt.json으로 봉인한다. 평가기는 두 봉인을 검증한 후에만 Silver를 읽는다. 로컬 변경이므로 Git 커밋을 전제하지 않으며 hash 영수증은 외부 타임스탬프/독립 공증이 아니다. 재실행은 동일 해시만 허용한다.

P/R/F1@5/10/20. P는10문항, R/F1은 양성6문항; 무양성4문항의 R/F1은 NA. 각 질문의3회 평균 후 질문 Macro. 동일 K, 동일 후보. 신규/유지/손실 관련 사례를 규칙 및 각 비교방식과 질문×회차×K별로 저장하고 회차 사건 수와 고유 질문-사례 수를 구분한다. Silver 음성 상위 진입도 확인한다. 33개 규칙 미인식 Task 전부의 필드 가용성 및 순위·기존 Silver 관련 검색 회복을 분석한다. 제조 불량/고객 답변/HR QA 지정 사례의 실제 Task·Action/Object/Output/Context와 전체/관점 cosine 및 순위를 공개한다.

상대 성능이 낮거나 같아도 그대로 보고한다. 18양성쌍과10 Dev 질문으로 일반화·통계적 유의성·독립 정확도·실제 기능 판별 성공을 주장하지 않는다. 새로 찾음/잃음은 기존 Silver 기준이며 실제 정답의 신규 발견을 뜻하지 않는다.
