# 다중관점 후보 결합 방식 — 원인 분석과 고정 조건 비교

## ① 현재 문제는 무엇인가?

이번 문제는 후보가 검색 대상에서 사라진 것과, 최종20개 안에 들지 못한 것을 구분해야 한다. 과거 각 관점에는 이미112개 사례 전체의 순위가 저장돼 있었다. 따라서 이번 데이터에서 초기 후보 풀 자체의 누락은 없다. 후보를 한데 모았다는 사실만으로 검색이 좋아진 것도 아니다.

원질문 Top20은 Single에서 관련15쌍,3-View에서14쌍을 찾았다(전체 Silver 양성18쌍). 기존 다중관점 Round-robin은 생성 세 회차를 평균하면 각각13.33쌍,12.00쌍이었다. 관점별로 돌아가며 최종20개를 고르는 과정과, 생성 관점에서 달라진 원래 순위가 함께 영향을 준다.

아래는 원질문 Top20 양성이 Round-robin에서 누락된 기록을 추적한 결과다. ‘건’은 서로 다른 질문·회차의 사건이며, 같은 사례가 세 회차에 반복 등장할 수 있다.

|---|---:|---:|---:|---:|
|Single Dense|7|5|4|4|

이 누락 사례 중 어느 관점에서든5위 안이었던 사례는 두 구조 모두0건이다. 즉 여러 사례는 관점 검색 단계에서 이미 원질문보다 순위가 내려갔다. 반면 같은 관점 순위를 고정한 채 결합만 바꿔 되찾은 사례도 있으므로, 하락을 전부 검색 모델 탓이나 전부Round-robin 탓으로 돌릴 수 없다.

## ② 후보 결합 방식을 바꾸면 성능이 달라지는가?

모든 관점의112개 순위를 그대로 썼다. RRF 상수60, 관점별 동일 비중, 원질문과 관점 집계 경로의 비중1:1을 결과 계산 전에 고정하고 커밋했다. 상수나 비중을 탐색하지 않았다.

- 관점 RRF 점수 = 각 관점의 `1/(60+순위)`를 평균한 값.
- 혼합 점수 = `0.5×원질문의1/(60+순위) + 0.5×관점RRF평균`.
- 예를 들어 관점4개라면 원질문 전체 비중1/2, 각 관점 비중1/8이다. 관점이5개라고 원질문 영향이 줄어드는 방식이 아니다.
- 정확한 분수로 계산했고 동점은 사례ID 순이다. 원래 코사인 점수와 RRF를 섞지 않았다.112개 후보에서 중복 없는Top5/10/20을 뽑았다.

**Precision 평균은10개 질문, Recall·F1 평균은 양성 판정이 있는6개 질문**이다. Q2·Q5·Q7·Q9는 Recall·F1 평가 불가로 두었고0점을 넣지 않았다. 표는 질문 안에서3회 생성 결과를 먼저 평균한 뒤 원질문별로 평균했다. 원질문 단독은 한 번만 계산했다.

## ③ 실제 사례는 어떻게 달라졌는가?

필수 분석 대상인 고객 문의 질문(V21D001), Single Dense 첫 생성 회차의 실제 결과다.

|사례|원질문 순위|관점별 순위|RR 최종20|RRF 순위|원질문+RRF 순위|
|---|---:|---|---:|---:|---:|
|고객 도움말센터 질문응답|3|13, 13, 12, 10|제외|6|5|
|직원 HR 규정 질문응답|25|7, 47, 47, 40|13|27|25|

고객 도움말센터 사례가 빠진 정확한 이유: RR이20개를 고른 시점에 네 관점은 각각9·7·6·7위까지 확인했다. 이 사례는각각13·13·12·10위에 있었으므로 어느 관점에서도 아직 확인되지 않았다. 후보 풀에서 삭제된 것이 아니다.112개까지RR을 계속한 진단 순위는25위였다.

HR 규정 질문응답 사례는 첫 관점7위였다. RR13번째 선택에서 첫 관점의 중복3개를 건너뛰고 이 사례를 골랐다. 다른 세 관점에서는47·47·40위여서 여러 관점의 순위를 평균하는RRF에서는27위로 밀렸다.

따라서 RRF는 여러 관점에서 고르게 괜찮은 도움말센터 사례를 되찾았지만, 한 관점에서만 강했던 새로운 HR 사례를 잃었다. 원질문을 절반 섞어도HR 사례는25위로Top20 밖이다. 두 목표를 모두 만족했다고 보고하지 않는다.

다른 오류 경로도 보였다. 같은 회차의 ‘답변 품질의 일관성’ 관점은 **제조 품질 불량의 원인 분석 사례**를2위에 놓았고 RR은 이를 최종7위로 선택했다. 이 사례는 기존Silver에서 고객 문의 질문에0점이었다. RRF는28위, 원질문 혼합은33위로 내려Top20에서 제외했다. 이는 실제 순위와 기존 정답에서 확인한 사실이다. ‘품질’ 같은 넓은 표현이 기능을 흐렸을 가능성은 있지만, 어느 단어·필드가 원인인지는 이번에 분리 검증하지 않았다.

RRF가 이 무관 사례를 내리면서 유용한 HR 사례도 함께 내린 점이 중요하다. 둘 다 한 관점에서만 높았지만 실제 업무 관련성은 달랐다. 공통 순위 집계만으로 이 차이를 충분히 구분하기 어렵다는 후속 검토 근거다. `functional_mismatch_example.json`에 원래 점수와 모든 계산 항을 저장했다.

Top20에서 RR이 새로 찾았던 관련 사례의 유지 여부도 따로 확인했다.

|구조|바꾼 방식|RR의 신규 발견 사건|그중 유지|그중 다시 누락|새로 생긴 원질문 관련 누락|
|---|---|---:|---:|---:|---:|
|Single Dense|관점 평균 RRF|2|0|2|0|
|Single Dense|원질문1/2 + 관점RRF1/2|2|0|2|0|
|3-View Dense|관점 평균 RRF|5|5|0|2|
|3-View Dense|원질문1/2 + 관점RRF1/2|5|3|2|2|

**3-View의 순수 RRF에서는 두 목표가 부분적으로 함께 좋아졌다.** RR의 신규 발견5건을 모두 유지하고 새로2건을 더 찾았으며, 기존 관련 사례의 전체 누락은11→9건으로 줄었다. 다만 누락을 모두 해결한 것은 아니고 원질문 단독의 전체 성능을 넘지는 못했다.

원질문 혼합은 RR의 기존 누락8건을 되찾지만, RR이 유지하던 다른 원질문 관련 사례2건을 새로 놓친다. 따라서 원질문 대비 전체 누락은11→5건이다. 이때 RR의 신규 발견5건 중2건을 잃었다. ‘8건 복구’, ‘순누락6건 감소’, ‘신규 발견2건 손실’을 구분했다.

같은 HR 사례도 3-View 첫 회차에서는 원질문20위·RR17위였지만 RRF24위·혼합22위가 됐다. 원질문에 비중을 절반 준다고 원래Top20을 반드시 보존하는 것은 아니다. 모든 질문·반복의 원문Task·순위 이동과 계산 항은 `case_rank_changes.csv`, `rrf_score_details.json`, `rr_novelty_retention.json`에 있다.

## ④ 가장 좋은 결과는 무엇인가?

|K|새 후보 결합 조건 중 최고F1|F1|원질문 단독까지 포함한 최고F1|
|---:|---|---:|---|
|5|3-View Dense 원질문1/2 + 관점RRF1/2|39.71%|3-View Dense 원질문 단독 41.19%|
|10|Single Dense 원질문1/2 + 관점RRF1/2|27.55%|Single Dense 원질문 단독 28.11%|
|20|Single Dense 관점 평균 RRF / Single Dense 원질문1/2 + 관점RRF1/2|18.81%|Single Dense 원질문 단독 19.92%|

Top20에서는 Single의 RRF와 원질문 혼합이 동률18.81%로 RR17.95%보다 높았다. 하지만 원질문Single 단독19.92%에는 못 미쳤다. 3-View에서는 혼합18.07%가 RR16.25%보다 높았지만 원질문3-View18.81%보다 낮았다. 좋은 상수나 비중을 찾아낸 최적화 결과가 아니라 사전에 고정한 조건의Dev 관찰이다.

세부 목표도 다르다. 3-View에서 신규 발견의 유지를 우선하면 순수RRF가, 기존 사례 복구를 우선하면 원질문 혼합이 더 나았다. 두 방식 모두30개 질문·회차에서 관련 발견 총40건이지만 질문별로 찾은 사례가 달라 MacroRecall·F1은 다르다. 하나의 지표에서 좋은 방식이 모든 목표에서 가장 좋다고 주장하지 않는다.

## ⑤ 교수님 피드백과 얼마나 부합하는가?

- 관점별 후보·순위·원래 유사도·선택 출처를 끝까지 보존했다. 각 분기의 전체112개를 통합해 후보 절단 때문에 좋은 사례가 사라지는 조건을 제외했다.
- 기존에도 전체112개가 있었으므로 Candidate Union 자체의 효과는 주장하지 않는다. 같은 후보에서 어떤 점수로 최종 순서를 정하는지가 실제 변경이다.
- 같은 분기 순위를 고정한 RR→RRF 변화는 결합 규칙의 관찰된 효과로 볼 수 있다. 원질문 혼합은 원질문 순위 경로도 추가하므로 두 효과를 같게 취급하지 않는다.
- 이번 RRF는 순위를 집계하는 비학습 비교 조건이다. 교수님 구조의 Query–Case 정밀 매핑·학습형 재평가를 구현했다고 주장하지 않는다. RRF60과1:1은 이번 사용자 지시의 실험 선택이며 교수님 승인 파라미터로 표현하지 않는다.
- 일부 설정에서 신규 발견 유지와 기존 누락 감소를 함께 확인했지만, 모든 사례를 동시에 보존한 것은 아니다. 최종 독립Test는 계속 봉인했다.

## ⑥ 다음에는 무엇을 개선해야 하는가?

1. **원질문·관점별 Query–Case 정밀 매핑**: 공통으로 괜찮은 사례와 한 관점에서만 유용한 사례를 구분하고, 원질문 관련성을 유지하는지 먼저 확인한다. RRF가 HR 질문응답과 무관한 제조 품질 분석을 모두 내린 문제가 직접 근거다. 현재Silver18양성에 맞춰 학습과 검증을 같이하지 말고 개발·검증 설계를 먼저 고정한다.
2. **검색 관점 생성 품질**: RR 누락 사건 중 어느 관점에서든5위 안이었던 경우가0건이다. 예를 들어 고객 질문이 시간 부담·품질 일관성 등으로 나뉘면서 실제 답변 업무의 순위가 밀렸을 가능성이 있다. 이는 의미 변화가 원인이라는 가설이며 새 관점 생성 실험 없이 확정하지 않는다.
3. **P/T/C 가중치 비교**: 같은 결합에서도 두 Dense 구조의 차이가 남았다. 어떤 필드가 관련 작업을 밀어내는지 분리해 볼 가치는 있지만 이번에는 기존1/3가중치를 유지했다. 새 가중치의 우수성을 여기서 주장하지 않는다.
4. **Dense+BM25 하이브리드**: 이번은 결합 원인 분석이라 새로 구현하지 않았다. 어휘 검색이 빠진 사례를 보완하는지는 별도 통제 실험에서 확인해야 한다. 현재 결과만으로 효과를 예측하지 않는다.
5. **BGE-M3 추가 학습**: 마지막 순서다.112개 사례·18양성쌍·동일모델Silver만으로 추가 학습 후 같은 질문에서 검증하면 과적합 우려가 크다. 정밀 매핑·관점 품질·평가 자료를 확보한 후 필요성을 판단한다.

위다섯작업은이번에구현하거나실행하지않았다. 본비교외파라미터탐색·추가평가·모델호출도없었다.

## ⑦ 최종 결론

**후보 결합 방식은 성능 하락의 일부 원인이지만 전부는 아니다.** 같은 관점 순위에서 RRF로 일부 누락을 복구했다. 원질문 정보를 추가하면3-View에서 복구가 더 늘었다. 그러나 관점 검색 순위의 하락과 단일 관점 발견의 소실도 남아 원질문 단독을 일관되게 넘지 못했다.

위 판단은 **이번에 시험한 RR·RRF60·1:1 혼합의 범위**다. 관점별 순위가 원질문보다 내려간 사실은 확인했지만, 생성 품질이나 P/T/C 계산을 따로 바꾸지 않아 원인별 기여율을 추정하지 않았다. 다른 결합 규칙만으로 더 많이 복구할 가능성도 배제하지 않는다. 고정 RRF가 완전히 해결하지 못했다는 사실을 모든 결합 방식의 한계로 일반화하지 않는다.

확인된 사실은 모든 후보112개 보존, RR 선택 과정, 고정 조건의 순위 변화, Silver 기준 P/R/F1이다. 추가 검증이 필요한 가설은 관점이 전체 의미를 잃었는지, 어떤 PTC 필드가 문제를 만드는지, 정밀 매핑이 실제로 개선할지다. 결합 규칙 변경의 효과와 학습 모델·생성 품질의 원인을 혼동하지 않는다.
