# AX 연구 결과 인계 — 2026-11-10

**주요관점을 활용하는 방식에는 개선 신호가 있다. 추가관점을 더하는 효과는 아직 확정하지 못했다.** 현재 권고는 **B를 기본안, C를 선택적 추가 검토**로 두는 것이다. 이번 문서는 11월 8~10일의 성공·실패·중단·재개 기록을 함께 보존하는 최신 진입점이다. 기존 보고서의 ‘원격 저장소 변경 없음’ 등은 각 실험 종료 당시의 기록이다. 이번 정리에서 실험을 새로 실행하거나 유료 API를 호출하지 않았다.

## 1. 최신 결과를 먼저 보면

새 합성 질문 20개에 대해 같은 112개 사례를 전수 AI 채점했다. **2,240개 질문×사례 조합을 모두 완료**했다. 질문마다 세 방식의 고유 출력 개수를 똑같이 맞췄으며 평균 12.7개다.

|---|---|---:|

| B 주요관점 | 기본 5개 + 주요관점별 최대 5개, 부족분은 기본검색으로 U개까지 채움 | 36.2% |
| C 추가검토 | 기본 5개 + 주요·추가관점별 최대 5개의 합집합; 이 고유 개수가 U | 37.3% |

- B−A: **+5.14%p**, 질문별 개선 13 / 악화 1 / 동률 6. 주요관점의 보완 효과에 대한 탐색적 근거다.
- 사전 주 비교 C−B: **+1.05%p**, 질문 bootstrap 95% 구간 **−0.56 ~ +2.67%p**. 개선 6 / 악화 2 / 동률 12. 구간이 0을 포함해 안정적 추가효과로 확정하지 않는다.
- C−A: **+6.20%p**, 탐색적 구간 **+2.91 ~ +9.53%p**. 이는 주요관점과 추가관점이 합쳐진 차이이며 추가관점만의 효과가 아니다.
- C가 B보다 새로 찾은 유용한 쌍 22개, 놓친 유용한 쌍 16개로 순증 6개다. 질문×사례 쌍 기준이며 독립 사례 6개라는 뜻은 아니다.

**B의 36.2%는 기본검색 채움분을 포함한 결과다.** 기본 5개와 주요관점만 보여주고 채우지 않는 화면의 점수로 옮겨 쓰면 안 된다. C는 기본 5개와 주요갈래를 보존한다. C−B의 손실은 B에서 개수 맞춤용으로 채운 기본검색 결과가 교체된 것이다. 추천 전체를 최종 5개로 잘라낸 실험이 아니다.

## 2. 지금 구현한 방식

1. 사례에 실제로 적힌 문제·수행 업무를 분석해 관점 후보를 만든다.
2. 시범 관점 4개에 정의, 포함·제외 조건, 연결 사례와 근거를 붙인다.
3. 사용자 질문을 받은 LLM이 MAIN / ADDITIONAL / NONE을 선택한다. 미확인 가정은 사실과 구별한다.
4. 기본검색 결과와 선택 관점별 사례를 갈래별로 제공한다. 중복 사례는 합집합으로도 계산한다.

P01은 업무 지식 탐색, P02는 비정형 정보 정리, P03은 문서·자료 대조, P04는 문의 응대 용량·시간대 공백이다. ‘현업/운영/기술’ 3직무 관점이나 임베딩의 P/T/C 3필드와는 다른 개념이다. 17개 후보 중 4개만 상세 시범화했으므로 모든 업무를 대표하는 완성 목록이 아니다.

처음에는 17개 사례·18개 연결이었다. 112×4 조합 검토와 경계 오류 보류 후 현재 **49개 사례·53개 연결**이다. 나머지 63개를 억지로 분류하지 않았다. 기존 배정에 노출된 동일 모델 계열 검토와 저장된 P/T/C 요약 대조이며, 사람의 독립 검토나 원 출판물 전수 재감사는 아니다.

## 4. 데이터와 ‘검증 완료’의 의미

- 기존 **84×30**, 이전 **112×20**, 최근 **112×새20(VQ001~020)**은 같은 정답지가 아니다. 앞선 두 집합의 라벨을 새 업무 적합성 기준의 정답으로 그대로 옮기지 않았다. 과거 숫자의 정의·라벨 변경 이력은 해당 실험 원본을 따른다.
- 최신 질문 작성 요청에는 기존 질문·사례·관점·검색점수를 주지 않았다. 하지만 미리 정한 업무 주제로 만든 합성 질문이며 실제 사용자 무작위 표본이 아니다. 알려진 이전16질문과 정확히 같은 문장은 없지만 의미상 질문군 중복은 가능하다.
- 같은 112사례를 계속 사용했고, 112레코드는 83개 출처/누수 그룹에 속한다. 사례별 완전 독립이나 새 사례 데이터셋 일반화로 해석하지 않는다.
- 작성·선택·채점은 OpenAI `gpt-5.4` 계열의 별도 요청이다. 선택기 입력에 채점 정답을 넣지는 않았으나 모델 공통 편향은 남는다. AI 평가표는 인간 Gold가 아니다.
- ‘파싱/계약 검사 통과’는 응답이 읽히고 필드·인용 규칙을 지킨다는 뜻이다. **선택 관점이나 관련도 판단이 맞다는 보증은 아니다.** 최초8개에서 정상 API 응답으로도 의미 오류가 발생했다.
- ‘전수 채점 완료’는 미평가 칸 없이 평가표를 채웠다는 뜻이다. ‘재현 검증 완료’는 고정 입력·같은 출력수·보존 규칙·계산 결과·원본 해시를 확인했다는 뜻이다. 두 표현 모두 사람 정답 검증이나 논문 전체의 성능 입증을 뜻하지 않는다.
- 최신20개는 기본안을 결정하는 데 사용했으므로 이후에 미사용 최종 Test로 재명명하지 않는다. 이번 최근 실행은 Test15를 열지 않았지만, [기존 기록](../improvement-results-final.ko.md)은 **과거 노출 이력**을 명시한다. 따라서 전체 연구 역사에서 한 번도 열지 않은 Test라고 주장하지 않는다.
- Claude는 크레딧, Gemini는 할당량 제약이 있었다. 초기112사례/8질문 평가에서 Gemini의 질문 전체 채점은 1개뿐이다. 최신20개는 OpenAI 단독이며 ‘3종 AI 독립 평가 완료’가 아니다.

## 6. 논문 주장과 다음 판단

지금 쓸 수 있는 주장은 **‘사례 근거 관점 목록과 질문별 선택이, 이 합성 질문·동일 모델 평가·같은 출력수 조건에서 기본검색을 보완했다’**이다. 추가관점만의 일관된 이득, 인간 평가 정확도, 보편적 다양성 향상은 아직 입증하지 못했다.

## 7. 재현과 보존

실험 코드·설정·실패 결과·원본 요청/응답·중단/재개 기록을 함께 보존했다. 비밀키와 로컬 사전학습 모델·캐시는 포함하지 않는다. 원문 출판물 전체 파일을 새로 추가하지 않으며 자료는 기존 구조화 요약·근거 인용 중심이다. 자동 비밀정보 검사 결과와 보존 해시는 [파일 목록](artifact-manifest.json), 오프라인 확인 결과는 [검사 기록](verification.json)에 기록한다. 자동 검사는 개인정보·저작권의 포괄적 법적 감사를 뜻하지 않는다.

Python 환경과 프로젝트 의존성이 준비된 저장소 루트에서 아래는 **저장된 자료만으로 하는 검증**이다.

```powershell
$env:PYTHONPATH='src;.'
$env:PYTHONUTF8='1'
python -m scripts.perspective_omission_validation20_20261110 verify
python -m pytest -q tests/test_perspective_omission.py tests/test_perspective_boundary.py tests/test_perspective_panels.py tests/test_panels_full112_metrics.py
```

원래 실행 파일에는 당시 로컬 경로·모델 의존성이 남아 있다. 새 머신에서 임베딩 생성·모델 재학습·API 재실행까지 자동 재현된다고 보장하지 않는다. `author`, `select`, `judge`, `run` 등의 생성·채점 동작은 비용이 생길 수 있으므로 위의 오프라인 확인과 구분한다. 과거 동결 자료와 실패 기록은 정리 과정에서 덮어쓰지 않는다.
