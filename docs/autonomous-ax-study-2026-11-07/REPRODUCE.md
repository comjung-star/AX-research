# 실행 기록과 재개 방법

## 현재 중단 지점

정답 신뢰성 진입 점검에서 중단했다. 개선 실험0회, 최종 후보0개, 신규 독립 Test 질문·정답·예측 생성0건이다. 기존75개 보류는 승인된 주 평가 정답에서 계속 보류다. `diagnostic_proposals.json`의12개 AI 일치 제안은 튜닝용 정답으로 승인된 자료가 아니다.

`expert_review_packet.jsonl`은75개 사례의 질문·Task·Context·출처와 빈 검토 칸을 담는다. 추천 방식·순위·기존 AI 점수를 제외했다. 실제 사람이 채운 결과가 아니며 사람 Gold로 사용할 수 없다.

## 이번 실행 순서

다음은 실제 실행 순서의 기록이다. 기존 경로가 있으면 준비·분석 산출물을 덮어쓰지 않는다. 그대로 처음부터 재실행하지 않는다.

```powershell
python -m scripts.autonomous_ax_gate prepare
python -m scripts.autonomous_ax_gate run
python -m scripts.autonomous_ax_analyze
python -m scripts.autonomous_ax_report
```

첫 유료 호출 전에 기준 E, 성공 목표, 정책 예시, 관련도 정의, 기존 해시와 최대5회·한 번의 최종 Test 원칙을 커밋했다. E는 기존6질문의 관측 최고 모델이며 독립적으로 검증한 최고 모델이라고 간주하지 않았다.

OpenAI·Claude 호출은 기존 환경변수/사용자 환경 설정에서 키를 읽는다. 요청 전에 이번 Work의 누적 비용·미확정 예약과 새 요청의 최대 비용을 합해 $2 한도를 검사한다. 인증 헤더는 저장하지 않는다. 불확실하게 종료된 요청은 재전송하지 않는다.

일부 응답이 출력 길이 상한에서 잘렸다. 완결된 JSON 객체만 원문에서 읽었고 잘린 마지막 항목을 합성하거나 API를 재요청하지 않았다. 복구 위치와 원문 해시는 `prefix_recovery_log.json`에 있다. 원문 인용 실패도 임의로 수정하지 않았다.

`sensitivity_witnesses.json`은 보류75개에0~3점을 허용한 넓은 가정이다. `observed_reviewer_scenarios.json`은 이전·새 검토에서 실제 제시된 AI 점수 선택지를 적용한 분석이다. 둘 다 가상 점수를 정답 파일에 넣지 않는다.4,096개 가정은 독립 질문 수 또는 신뢰구간의 표본 수가 아니다.

## 재개 조건

1. 현재 감지/미래 예측, 핵심/보조 기능, 자료 부족/무관 판정의 경계를 업무 담당자 등이 확인한다.
2. 원문 인용·수행 기능의 근거를 보완하고75개 보류의 지표 영향을 다시 평가한다. 새 평가 정책을 쓰면 기존821개 판정의 호환성도 점검한다.
3. 정책과 주요 정답의 독립 검증을 통과한 뒤 비교 기준 모델을 확정한다. 이때부터 한 회차 한 요소의 개선 실험을 최대5회 진행한다.
4. 새 후보가 성능·신뢰구간·안정성·정답 검증 목표를 충족하면 최종 후보와 설정을 동결한다.
5. 새40질문과4,480쌍 검증 계획·비용을 준비하고 별도 최종 Test를 한 번 실행한다. 결과를 본 뒤 같은 Test로 튜닝하지 않는다.

현재 중단 원인은 API 조직 비용 조회 권한이나 잔액 확인 실패가 아니다. 평가 기준 적용의 신뢰성 문제다. 이번 형식을 그대로 확대한40질문 비용은 단순 비례 참고값만 산출했으며, 출력이 잘린 자료이므로 정확한 견적이나 완전 평가 상한으로 사용할 수 없다.
