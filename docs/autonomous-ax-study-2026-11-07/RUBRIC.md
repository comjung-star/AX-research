# 이번 정답 검토 기준

첫 유료 요청 전에 `preregistration.json`에 등록한 기준의 한국어 설명이다. 아래 예시는 판정 원칙을 확인하는 인공 자료다. 실제 사람 Gold 또는 새 독립 Test가 아니다.

| 등급 | 판단 기준 | 예시 |
|---|---|---|
| 3 | 실제 수행한 핵심 행동·대상·기능적 결과가 직접 일치하며 원문으로 뒷받침됨 | 주문번호·금액을 추출해 표를 요청하고 사례도 같은 항목을 추출해 검토표를 생성 |
| 2 | 분야가 달라도 이미 수행한 기능을 합리적으로 전이해 핵심 작업을 충분히 지원 | 제품 매뉴얼 기반 질의응답을 다른 분야의 안내 문서 질의응답에 적용 |
| 1 | 준비·일부·보조 작업만 관련되어 핵심 작업을 충분히 충족하지 못함 | 핵심이 청구 금액 검증인 질문에 필드 추출만 수행하는 사례 |
| 0 | 실제 수행 업무와 실질적인 기능 연결이 없음 | 조회만 필요한 업무에 명시적으로 값을 변경하는 기능만 확인됨 |
| ABSTAIN | 수행 정보 또는 핵심 전이의 충분성을 판단할 근거가 부족함 | 실제 구현된 작업이 확인되지 않거나 복합 질문의 우선 과업을 결정해야 함 |

다른 업종이라는 이유만으로 유용한 기능 전이를 제외하지 않는다. 같은 업종, 수작업 감소, 같은 기술이라는 공통점만으로2점을 부여하지도 않는다. 단순 키워드 수나 체크박스 수로 점수를 산정하지 않는다.

AI는 의미상 범주를 제안하고 프로그램은 범주를0~3점에 대응한다.3점에 필요한 행동·대상·결과 인용은 필수 근거 검사다. 인용3개가 있다는 사실만으로3점을 만들지는 않는다. 의미상 범주 판단도 독립 검증이 필요하다.

## 수행 업무와 희망사항 구분

Problem은 필요나 어려움을 설명할 수 있다. 수행 기능을 주장하려면 Task·Context에서 실제 작업을 뒷받침해야 한다. 출력물·보안 정책·개선 효과·인사 인계·사람 승인 절차가 사례에 없으면 미상으로 남긴다.

사용자가 원하는 조건을 사례의 실제 기능으로 복사하지 않는다. 사람에게 최종 권한이 있다는 문장을 AI가 자동으로 실행한다는 뜻으로 바꾸지 않는다. 특정 조건이 사례에 없다는 사실만으로 그 조건과 명시적으로 충돌한다고 단정하지 않는다.

## 핵심과 보조 작업 구분

필드 추출은 금액 대조·검증과 다르고, 문서 검색은 답변 생성과 다르며, 현재 임계치 감지는 미래 고장 예측과 다르다. 새 기능을 추가해야 비로소 요청을 수행할 수 있다면 기존 사례가 그 기능을 이미 수행했다고 쓰지 않는다.

여러 과업이 있는 질문에서 무엇이 핵심인지 명시되지 않았고, 그 선택으로1점·2점이 갈리면 판단 근거와 전문가 확인 질문을 남긴다. 추천 순위를 보고 핵심 과업을 다시 정하지 않는다.

## 검증 중 확인된 한계

실제 응답에서는 현재 감지가 예측 모델의 입력이 될 수 있다는 이유로 미래 예측 질문에2점을 부여한 예가 나왔다. 해당 예시의 실제 수행 기능은 현재 경보다. 추가 예측 단계가 없다고 이유에 적으면서도 핵심 전이에 충분하다고 선택해 이번 기준과 일관되지 않았다.

수행 정보 부족을0점과 보류 중 어느 쪽으로 처리할지에도 차이가 있었다. 예시 판정 기대값은 사람 Gold가 아니므로, 이러한 경계의 운영 정의를 업무 담당자 등이 확인한 후 정책을 확정해야 한다. 이번 AI 일치 제안은 튜닝용 정답으로 승인하지 않았다.
