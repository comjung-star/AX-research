# v2.2 자동 반복 채점: 방법·보호장치

## 목적
동일 질의 10개 × 3 평가용 참조 관점 × 93개 실제 운영 사례 = **2790개 항목**을 동일 모델/동일 평가기준으로 **독립 3회**(총 8370판정) 채점한다. 의도는 **LLM 점수 반복 일관성**을 진단하는 것이며, 올바른 정답 확인이나 검색모델 성능 입증이 아니다.

## 실행
GitHub Actions `.github/workflows/v22-repeatability.yml`은 `experiment/v22-repeatability-audit`에 감사 스크립트/워크플로 변경을 push하면 실행된다.
30개 분리 실행(Dev 질문 10개 × 반복 번호 3개)이 각자 `OPENAI_API_KEY` secret으로 **새 stateless API 호출**을 사용한다. 각 워커는 기준 Q의 동일 93사례 × 3 참조 관점 = 279판정을 **13사례 단위** 8개 배치로 수행한다. 모든 응답에는 API response ID, 모델 ID, prompt SHA, 청구와 무관한 UTC timestamp, 원문 문제/Task/Context 입력 및 RAW AI 의견을 보존한다. 이전 반복 평점/정답/개발 이력/구현을 모델에 전달하지 않는다.

`compare-and-sample`은 총 30개 모든 작업이 성공한 경우에만 2790×3 판정을 정확하게 검사한 뒤 동일 점수율/3점 이상 여부 전환율/질의별 흔들림을 정리한다. 누락/실패/응답 중복/프롬프트 불일치는 결과를 확정하지 않고 실패 처리한다.

## 연구자 검토 표
`human_blind_review_50.csv`: 신규 적격 사례 2건 포함, 3점 관련성 문턱 전환 위주 + 점수 차이 사례 + 안정적 대조 사례 최대 50건. AI 채점/이유는 **전혀 표시되지 않음**. 연구자가 먼저 독립 평가하고 AI 결과는 별도 comparison 파일로 검토한다.

## 인간 검토 입력 간소화
- 연구자 0–4점 1차 평가는 **서술형 판단 이유가 없어도 유효**하다. 제출한 50개에 추가 이유 작성은 요청하지 않는다.
- 점수만으로 독립 제2평가를 하고, 불일치 시 추가 수치 평가자/조정자 ID와 두 초안 점수·최종 선택 점수를 보존한다. 독립 검토 부재 시 Ground Truth가 아니다.
- 별도 [`data/v2_2/score_only_review_protocol_v2_2.md`](../data/v2_2/score_only_review_protocol_v2_2.md)를 따른다. 기존 v2.1 엄격 GT 검증기/동결 자료는 수정하지 않는다.

## 중요한 한계
- 이 3회는 LLM 판단의 일관성만 재고, 올바름을 보증하지 않는다. 반복 채점 결과를 다수결로 자동 Human GT에 올리지 않는다.
- 전체 2790개를 사람 두 명이 독립적으로 검수한 것은 아니다. 50건만 검수해도 최종 RQ1 Recall@K용 전체 정답을 만들었다고 발표할 수 없다.
- v2.2 Wayfair/제주은행 사례는 v2.1 Dev coverage gap을 본 뒤 모집한 사례라 선택편향이 있다. v2.1/2.2 모델 성능 개선 주장은 금지한다.
- 91개 frozen v2.1, 기존 93개 v2.2, Gold 파일은 일절 수정하지 않는다.
