# AX v2.1 — 관련 사례 0건인 평가 관점 2개 원인 분석 및 처리

**작성일:** 2026-10-23 (KST)  
**분석 범위:** 동결된 91건, 기존 AI 예비평가(2,730건) 중 양성점수 ≥3 사례가 0건인 관점 2개.  
**주의:** 아직 독립 인간 Ground Truth가 아니므로 '실제 정답 0개 확정'은 아님.

## 1. 결과 요약

|---|---:|---:|---|

## 2. 첫 번째 문제 — 상품 카탈로그 자동 속성분류

- 91건 내 P1 점수 2점 사례 총 3건:
  - `AXV2N_0127` Sandvik/SigmaNEST: 신규 영업 직원의 기술 제품지식 교육. **카탈로그 속성 자동 분류가 아님**.
  - `AXV2N_0135`: 라벨 위치·내용 품질 검증. **상품 카탈로그 메타데이터 태깅과 과제가 다름**.
  - `AXV2P2_0012_01` Shift Technology: **보험 문서의 분류·추출**. 대상은 상품이 아니며 단순 '분류' 유사성만으로 정답 처리하면 과대관련성.
- 기존 100건 v1의 `AX0079` Wayfair 원본은 상품의 색상/스타일 자동분류를 설명하여 질문과 직접 관련되지만, v2.1의 91건에는 **존재하지 않음**.
- 공식 1차출처: https://cloud.google.com/customers/wayfair-ai (Gemini로 상품 속성 보강 및 카탈로그 입력 작업 67% 단축). 사례 진위에 대한 현재 출처 근거는 확인되지만, 신규 91건에 임의로 편입하는 것은 **사용자가 확정한 동결 코퍼스 변경**이므로 수행하지 않음.
- 기존 v1 `AX0095`는 문서 메타데이터 자동 분류이지 상품 카탈로그 직접 증거는 아님.

**현재 결론:** AI가 단순히 Wayfair를 누락해 검색하지 못한 게 아니라, **91건 데이터셋의 구성에서 해당 기업 사례가 빠져 있는 것**이 주원인. 이 관점이 끝내 무정답이면 "자료 없음/추가 수집 필요"가 적절하며 허위 사례를 추천하면 안 됨.

## 3. 두 번째 문제 — 외부 AI 보안·규제 제약

- 91건 내 P1 2점 사례 총 7건: `AXV2C_0074_02`, `AXV2C_0080_02`, `AXV2H_0003_01`, `AXV2H_0008_01`, `AXV2H_0071_01`, `AXV2N_0136`, `AXV2P2_0013_01`.
- 이 중 `AXV2H_0071_01` **BPC**의 현재 Problem/Task/Context:
  - Problem: 결제 고객과 내부 지원팀의 기술문의 답변 정확성, 높은 프롬프트 비용
  - Task: 결제 기술문의 검색·답변
  - Context: 결제 솔루션 운영·고객지원
- 하지만 공식 AWS 출처 https://aws.amazon.com/solutions/case-studies/bpc/ 의 Overview와 'Opportunity | Using Amazon Bedrock...'에는 **규제 산업 데이터 보호, 클라우드 데이터 주권, 보안 기능을 갖춘 환경 도입**이 명시됨.
- 따라서 실제 원문은 BPC의 보안 맥락을 뒷받침하나, v2.1의 문제 단위가 이를 충분히 표현하지 못한 것이 **가능한 누락 요인**임. 다만 **외부 상용 AI를 사용할 수 없고 온프레미스로 해결했다**는 구체 명제는 BPC 원문이 말하지 않음. 실제 실행은 AWS Bedrock 클라우드, AWS Outposts는 시험/검토 맥락임.
- v1 `AX0056` 롯데캐피탈과 `AX0088` Home Credit Bank는 기존 보안/보호 관련 사례였지만 두 사례 모두 91건에 들어있지 않음. Home Credit 공식 출처 https://cloud.google.com/customers/homecreditbank 는 비인가 공개 AI 사용·은행 데이터 규제·보안형 Gemini Enterprise 도입을 언급하지만 **온프레미스 구축의 증거는 아님**.

**현재 결론:** 보안 관련 내용을 **정확한 연구 업무문제의 중심 요소**로 삼을 수 있는지는 별도 검토가 필요. 원문의 보안 문구만 보고 BPC를 3점 이상으로 기계적으로 올리는 것도 금지한다.

## 4. 이번에 적용한 해결책

1. **동결 91건 및 AI 원래 점수 보존.** 추론을 편리하게 만들기 위해 사례 설명을 무단 변경하거나 새 사례를 추가하지 않음.
2. **관점별 미해결/무정답 위험을 명시적으로 기록.** 해당 관점에 실제 정답이 없다면 모델이 검색을 못 했다는 오해를 막음.
3. `scripts/v21_evaluate.py`는 **향후 인간 검증 Ground Truth가 완성된 뒤** 해당 관점 Gold Set이 비었을 때:
   - 긍정 사례가 있는 평가 관점만 Perspective Coverage 분모에 포함
   - 무정답 관점은 별도 ID와 개수로 노출
   - '무정답 관점에 아무 사례도 못 찾으면 성공' 같은 모델 능력으로 간주하지 않음
   - Ground Truth가 미확정일 때는 **기존처럼 평가 실행 거부** 유지
4. 2건은 **Dev benchmark의 범위/원천 추적 한계**로 추적. 남은 91건 중 다른 사례에 억지로 3~4점을 부여하거나 연구 가설에 맞춰 평가 질문을 숨기지 않음.

## 5. 연구자 승인 없이 적용하지 않은 변경

- 새 운영사례(예: Wayfair, Home Credit)를 연구 메인 코퍼스에 보충해 91건을 92~93건으로 늘리는 조치.
- `AXV2H_0071_01`의 동결된 Problem/Task/Context를 보안 중심으로 고쳐 새 dataset/Git SHA를 발급하는 조치.
- AI 예비 점수를 사람의 최종 평가로 승격하거나 특정 질문을 성능이 잘 나오게 교체하는 조치.

이 조치들은 **별도 원문검증·새 버전·연구자 승인**이 필요한 수정이며, 과거 91건 동결 결정과 충돌하지 않도록 지금은 실행하지 않았다.

## 6. 재개할 때 우선 확인

- **상품 분류:** 91건 유지 시 P1은 관련 사례 미발견으로 독립평가를 요청. 필요 시 별도 연구 데이터 버전에서 Wayfair의 상품분류 사례를 근거 검토 후 포함.
- **보안:** BPC 원본/현행 Problem View 대조 후 외부AI 활용 제약과 규제·데이터 주권이 **같은 업무문제인지** 독립평가로 판단. "AWS Bedrock ≠ 온프레미스" 구분 유지.
- **성능 평가:** 최종 Ground Truth에서 실제 Gold 0건으로 확인된 관점은 검색 실패로 점수 감점하지 않되, 무정답 질의/관점을 별도로 보고하고 실제 무정답 탐지 성공률은 설계·GT 없이 주장하지 않음.

**종합:** 새 91건이 실패한 게 아니라, **이전 질문과 바뀐 사례의 주제 범위가 맞지 않는 부분 + 보안 사례의 문제 맥락 기재가 부족한 부분**이 확인됐다.
