# 관점별 결과 제시: 먼저 승인된1~3단계

## 1. 관점 선택·평가 기준

목표는 사용자의 문제에 도움이 되는 실제 참고 사례를 관점별로 발견하는 것이다. 기존4관점의 정의와 승인 연결18개/고유17사례를 유지한다. 질문에 명시된 작업만 같은 업무로 매칭하는 방식으로 제한하지 않는다.

QUERY_EXPLICIT은 그 관점의 문제나 작업이 질문에 명시된 경우다. PROBLEM_HYPOTHESIS는 질문에 실제 있는 문제·증상에서 다른 측면을 살펴볼 가능성을 제안하는 경우다. 후자는 질문의 연속 원문 인용, 문제→관점의 연결 설명, 확인되지 않은 가정을 반드시 남긴다. 가정을 사용자의 실제 원인으로 단정하거나 질문에 없는 사실을 추가하지 않는다. 관련 산업·기술이라는 이유만으로 관점을 추가하지 않는다. 명시 제외를 어기거나 모든 관점을 강제로 선택하지 않는다. 애매하면 보류하고 목록 밖 요청을 구분한다.

관점→사례는 실제 원문 P/T/C 및 앞서 검토한 연결 근거를 보존한다. 사례가 질문과 같은 업무면 직접적인 참고 가치가 있을 수 있고, 다른 업무라도 타당한 문제 해결 경로가 있으면 조건부 참고 가치가 있을 수 있다. 관점 매핑과 사례 연결의 의미 타당성을 기능 검사 통과로 인증하지 않는다.

새 선택기 지시문과 JSON 계약을 구현하되 이번에는 실제 새 LLM 호출을 하지 않는다. 이전 실제 LLM 응답은 과거의 업무형 선택 기준으로 생성됐다는 출처를 유지해 표시 동작에만 재사용한다. 다른 문제 관점 예시는 assistant가 수동 작성한 동작 fixture로 분리한다. 기존 응답을 새 문제관점 LLM 선택의 검증 결과로 바꾸어 보고하지 않는다.

향후 관련성 평가 기준은 config의0~3을 먼저 고정한다. ‘바로 도입할 때 모든 조건이 확인됐는가’와 ‘참고 사례인가’를 분리한다. 단순검색에도 같은 관점 기준으로 독립 평가를 적용해야 한다. 기존의 같은 핵심업무 중심 정답표를 그대로 새 목표의 Gold라고 부르거나, 새 점수가 높아질 때까지 정답을 바꾸지 않는다. 본 평가와 새 채점은 후속4~6단계다.

## 2. 관점별 표시

선택한 관점마다 연결된 승인 사례를 최대5개씩 로컬 Task cosine으로 정렬한다. query는 원질문에 해당 관점의 원래 정의를 명시적으로 붙인 고정 문자열이다. 가정은 사실로 바꿔 검색문에 넣지 않는다. cosine은 정렬 보조값이며 정확도나 확률이 아니다. 관점 간 전역 top5 재선별이나 RRF는 없다. 부족하면 채우지 않는다.

각 관점은 질문 근거·선택 이유·직접 명시/검토 가설 구분·미확인 가정을 표시한다. 각 사례는 해당 관점에서의 실제 수행 업무, 연결 근거, 원문 인용, 질문과의 입력/업종/세부 항목 차이, 원문에 없는 조건을 표시한다. 조건 미기재만으로 유용한 참고 사례를 전부 버리지 않는다. 대신 직접 적용이 확인됐다고 하지 않는다. 알려진 제외 연결/HOLD/소스 인용 불일치는 사용하지 않는다.

같은 사례가 여러 관점의 top5에 들어오면 관점별 순위와 연결을 모두 유지하고 상세 근거는 case_details에 한 번만 둔다. display_slots와 unique_case_count를 따로 집계한다. 미래 단순검색 비교 개수는 고유 사례 U개다. U를 계산했다고 성능을 비교한 것이 아니다.

## 3. 17사례 기능 검사

다중관점 보존, 관점당5상한, 전역5초과 허용, 공유사례의 상세 중복 제거와 각 관점 근거 보존, 가정의 별도 표시, 인용 문자 일치, HOLD/제외 금지, 정보 부족/관점 없음, 미기재 조건 설명, 동일U 집계를 검사한다. source-catalog·profiles·기존 코드는 수정하지 않는다.

먼저 검사를 마친 소스/정책/지시문을 저장하고, 기존 실제 선택 응답28개와 명시적으로 수동 작성한 fixture로 로컬 표시 예시를 생성한다. 저장된 벡터로 같은 표시를 재현한다. 동일 질문 반복4개는 독립 표본이 아니며 합성 fixture는 독립 Gold가 아니다. 호출용 builder만 준비하고 API 클라이언트는 이번 실행 경로에 두지 않는다.

이 단계는 기능 구현과 출처 확인이다. 새 LLM 문제관점 선택의 의미 정확도, 관련 사례 검색 성능 향상, 관점의 추가 이득, 전체112 적용성은 주장하지 않는다. 후보17<20의 한계도 유지한다. 전체112 연결 확장과 새 질문 성능 평가는 이번에 하지 않는다. 새 유료 호출·학습·정답표 접근·Test15 접근·GitHub 업로드 없이 종료한다.
