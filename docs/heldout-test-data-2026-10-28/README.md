## 파일과 접근

질문, 정답, manifest, 질문 고정 기록은 Git 작업 폴더와 OneDrive 밖인 `%USERPROFILE%\.ax-heldout-work-b\20261028`에 보관한다. `handoff.json`에 실제 절대경로 및 SHA-256을 기록한다. 정답 내용과 생성 스크립트는 Git에 올리지 않는다. 기존 112개 코퍼스는 수정하지 않는다. 공개한 메타데이터만으로 정답을 복원할 수는 없으며 완전 재현에는 봉인 파일이 필요하다.

Work A에는 먼저 questions.jsonl과 manifest.json만 전달한다. 추론 결과와 실행 버전 및 예측 해시를 봉인한 뒤 평가 담당자에게 qrels.jsonl을 전달한다. 원래 세 파일은 같은 디렉터리를 기준으로 상대경로를 사용한다. 분리 전달할 때 원본 파일 바이트와 해시를 보존하고 평가 시 원래 구조로 복원한다. manifest 수정으로 경로를 바꾸면 추론 영수증과 불일치할 수 있다.

## 평가 기준과 범위

- 3: 직접 수행 기능 일치. 부가적인 요구가 충족되지 않으면 근거에 명시한다.
- 2: 주요 Action/Object/Output을 기능적으로 응용할 수 있으나 환경·연동 변경이 필요하다.
- 1: 인접 업무나 보조 기능만 관련된다. 업종·용어만 같다는 이유로 2점을 부여하지 않는다.
- 0: 확인한 실제 수행 기능이 해당 업무와 다르다.
- ABSTAIN/null: 개별 검토했으나 근거 부족으로 점수를 결정할 수 없다.
- UNJUDGED/null: 개별 관련성 검토를 완료하지 않았다. 0점으로 변환하지 않는다.

관련성 임계값은 2점으로 고정한다. 동일 AI가 작성하고 판단한 AI-Silver이며 Human-Gold는 없다. 112개 Task/Context 목록을 읽었지만 질문마다 전체 사례의 세부 판정을 완료하지 않았다. 질문당 3개 사례를 목록에서 직접 골라 개별 기능을 비교했다. 이 선택은 추천 모델이나 순위에 기반하지 않지만 대표성·평가자 선택 편향이 있다. 원문 링크를 새로 방문해 검증하지 않았으며 저장된 Problem/Task/Context 요약만 사용했다. Action/Object/Output은 이 요약의 명시적 내용에서 해석했으며 별도 원문 필드가 아니다. 일부 근거 설명은 일본어 및 영어로 기록되어 외부 검토 전 한국어 교정이 권장된다.

전체 Recall/F1 및 전체 코퍼스 nDCG는 계산하면 안 된다. 관련 사례가 없다고 확정한 질문도 없다. 관련 사례가 발견되지 않은 질문과 관련 사례가 없는 질문은 다르다. 부분 Precision도 TopK가 모두 판정된 경우에만 가능하다. 현재 Test 추론·성능 계산은 전혀 수행하지 않았다.

## 독립성과 품질 검사

기존 Dev 10개와 파일럿 5개를 읽고 새 업무 질문을 작성했다. 교대 공평 배정, 퇴사 권한 회수, 회의실 미사용 예약 해제, 중복 접수 통합, 약속 연락 추적, 포장 누락품 검사, 영상 익명화, 지게차 위험 경고, 은행 거래 대사, 채권 독촉, 근태 수당 계산, 창고 배치, 회수 차량 경로, 장애 담당팀 배정, 미사용 이용권 회수로 구성했다.

동일 문장과 단순 문장 변경 재사용은 확인되지 않았다. 다만 고객지원(HB004/005), 인사(HB001/002/011), 영상 검사(HB006/007/008)는 기존 질문 또는 서로와 영역이 겹친다. 각각 통합·추적, 배정·회수·계산, 누락검사·익명화·안전경고로 Task와 Output이 다르다는 작성자 판단이다. 문자열 유사도는 의미 독립성의 증명이 아니며 외부 검토가 필요하다. `validation.json` 및 `quality_checks.json`에 정량 검사를 기록한다.

**질문 작성 전에 사례 목록을 열람했다.** 따라서 사례를 전혀 모르는 독립 작성자가 만든 시험이라고 주장할 수 없다. 같은 대화·같은 AI의 단계 분리와 파일 고정은 평가자 독립성을 만들지 않는다. 추천 점수·순위, 기존 Silver 점수는 사용하지 않았다. 질문 작성 후 정답 평가를 이유로 질문을 바꾸지 않았다. 기존 알고리즘을 실행하거나 수정하지 않았고 유료 API도 호출하지 않았다.
