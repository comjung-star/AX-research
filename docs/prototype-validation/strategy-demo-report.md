# 우리 업무의 AX 적용 전략

업무문제: 심사와 검증 업무에서 여러 형식의 문서를 사람이 읽고 필수 항목과 규정 준수 여부를 일일이 확인해야 해서 처리시간이 길고 누락이나 오류 위험도 높다.

문서에서 필수 항목을 먼저 추출하고 기준에 따라 검토를 보조하도록 설계한 뒤, 예외·불일치 건은 사람이 확인하는 방식으로 심사 흐름을 나누는 방안을 검토합니다.

## 먼저 해볼 일

최근 심사 문서 한 건과 해당 문서의 필수 항목·검토 기준을 골라, 사람이 확인하는 항목을 목록으로 정리합니다.

## P1. 심사·검증 처리 지연

여러 형식의 문서를 사람이 직접 읽고 항목을 확인해야 해 업무 처리시간이 길다.

### 문서 검증 항목 분석을 먼저 보조 · 먼저 검토

우리 업무의 문서에서 검증 대상 항목을 추출·정리하고, 담당자가 결과를 확인한 뒤 심사하도록 절차를 바꿉니다. 우선 반복적으로 확인하는 문서 유형부터 적용 범위를 정합니다.

실행 순서:
1. 자주 처리하는 문서 유형 하나와 그 유형의 검증 항목을 정리합니다.
2. 문서에서 항목을 찾아 표시하는 보조 절차를 마련합니다.
3. 담당자가 원문과 대조해 결과를 확인하고, 불일치는 별도로 기록합니다.
4. 정리된 결과를 기존 심사 절차에 전달하는 방법을 정합니다.

준비할 것:
- 대상 문서의 표본과 현재 사용하는 검증 항목·기준
- 추출 결과를 확인하고 수정할 담당자
- 문서 열람 및 처리에 관한 내부 권한과 보안 조건

확인할 점:
- Genpact 사례의 수치는 해당 사례의 결과이며 우리 업무의 처리시간이나 정확도를 보장하지 않습니다.
- 사례에서 모델 정확도는 별도로 80%로 보고됐으므로, 보조 결과를 사람의 확인 없이 확정 판단으로 사용하지 않아야 합니다.

근거: Genpact 사례에서는 생성형 AI로 직원 신원조회 보고서의 검증 항목을 분석해 인적 검토를 보조했습니다. 보고서 검증 주기는 5일에서 2.5일로 줄었다고 보고됐지만, 이를 우리 업무의 예상 성과로 볼 수는 없습니다.

### 반복적인 보완 요청·처리 절차를 자동화 후보로 분리 · 함께 검토

필수 정보가 빠진 문서의 보완 절차를 확인해, 정해진 조건에서 반복되는 보완 작업은 담당자의 검토를 거쳐 진행하고 예외 건은 사람에게 넘기도록 업무 흐름을 나눕니다.

실행 순서:
1. 현재 보완 요청이 자주 발생하는 누락 항목과 처리 규칙을 모읍니다.
2. 규칙으로 처리 가능한 건과 사람의 판단이 필요한 예외 건을 구분합니다.
3. 보완 결과를 담당자가 승인하는 절차를 정합니다.
4. 승인 전후의 수정·반려 사례를 기록해 적용 범위를 조정합니다.

준비할 것:
- 누락 항목별 보완 규칙과 예외 처리 기준
- 보완 결과의 승인 책임자와 기록 방식
- 문서·심사 시스템 간 정보 전달 가능 여부 확인

확인할 점:
- BNY 사례는 지급 지시 보완에 관한 것으로, 심사 문서의 모든 누락을 자동으로 처리할 수 있다는 근거는 아닙니다.
- 사례의 처리 비율을 우리 업무의 예상 처리 비율로 해석할 수 없습니다.

근거: BNY 사례에서는 Eliza 에이전트가 불완전한 지급 지시를 반자동으로 보완해 이전의 수작업 검토 없이 지급이 진행될 수 있도록 했습니다. 지급 보완 문제의 10% 초과를 처리했다고 보고됐으며, 이는 전체 거래의 10%라는 뜻은 아닙니다.

원문 보고 성과: 지급 보완 문제의 10% 초과를 처리했다고 보고했습니다. 이는 전체 거래의 10%를 처리했다는 뜻은 아닙니다.

원문 보고 성과: 출처에 따르면 이관 해결 시간이 50% 감소했습니다. 연간 48,000건 티켓 처리는 예상치로 제시됐습니다.

출처: https://openai.com/index/oscar/

## P2. 필수 항목 누락 위험

필수 항목을 일일이 확인하는 과정에서 누락이 발생할 위험이 있다.

### 문서에서 필수 항목을 추출해 누락 확인을 보조 · 먼저 검토

우리 업무의 문서에서 필수 항목을 추출하고, 항목별로 확인 여부를 표시해 담당자가 빠진 항목을 빠르게 확인하도록 절차를 바꿉니다. 서로 다른 문서 형식별로 추출 결과를 확인하는 단계를 둡니다.

실행 순서:
1. 문서 종류별 필수 항목과 허용되는 표기 형태를 정리합니다.
2. 대표 문서에서 항목 추출 결과를 만들고 원문과 대조합니다.
3. 누락·불명확·추출 실패 항목을 담당자 확인 대상으로 표시합니다.
4. 확인 결과를 반영해 문서 유형별 항목 목록을 보완합니다.

준비할 것:
- 문서 유형별 필수 항목 정의
- 서로 다른 형식의 문서 표본과 원문 대조를 맡을 담당자
- 문서 처리 및 보관에 대한 내부 보안·개인정보 조건

확인할 점:
- 사례의 결과는 문서 준비 및 추출 설정에 관한 것이며 전체 심사 주기의 단축을 뜻하지 않습니다.
- 사례에서 언급된 과거 청구 건수는 이 기술 도입의 성과나 생성형 AI의 기여로 해석할 수 없습니다.
- 우리 문서 형식과 항목에서의 추출 가능성은 별도 확인이 필요합니다.

근거: Shift Technology 사례에서는 여러 보험 문서에 OCR·레이아웃 추출을 적용하고, 그 결과에 프롬프트를 사용해 관련 데이터를 추출했습니다. 공급사는 문서 준비 및 추출 설정이 수주에서 수일로 줄었다고 보고했지만, 이는 보험금 청구 전체 처리주기를 뜻하지 않습니다.

### 검증 항목 분석과 사람의 재확인 절차 결합 · 함께 검토

필수 항목을 문서와 대조하는 현재 절차를 항목별 확인 결과가 먼저 정리되고 담당자가 미확인·불일치 항목을 점검하는 방식으로 바꿉니다.

실행 순서:
1. 현재 필수 확인 항목과 해당 항목의 근거가 되는 문서 위치를 정리합니다.
2. 문서별 항목 확인 결과를 담당자가 검토할 수 있는 형태로 만듭니다.
3. 누락 또는 근거 불명확 항목은 자동 통과시키지 않고 사람이 확인하도록 정합니다.
4. 사람이 수정한 결과를 기록해 항목 정의와 검토 절차를 보완합니다.

준비할 것:
- 업무에서 사용하는 필수 항목 목록과 확인 기준
- 결과를 원문과 대조할 담당자 및 검토 절차
- 수정 이력과 예외를 기록할 방법

확인할 점:
- Genpact의 준수 확인 범위와 모델 정확도는 서로 다른 지표이며, 우리 업무에 그대로 적용할 수 없습니다.
- 사례는 직원 신원조회 보고서 검증이므로 우리 문서의 항목 정의와 형식은 별도로 확인해야 합니다.

근거: Genpact 사례에서는 생성형 AI가 보고서의 검증 항목을 분석해 인적 검토 업무를 보조했습니다. 해당 사례는 준수 확인 범위 100%를 보고했지만, 모델 정확도는 별도로 80%라고 보고됐으므로 두 수치를 같은 의미로 보아서는 안 됩니다.

## P3. 규정 준수 확인의 오류 위험

문서별 규정 준수 여부를 사람이 확인하는 과정에서 판단 오류가 발생할 위험이 있다.

### 규정 관련 검토 항목을 문서에서 찾아 표시 · 먼저 검토

우리 문서에서 규정 준수 판단에 필요한 주요 정보를 찾아 표시하고, 담당자가 해당 정보와 적용 기준을 대조한 뒤 판단하도록 절차를 구성합니다. 판단 근거가 불명확하거나 정보가 빠진 건은 사람의 추가 검토 대상으로 둡니다.

실행 순서:
1. 검토할 규정 항목과 문서에서 확인해야 할 근거 정보를 정리합니다.
2. 문서에서 관련 정보를 표시하는 보조 절차를 시험합니다.
3. 담당자가 표시된 내용과 원문·기준을 대조하고 판단 근거를 기록합니다.
4. 위험 신호가 있거나 근거가 모호한 건은 기존 상위 검토 절차로 넘깁니다.

준비할 것:
- 적용할 규정과 위험 항목의 최신 기준
- 문서상 근거를 확인하고 판단할 담당자
- 검토 결과와 판단 근거를 남길 기록 방식

확인할 점:
- 사례는 제재 심사 문서의 위험 선별 보조에 관한 것으로 우리 규정 준수 판단을 대신하지 않습니다.
- 수치 성과가 보고되지 않아 처리시간이나 오류 감소 효과를 추정할 근거가 없습니다.

근거: Hong Leong Bank 사례에서는 Document AI가 제재 심사용 문서의 주요 세부 정보를 표시해 위험 선별을 보조했습니다. 보고된 결과는 정성적인 위험 선별 지원이며, 별도의 수치 성과는 제시되지 않았습니다.

### 검증 항목 분석을 활용하되 준수 판단은 담당자가 확정 · 함께 검토

우리 업무의 규정 관련 확인 항목을 문서별로 정리해 담당자에게 제시하고, 담당자가 원문 및 기준을 대조해 최종 준수 판단을 내리도록 합니다. 항목 누락과 기준 해석이 필요한 상황은 별도 검토 대상으로 구분합니다.

실행 순서:
1. 규정별 확인 항목과 문서에서 확인할 근거를 정리합니다.
2. 항목별 문서 확인 결과를 담당자에게 제시하는 절차를 마련합니다.
3. 담당자가 원문과 기준을 대조해 준수 여부와 판단 근거를 기록합니다.
4. 기준 해석이 필요하거나 결과가 불명확한 건은 추가 검토로 넘깁니다.

준비할 것:
- 현재 적용되는 규정과 문서별 검증 기준
- 최종 준수 판단을 맡을 담당자와 예외 처리 절차
- 판단 근거 및 수정 이력을 보관할 방법

확인할 점:
- Genpact 사례의 수치는 해당 보고서 검증 업무에 관한 것이며 우리 업무의 성능을 보장하지 않습니다.
- 준수 확인 범위와 모델 정확도는 별개의 지표입니다. 우리 문서와 규정에 대한 검증이 필요합니다.

근거: Genpact 사례에서는 보고서 검증 항목 분석으로 인적 검토를 보조하고 준수 확인 범위 100%를 보고했습니다. 동시에 모델 정확도는 별도로 80%로 보고됐으므로, 이 사례는 사람의 확인을 없애는 근거가 아닙니다.

### 참고 기업의 실제 해결 방식

**Genpact · 직원 신원조회 보고서 검증**

Genpact는 생성형 AI로 직원 신원조회 보고서의 검증 항목을 분석해 인적 검토를 보조했습니다.

원문 보고 성과: 보고서 검증 주기는 5일에서 2.5일로 줄었고, 수작업은 약 90% 감소, 준수 확인 범위는 100%로 보고됐습니다. 모델 정확도는 별도로 80%로 보고됐습니다.

출처: https://aws.amazon.com/solutions/case-studies/genpact-case-study-generative-ai/

**BNY · 고객 등록 문서·위험 검토**

BNY는 Eliza 에이전트형 업무 흐름으로 신규·과거 문서를 검토하고 추가 자료를 요청해 위험 판단을 보조했습니다.

원문 보고 성과: 신규 고객 등록의 25%를 AI가 보조했으며, 해당 고객 또는 일부 프로세스에서 완료 시간이 20% 빨라졌다고 보고됐습니다.

출처: https://www.microsoft.com/en/customers/story/27322-bny-microsoft-365-copilot

**Hong Leong Bank · 제재 심사용 문서 위험항목 확인**

Hong Leong Bank는 Document AI로 제재 심사용 문서의 주요 세부 정보를 표시해 위험 선별을 보조했습니다.

원문 보고 성과: 정성적인 위험 선별 지원이 보고됐으며, 별도의 수치 성과는 제시되지 않았습니다.

출처: https://cloud.google.com/customers/hongleongbank

## 작성 범위

실제 LLM이 관점별 상위 3개 이내의 선택 사례를 근거로 작성한 적용 전략입니다. 사례 사실과 우리 업무에 대한 제안을 구분해 읽어 주세요.

사용자에게 제안한 실행 순서는 실제 기업의 확정된 절차와 구분해야 합니다. 학습형 Evidence Fusion이나 Wald 통계 분석의 검증 결과가 아닙니다.
