# 요청/제외 분리와 누락 복원 비교 — 고정 개발 검증 규칙

사용자 승인3~6단계. 기존 개발20질문/112사례만 사용한다. 유료 호출/새 모델 다운로드/새40질문/Test15 접근은 없다. 이전 작업과 같은 동결 모델 BGE-M3의 로컬 추론으로 새 필드 임베딩을 계산한다. 과거 자료/규칙/점수는 덮어쓰지 않는다.

3단계: 원문 문장과 위치를 보존해 요청(싶다/원한다), 제외(않다/금지/제외), 사람 승인 제약, 배경을 구분한다. ‘안내만 제공하고 장비 제어 명령은 실행하지 않는다’는 일반적인 혼합 문장 형식을 분리한다. 요청이 인식되지 않으면 제외/승인 외 문장을 fallback으로 쓰고 그 사실을 표시한다. 제외 문장은 요청 임베딩에서 빼되, 사례와의 유사도는 학습 가능한 별도 보조값으로 기록한다. 제외 문장과 비슷하다는 것만으로 실제 위반이라고 단정하거나 후보를 차단하지 않는다. 이는 한정된 언어 규칙이며 완전한 부정 범위 해석이 아니다.

4단계: 비교는 Dense, 직전 학습채점기(동결 예측), Recovered(누락24사례의 행동/잔여대상 복원으로 바뀐 cosine만 반영), WorkAligned(복원+요청만의 Task/행동/대상, 제외문장 유사도, 요청 결과 단어와 사례Task의 유사도 및 명시 출력필드 비교)로 고정한다. 기존10차원 특성을 유지/갱신하고 WorkAligned에는 제외Task유사도·결과단어Task유사도·양쪽 명시출력 유사도·출력쌍존재의4차원만 추가한다. 결과 단어는 원문에 있는 목록/요약표/현황표/근거/출처/시각/위치/우선순위/점검 순서다. 이는 결과 요구의 부분적 단서이지 결과의 동등성 보장이 아니다. 사례의 명시 출력은112개 중1개뿐이므로 출력 비교 미측정은0+존재표시로 구분하며 추정 산출물을 만들지 않는다.

Recovered는 기존 query profile과 동일한 사례Task를 사용하고24사례의 action/object만 바꾼다. 나머지88사례의 기존값은 그대로다. WorkAligned의 원문Dense/토큰/BM25는 기존값을 유지해 새 전체검색기의 효과와 혼동하지 않는다. 후보풀은 이전 Dense20/원문토큰보완20/관점보완20 파일을 고정해 재사용한다. 관점별 출처는 기존trace에서 보존한다. 모든 후보20/최종5로 비교하지만 특성/임베딩 계산은 전체112사례이므로 계산량 동일이라고 주장하지 않는다. 전략 추천 자체는 이번 검증 대상이 아니다.

5단계: 이전과 같은5개 질문 외부폴드(각4개), 외부 학습16개 안의4개 내부폴드(12학습/4검증)로 고정한다. pairwise ridge 학습과 λ={0.1,1,10}, 학습점수비중={0,0.5,1}만 사용한다. 내부 Dense20 F1우선/nDCG차선, 동률은 학습비중 작게/λ크게. working_transfer만 학습/설정선택에 쓰고 예측 고정 후 original/scoped 정답으로 민감도 평가한다. 모든 반복은 질문에 묶고 평가질문을 학습/선택에서 배제한다. 질문/사례ID는 특성이 아니다. 동일 사례DB는 공유하며 새 사례 일반화는 검증하지 않는다. 이전에 관찰한 개발자료이므로 새 독립시험이 아니다.

6단계 종료기준: 이 두 개선버전의 중첩검증을1회 끝내고 결과를 보고 추가조정하지 않는다. 각 버전의 관점후보 조건이 세 정답표 모두 Dense F1상승/nDCG비감소, working F1의 질문bootstrap10,000회95%하한>0을 만족해야 잠정 개발채택이다. 미달이면 채택보류/기각한다. Recovered 대 직전채점기, WorkAligned 대 Recovered, 관점 대 동일채점기의 단일질문후보도 별도 보고한다. 자료누출을 막았다는 주장은 이번 학습절차에 한정하며 과거 개발 노출/규칙설계의 편향을 제거했다고 말하지 않는다. 신뢰구간은 개발 탐색의 기술 통계이며 다중비교/선택편향 보정을 한 확증시험이 아니다.
