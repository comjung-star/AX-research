# 관점별 결과 표시 시범: 1~3단계 완료

**문제관점 기준 정리, 관점별 최대5개 표시 구현, 현재17개 사례에서 기능 확인까지 마쳤다.** 전체 결과를 다시5개로 자르지 않고 관점별 연결을 유지한다. 같은 사례의 상세 근거는 한 번만 보존하고 여러 관점의 순위·연결은 남긴다.

**이번에 확인한 것은 표시와 자료 연결 동작이다. 새 문제관점 기준으로 LLM이 실제 선택을 잘하는지와 검색 성능 개선은 아직 평가하지 않았다.** 새 기준 호출용 지시문과 출력 계약만 준비했다. 수동 구성 예시6개와 이전 실제 LLM 응답28개를 구분해 사용했으며, 이전 응답을 새 기준의 검증 결과로 바꾸어 보고하지 않았다.

## 1. 관점 기준을 문제 중심으로 정리

- **질문에 명시된 문제·업무:** 질문에 직접 근거가 있는 관점.
- **다른 관점에서 검토할 가설:** 같은 문제를 다른 측면에서 볼 연결 이유와 확인되지 않은 가정을 함께 표시. 질문의 실제 원인으로 확정하지 않음.
- 다른 업무 사례도 질문→관점→사례의 연결 근거가 있으면 참고 가능. 단순 업종·기술 겹침만으로 유용하다고 하지 않음.
- 질문 근거는 원문 인용으로 보존하고 명시 제외는 존중. 관점을 모두 강제 선택하지 않고 모호하면 보류.
- 참고 사례의 관련성과 직접 적용 조건을 분리. 세부 조건 미기재만으로 전부 제외하지 않고 차이를 설명.

예: ‘고객 답변 지연’에 응대 용량 관점뿐 아니라, ‘답변 근거를 찾는 시간이 지연 요인이라면’이라는 가정 아래 지식 검색 관점을 살펴볼 수 있다. 이 연결 예시는 assistant가 수동 작성했으며 실제 LLM의 새 기준 판단은 아니다.

평가 준비 기준도 고정 파일에 정리했다. 직접 관련3, 타당한 다른 관점의 도움2, 단순 주제/기술 겹침1, 관련 없음0이다. 실제 채점은 하지 않았다. 같은 사례 수의 단순검색에도 동일 관점 기준을 적용해야 하며, 이전의 같은 업무 중심 정답표를 새 목표의 Gold로 재사용하지 않는다.

## 2. 관점별 표시 구현

질문 → 관점 선택 결과 → 승인된 관점별 사례 → 관점별 정렬 → 각 최대5개 표시. 전역 최종5개 선별이나 강한 fit 필터는 없다.

- 관점 제목·질문 근거·선택 이유·가설/직접 명시 구분·미확인 가정 표시.
- 사례별 실제 수행 업무·관련 이유·원문 연결 근거·차이와 확인할 조건 표시.
- 관점 내 중복은 없으며, 관점 간 공유 사례는 다른 연결 관점을 표시하고 case_details 상세를 공유.
- 부족하면 억지로5개를 채우지 않는다. 현재 P01은3개, P02는6개 중상위5개, P03은5개, P04는4개가 가능.
- PDF 추출과 야간 응대처럼 별도 작업 조건을 이름 붙은 관점에만 표시. 과거 응답의 적용 관점 미지정 조건은 원문 전체 기록으로 별도 보존.
- 표시 합계와 중복 제외 사례 수 U를 따로 계산. 미래 단순검색 비교 수는 U개로 기록하되 이번에 비교 실행은 하지 않음.
- 정렬은 원질문+관점 원래 정의와 실제 사례Task의 기존 로컬 BGE cosine. 정렬 보조값이며 검증된 적합 확률이 아님.

## 3. 동작 확인 결과

|예시|관점별 표시 수|표시 합계|고유 사례|해석|
|---|---|---:|---:|---|
|하나의 문제를 다른 관점에서도 살펴보기·수동|지식 검색3 / 문의 응대4|7|7|전역5개로 줄이지 않음|
|자유서술 구조화와 누락 검사·수동|정보 구조화5 / 대조검증5|10|9|공유 사례1개의 상세는 한 번만 보존|
|네 관점·수동|3 / 5 / 5 / 4|17|16|부족한 관점은 채우지 않음|
|이전 실제 LLM D11 응답 재사용|3 / 5 / 5|13|12|예전 업무형 기준 응답임을 명시|

관련 기능 검사71개가 통과했다. 수동6개와 이전 응답28개에서 생성한34개 표시를 저장 벡터로 재현했다. 기존28개 중 동일 질문의 순서 반복4개가 포함되므로34개를 독립 질문 정확도 표본으로 세지 않는다. 인용 문자 일치, 승인 연결만 사용, 관점별 상한, 전역 절단 없음, 공유 근거 보존, 가정·제외·범위 밖 표시, 동일U 집계를 검사했다.

로컬 새 문자열34개를 벡터화했다. 새 유료 API 호출0회, 새 모델 학습0회, 성능 비교0회다. 네 관점의 고유17사례 범위이며 전체112 확장은 하지 않았다. 정답표·봉인Test15를 읽지 않았고 기존 동결 소스와 연결표를 수정하지 않았다. GitHub에 커밋·업로드하지 않았다.

## 무엇이 아직 남아 있는가

새 지시문으로 실제 LLM이 문제관점을 선택하는 의미 검증은 아직 남아 있다. 이번 수동 가설 예시는 올바른 선택 정확도의 증거가 아니며, 기존 응답 재사용도 새 문제관점 선택이 작동했다는 증거가 아니다. 또한 현재17개에서 결과가 잘 표시되는 것과 전체112개에서 더 유용한 사례를 발견하는 것은 다른 주장이다.

합의한 다음4~6단계는 전체112의 연결 확대, 고정한 방법으로 개발에 사용하지 않은 질문 비교, 같은 고유 사례 수와 같은 관점 기준으로 유용성·추가 발견·누락을 확인하는 것이다. 이번에는 실행하지 않았다.
