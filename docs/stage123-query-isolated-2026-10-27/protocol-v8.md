# 최신 실행 정책 v8 — 2026-10-27

최초 protocol.md와 그 이후 시도는 덮어쓰지 않는다. 최신 입력/비용/응답은 format-v8 아래에 보존한다. 원래 40쌍 구성과 0~4점, 양성 3 이상, 업무 관련도 원칙은 동일하다. 이유 상한은 format-v6부터 40단어이며 최신 지시/검증/시험 모두 일치한다.

## 출력과 질문·사례 연결

세 공급자의 JSON Schema 출력 기능을 사용한다. 키와 ID의 허용값, 점수 0~4, 관련 업무/불확실성 표기를 고정하고 추가 키를 거부한다. 구현은 공급자 공통 지원 기능만 사용하며 실제 항목 수, 중복, 점수-업무 표기의 일치, 이유 단어 수는 다시 로컬 검증한다.

v7까지 남은 한국어 인용문 바꿔쓰기 오류를 해결하기 위해 v8은 질문 앞 60자와 사례 Task 앞 최대 120자(8자보다 짧으면 Problem)를 입력 양식에 자동으로 제공한다. 참조관점도 원문 발췌를 제공한다. 허용된 발췌만 반환할 수 있고 다른 사례 발췌를 연결하면 중대한 매핑 오류로 중단한다. 이는 기계적 연결 검사이며 모델이 질문을 올바르게 이해했다는 증명은 아니다. 실제 관련도는 원질문과 P/T/C **전체**로 판단하고 이유의 업무 문맥도 별도로 점검한다. 구현 검증의 한계를 숨기지 않는다.

v8은 같은 40쌍을 세 모델 모두 새로 호출한다. v7의 다른 모델 재사용 방안은 v8에서 사용하지 않는다. 과거 실패 응답의 점수/이유를 다른 평가 모델에게 제공하지 않는다.

## 비용·실패·재개

- 이전 v3/v5/v6/v7 유료 생성 사용액과 미확정 예약을 합산하여 Claude $4.484424 이내로 관리한다. 기존 확인 사용액 $0.015576 및 안전 여유 $0.50는 별도다. 사용자가 말한 최초 $5를 기준으로 장부를 계산하며 실제 계정 잔액을 조회했다고 주장하지 않는다.
- token count API에서 확인된 일시적 HTTP503 한 건은 원본 실패 기록을 보존하고 별도 이름으로 1회 재계산한다. 이는 유료 텍스트 생성의 불확실한 재호출과 구분한다.
- 생성은 확인된 출력 형식 오류만 1회 재요청한다. 응답 없는 생성의 청구 여부는 예약 전액으로 유지하고 자동 재호출하지 않는다.
- API에 전송하기 **전** 취소되고 예약 0으로 기록된 요청만 별도 resume1 파일로 최초 전송할 수 있다. 기존 기록을 수정하지 않는다. 이미 받은 정상 응답은 재검증·출처 기록 후 다시 호출하지 않는다.
- 원문 `body shop/weld splatter`의 manufacturing 설명과 `quoting/manufacturing quotes`의 quotation 설명은 각각 같은 사례의 근거가 있는 표현이었다. 두 문자열 경고는 검사 사전의 오탐으로 검토했고, 원래 경고를 남겼다. 다른 질문 혼동이 재발한 것으로 집계하지 않는다. 사례 점수는 바꾸지 않는다.

## 정답 승인과 후속 단계

모델 세 개의 독립 점수/이유를 원본으로 보존한다. 관련 여부 삼자 일치는 임시 AI Silver 후보이며 사람 Gold가 아니다. 0~2 또는 3~4 내부 등급 차이와 2/3 경계의 이견을 구분한다. 경계 이견은 다수결로 승인하지 않고 실제 원질문과 P/T/C의 과업·대상·산출물 근거를 별도 검토한다. 근거가 불충분하면 UNRESOLVED로 유지한다. 에이전트의 검토는 사람 검증이나 네 번째 독립 LLM으로 표현하지 않는다. 점수 규칙을 명백히 어긴 응답도 승인 대상에서 분리한다.

전수 평가는 검토한 파일럿 게이트와 출처/필드 구조 점검이 통과해야 실행할 수 있다. 아직 미판정인 사례를 0으로 바꾸지 않는다. 확정적인 검색 성능표를 낼 만한 정답이 준비되지 않으면 Stage2·3을 멈추고 보류 이유를 보고한다. 관련 사례가 실제로 0개인 질문은 남기고 Recall/F1은 미정의로 표시하며 평균의 질문 수를 공개한다.

Stage2를 실행하게 되면 같은 원문 P/T/C, BGE-M3, 동일 후보 예산20, K=5/10/20을 적용한다. 세 View는 기존 구현의 동일 가중 평균이며 결과를 보고 가중치를 조정하지 않는다. Stage3은 같은 원질문만으로 세 모델의 동적 관점을 생성하며 기존 참조관점과 정답을 생성 입력에 주지 않는다. 참조관점 정답의 검증 전에는 Reference Coverage를 주요 지표로 보고하지 않는다. 새 임베딩/검색 알고리즘, 독립 Test 및 Stage4는 실행 범위 밖이다.
