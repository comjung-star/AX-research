# 출력 형식 수정 이력

2026-10-27. 기준 점수체계(0~4, 관련 3 이상), 관련도 원칙과 정확한 40쌍 구성은 모든 버전에서 같다. 모델 간 점수 일치를 높이기 위한 수정이 아니다.

- v3(이 폴더 루트): 질문/관점별 분리 및 원문 반복, 정확한 ID와 인용문 검증. Claude 이유가 20단어를 넘거나 필수 키를 빠뜨림. Gemini는 요구된 ratings 객체 대신 배열을 반환함. 제한을 넘는 응답은 불채택. 1회 형식 재요청 후에도 오류가 남아 후속 요청 자동 중단. 원시 응답과 비용은 attempts에 보존.
- format-v4: 모든 항목의 키와 ID를 포함한 출력 양식을 입력에 추가하고, 이유 6~12단어 권장/20단어 절대 상한을 명시. 생성 요청 전 토큰 계산에서 OpenAI 167건이 HTTP400: JSON 객체 출력 모드에서는 사용자 입력에도 json 문구가 필요함. 오류 메시지의 type/code/param/message만 키를 가린 채 진단했고, 비밀정보 및 원시 HTTP 본문은 저장하지 않음. 생성 호출 0건. 다른 공급자의 성공한 계산도 함께 보존.
- format-v5: 사용자 입력에 `Return JSON`을 명시하여 위 API 형식 조건 해결. 다시 토큰 계산하고 동일한 40쌍 전체를 독립 재시험한다. v3 점수를 v5 결과와 섞거나 실패 점수를 정답으로 사용하지 않는다. 루트 v3의 실제 비용 및 미확정 예약은 v5 지출 제한에 합산한다.

모든 버전은 사람 검증이 없는 AI 임시 판단이다. 단어 상한을 늘리거나 응답의 이유를 임의로 잘라 통과시키지 않았다. 키 누락 시 위치를 근거로 대상을 추정하지 않는다.

위 문장의 '상한을 늘리지 않았다'는 v3~v5 당시 처리에 한정한다. v5에서도 Claude가 20단어를 반복 초과하여 다음 변경을 생성 전에 명시했다.

- format-v6: 이유의 절대 상한을 40단어, 권장 길이를 8~20단어로 변경한다. 출력 지시/형식 재요청/검증기/설정/자동시험을 모두 40단어로 일치시킨다. 기존 v3/v5 응답을 소급해 통과시키지 않으며 정확히 동일한 40쌍을 새로 평가한다. 점수체계와 업무 관련도 기준은 그대로다. 이전 버전의 사용액도 누적 비용 제한에 포함한다. 새 정책 파일은 `configs/stage123_query_isolated_format_v6_20261027.json`이다.
- 문맥 검사 오탐: v5 Claude의 D001/AXV2N_0117은 고객 문의와 자동차 제조 검사를 구분했고, 원문의 `vehicle underbodies`, `weld splatter`, `body shop series production`에 제조 근거가 있었다. 문자열 검사에서 제조의 근거 표현 `body shop`, `weld splatter`를 누락한 오탐으로 판정했다. 검사 사전에 두 표현을 추가하고 회귀시험을 남겼다. 원래 경고/응답을 덮어쓰지 않았다. 이것은 사람이 정답을 검증한 기록이 아니라 에이전트의 검사 코드 오류 검토다. 기존 D010/이메일 혼동 반례는 여전히 탐지한다.
- v4 OpenAI 오류 진단의 안전한 요약: `invalid_request_error`, param=`input`, JSON 객체 출력 모드를 사용하려면 사용자 입력에 json 문구가 필요함. 실패한 토큰 계산은 유료 생성 요청이 아니다. 계정 청구서를 조회한 것으로 표현하지 않는다.
