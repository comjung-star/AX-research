# 기존 A/B 추천의 독립 AI 교차검증 — 2026-11-10

## 1. 최종 결론

**아직 ‘다른 AI도 B가 더 좋다고 확인했다’고 말할 수 없다. 교차검증 미완료다.**

Claude는 잔액 부족으로 판정을 하나도 받지 못했다. Gemini는 첫 질문의 일부를 평가한 뒤 무료 일일 요청 한도를 초과했다. 유효한 근거까지 확인된 결과는 Claude **0/330건**, Gemini **21/330건**이다. B가 나쁘다는 결론도, B의 개선이 독립적으로 재현됐다는 결론도 낼 수 없다.

작은 범위지만 경고 신호는 있다. OpenAI와 Gemini의 유용/비유용 판단은 같은 첫 질문의 **21건 중 8건(38.1%)**만 같았다. 이 불일치를 숨기거나 한쪽에 맞춰 재채점하지 않았다.

현재 분류는 **‘개선 미확인 — 교차검증 미완료’**다. 두 방식이 같거나 B가 열세라는 실험 결과를 얻었다는 뜻이 아니다. 기존 OpenAI 기준의 관측 개선과 이번 검증의 미완료를 구분한다.

## 2. 결과 비교표

아래 지표는 **Precision: 추천한 것 중 유용한 사례의 비율**이다. 기존 보고의 F1 31.1%→36.2%와 다른 지표다. 이번 작업에서는 전체 Recall/F1을 새로 계산하지 않았다.

| 채점 기준 | 실제 확보 범위 | A 기본검색 Precision | B 주요관점 Precision | B−A |
|---|---|---:|---:|---:|
| 기존 OpenAI | 기존20질문, A/B 합집합330쌍 재집계 | 54.8% | 64.5% | +9.77%p |
| Claude Sonnet 5.5 | 0/330쌍, 잔액 부족 | 산출 불가 | 산출 불가 | 산출 불가 |
| Gemini 3 Flash Preview | 첫 질문의 유효21/330쌍 | 전체20질문 점수 미확정 | 전체20질문 점수 미확정 | 미확정 |
| Claude·Gemini 합의 | 비교 가능한 공통 판정0쌍 | 산출 불가 | 산출 불가 | 산출 불가 |

OpenAI의 +9.77%p에 대한 **질문20개 단위 paired bootstrap 95% 구간은 +5.52~+14.24%p**다(20,000회, seed20261110). 새로운 독립 AI의 검증 결과가 아니라 기존 OpenAI 판정의 Precision을 재집계한 것이다. 기존 원본 평균 Precision과 일치한다. 단순히 전체 추천254건의 유용 건수를 나눈 micro 평균과 혼동하지 않는다.

기존 OpenAI 기준 질문별 B 개선13 / 악화1 / 동일6개다. B만 찾은 유용한 질문×사례 쌍66개, A만 찾은 유용한 쌍38개로 순증28개다. 같은 사례가 다른 질문에 반복될 수 있다. Gemini에서 현재 확인된 추가 유용 쌍은1개지만 나머지 대부분이 미평가라 전체 이득·손실로 해석하지 않는다. 점수 파일의 Gemini ‘동일4개’는 A/B 목록 자체가 같은4질문의 수학적 동일성일 뿐, 그 질문들을 AI가 채점 완료했다는 뜻이 아니다.

Gemini 첫 질문 VQ001만 보면 A는 원래18개 중 유용하다고 확인된2개와 미확정2개, B는18개 중 확인된3개와 미확정1개다. 따라서 해당 질문의 Precision 범위는 A **11.1~22.2%**, B **16.7~22.2%**다. 같은 미확정 사례의 A/B 판정은 같아야 하므로 차이 범위는 **0~+5.56%p**다. ‘B가3개, A가2개니 전체 개선 입증’이라고 말하지 않는다.

미평가를 가장 유리/불리하게 채우는 전체20질문 민감도에서 B−A 평균은 **−24.04~+24.32%p**, 질문 bootstrap을 결합한 미확정 범위는 **−32.56~+32.72%p**다. 이는 완료된 Gemini 성능의 95% 신뢰구간이 아니라 **자료가 대부분 비어 있어서 결론이 양쪽으로 바뀔 수 있음을 보여 주는 범위**다. Claude와 합의 기준에는 비교 판정 자체가 없어 추정치를 내지 않았다.

## 3. 가장 중요한 발견

### 추천 목록과 검증 범위는 올바르게 고정했다

- 기준 커밋: `bdcaefceb2e7a12fd30da1141fa8a39aaacc226c`.
- 112사례·20질문을 유지했다. 질문마다 A/B 개수가 같으며 각각 총254개 추천이다.
- A/B 공통178쌍을 한 번만 평가하도록 합쳐 **질문×사례330쌍**을 만들었다. 고유 사례69개, 출처 그룹53개다. 같은 사례가 다른 질문에 나오면 별도 질문×사례로 취급하되 통계의 독립 표본 수를 늘리지 않는다.
- A와 B의 원래 순서와 사례를 그대로 복사했다. B의 기본검색 채움분도 유지했다. C는 제외했다.
- 새 검색·관점 생성·후보 재선정·학습·Test15 열람·OpenAI 대체 호출은 하지 않았다.

### 평가자의 해석 차이가 보인다

첫 질문은 지점별 고객 답변 차이와 부서 인계 시 반복 확인 문제다. 아래는 판정이 다른 대표 사례다.

| 실제 사례 업무 | OpenAI | Gemini | 설명에서 보이는 차이 |
|---|---:|---:|---|
| 여러 사내 시스템의 지식 통합 검색 | 2 | 1 | OpenAI는 공통 근거를 찾는 참고로 인정. Gemini는 직원 검색과 고객지원 맥락 유지를 구분함 |
| 상담 통화 내역 요약 | 3 | 1 | OpenAI는 다음 상담원이 맥락을 파악하는 데 도움이 된다고 봄. Gemini는 지점별 답변 불일치를 직접 다루지 않는다고 봄 |
| 직원 신원조회 보고서 검증 | 2 | 0 | OpenAI는 반복 대조 작업의 전이를 인정. Gemini는 고객지원 문제와의 연관성을 인정하지 않음 |

이는 설명을 읽고 정리한 **가능한 해석 차이**이며 누가 정답인지 재판정한 것이 아니다. 특히 ‘도움이 될 수 있으나 직접적이지 않다’며1점을 준 이유는2점의 전이 가능성 기준을 좁게 해석했을 가능성이 있다. 반대로 OpenAI가 업무 간 연결을 너무 넓게 인정했을 가능성도 있다. 이번 소표본으로 어느 쪽이 옳다고 결정할 수 없다.

21쌍의 정확한0~3점 일치는 **2/21(9.5%)**, 유용/비유용은 **8/21(38.1%)**다. 유용 여부가 다른13쌍은 모두 OpenAI가 유용, Gemini가 비유용으로 판정했다. 단순 kappa −0.087, 이차가중 kappa0.316이며 첫 질문에 한정된 기술 통계다. 출처 그룹별 동일 가중 유용 일치는32.4%(17그룹)다. Claude·Gemini 일치도는 **0%가 아니라 계산 불가**다.

또한 기존 OpenAI는 P/T/C 요약과 관점 정의를 받았고, 이번 Gemini는 사용자 요청에 따라 실제 구현·상태·출처 인용까지 받았다. 기존 프롬프트는 ‘다른 측면의 합리적 참고’를 더 구체적으로 허용했다. 따라서 OpenAI와의 차이를 **모델만 바뀐 효과로 분리할 수 없다.** Claude/Gemini에 준비한 새 기준과 자료는 서로 동일하다.

### 막힌 이유는 분리해서 기록했다

| 항목 | 실제 발생 | 처리 |
|---|---|---|
| 모델 목록 연결 | 두 제공사 모두 접근 가능 | 모델 조회 성공은 크레딧/생성 가능 보증이 아니라고 기록 |
| Claude 실제 채점 | HTTP400, `credit balance is too low` | 첫 요청에서 중단, 다른 모델로 대체 안 함 |
| Gemini 첫 응답 | 23개 판정 중15개가 근거 인용 검사 통과,8개 실패 | 정상15개 보존, 실패8개만 한 번 기술 복구 |
| Gemini 기술 복구 | 8개 중6개 통과,2개는 인용 불일치 지속 | 유효21개 확정,2개는 미확정 유지. 정상 판정 재채점 없음 |
| Gemini 다음 질문 | HTTP429, 무료 일일 요청20회 한도 초과 | 즉시 중단. API가 안내한 약7시간32분 뒤까지 기다려 우회 실행하지 않음 |

첫 계획의 ‘잘못된 배치 전체를 동일 본문으로 한 번 재전송’은 사용자 지시인 **정상 판정 재사용·불필요한 중복 방지**에 맞춰 실행 방법만 수정했다. 정상15개를 제외하고 실패8개만 같은 기준·같은 사례 사실로 요청했다. 배치 구성은 달라졌으므로 바이트까지 같은 전체 요청 재전송이라고 주장하지 않는다. 평가 기준·모델·분석 규칙은 그대로다. [수정 기록](execution-amendment.json)을 추가 호출 전에 남겼고, 결과를 개선하려는 재채점은 하지 않았다.

일부 인용은 `·`를 `&#183;`로 쓴 형식 문제였고, 일부는 제공 문장과 다른 표현이었다. 동결한 정확 인용 검사를 사후에 느슨하게 바꾸지 않았다. 근거 검사 실패를 ‘관련 없음0점’이나 AI의 `ABSTAIN`으로 바꾸지 않았다. 실제로 받은 AI ABSTAIN은0건이다.

Gemini가 답을 생성한 고유 쌍은23개다. 복구8개를 포함한 원시 판정 시도31개를 독립31표본이나 유효31개로 세지 않는다. 최종 유효 판정은 각 쌍당 하나만 쓴다. 요청이 거절된 VQ002의26쌍을 포함해 Gemini에 전송을 시도한 고유 쌍은49개지만, 그것이 채점 완료49개라는 뜻은 아니다.

## 4. 신뢰성 판단과 논문에서의 표현

지금 쓸 수 있는 표현:

> 동일 합성20질문과 기존 OpenAI 관련도 평가에서는 B의 평균 Precision이 A보다9.77%p 높았다. 독립 제공사 교차검증은 Claude 잔액 부족과 Gemini 무료 할당량으로 미완료다. 확보한 Gemini 첫 질문의 유효21쌍에서는 기존 평가와 유용 여부 일치가38.1%여서 평가자 해석 차이를 추가 확인할 필요가 있다.

지금 쓰면 안 되는 표현:

- ‘Claude·Gemini가 B의 우수성을 확인했다.’
- ‘3종 AI 정답이 검증됐다’ 또는 ‘AI 합의가 인간 정답이다.’
- ‘Gemini의 전체20질문 성능이 낮다’ 또는 ‘Gemini 때문에 B가 나쁘다고 밝혀졌다.’
- ‘전체 Recall/F1을 독립 평가로 새로 확정했다.’

Bootstrap은 질문20개를 재표집했으며 같은 사례의 반복을 새 독립 질문으로 세지 않았다. 질문군·출처의 상관, 합성 질문의 편향, 이미 선택에 사용한 검증 자료라는 한계는 남는다. [출처 그룹 기여 제거 민감도](source-group-sensitivity.json)는 고정K에서 해당 그룹의 순기여만 빼 본 기술 분석이며 새 검색 결과나 독립 군집 추론이 아니다.

## 5. 남은 작업 — 꼭 필요한 것만

1. **연결 조건부터 해결:** Claude API 크레딧 확보, Gemini 일일 한도 복구 또는 사용자 계정의 적절한 사용 한도 확보. 이번 작업은 결제·할당량 설정을 변경하지 않았다.
2. **같은 평가를 이어가기:** Claude330쌍, Gemini 답을 받지 못한307쌍을 기존 질문·추천·기준·입력 그대로 이어간다. Gemini 유효21개는 재사용하고, 한 번 복구 후에도 근거 오류가 남은2개는 미확정으로 유지한다. [남은 작업 목록](pending-jobs.json)을 참고한다.
3. **완료 후 한 번 분석:** 각 평가자 Precision,20질문 차이·신뢰구간, 평가자 일치도, 합의/불일치/ABSTAIN 민감도를 다시 계산한다. 원하는 결론이 될 때까지 기준이나 추천을 바꾸지 않는다.

현재 자료로 알고리즘을 고치거나 관점 목록을 늘릴 필요성을 확정하지 않는다. 먼저 평가를 끝내야 한다.
