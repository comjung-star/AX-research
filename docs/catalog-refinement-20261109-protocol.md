# 사례 선별 보완: 승인된1~4단계의 고정 실험

## 범위

기존4관점·17사례·승인연결을 유지한다. 전체112 확장은 하지 않는다. 기존 동결 코드·응답·정답표는 수정하지 않는다. 별도 모듈로 문장/입력 해석 오류와 질문−사례 비교를 구현하고, 한 번의 고정 비교 후 종료한다. 교수 전체 모델의 대체·완성 주장은 하지 않는다.

## 1. 해석 오류

한국어 단어 내부의 ‘안하’를 금지로 오인하지 않게 안 부정어 앞 경계를 확인한다. 실제 ‘안 합니다’ 등 명시 부정은 보존한다. ‘통화 녹취 텍스트/전사문/대화록’은 이미 문자화된 입력으로 취급하되 같은 질문의 별도 음성 입력은 유지한다. 기존 절 구분·읽기전용·시간·PDF 조건은 가능한 그대로 사용한다. 이것은 완전한 의미 파싱이 아니며 긴 복합절 한계를 남긴다. 추천 점수와 분리한 기능 검사를 먼저 통과시킨다.

## 2. 사례별 정밀 선별

Claude Sonnet5.5/high가 질문과17개 사례의 Problem/Task/Context만 보고 각 사례의 실제 수행 업무·자료·기준·명시 조건을 비교한다. 관점명·연결·정답·검색 순위는 보내지 않는다. 고정 fit0~3과 SUPPORTED/CONDITION_UNKNOWN/UNSUPPORTED를 반환한다. fit>=2와SUPPORTED만 제시한다. fit1은 단순 목적·기술·보조 작업 겹침이며 quota를 채우기 위해 넣지 않는다. 양성 판단에는 질문 원문과 수행 Task 원문의 연속 인용을 요구한다. 문자 일치 검사가 의미 정확도를 인증하는 것은 아니다.

동일17개에 대한 한 번의 fit 응답을 모든 절제 조건이 공유한다. fit은 이번 모델의 예측이며 평가 정답으로 쓰지 않는다. 동일 fit 안에서 기존 질문전체−Task cosine, 사례ID 순으로 정렬한다. 임계값 fit2는 성능 확인 전에 고정하며 새로운 수치 임계값이나 학습 가중치를 탐색하지 않는다. 관점 분기는 최종 배정까지 유지하고 중복 사례는 출처를 합친다.

## 3. 후보 범위 비교

B: 기존 업무 중심 검색. E: 직전 LLM 관점 추천. J: E에 해석 오류만 고친 조건. F: J의 관점별 후보에 fit 선별. G: F와 전체17개 검색 후보를 함께 검토. H: G의 전역 후보와 동일한 fit/조건을 사용하되 관점별 대표 배정 없이 전역 점수순으로 제시하는 보조 조건이다. H를 함께 두어 G의 이득이 단순 LLM 선별 덕분인지 확인한다. H의 조건 판정은 G와 공유하므로 관점 정보와 완전히 독립적인 모델이라고 부르지 않는다.

관점 밖 후보도 원문 fit과 명시 조건을 확인한다. 이미 관점별 조건을 통과한 사례는 그 판정을 보존하고, 나머지 후보는 단일 작업이면 전역 조건을 적용한다. 여러 작업에 입력 조건이 섞여 적용 범위가 불명확한 전역 후보는 보류한다. 동일 업종만/직접 사례만/읽기 전용 제약도 보존한다. 모든 조건 후보<=20·최종<=5이며 부족하면 비운다. 17개보다 큰 예산이므로 원래 후보Recall20=1은 개선 근거가 아니다.

## 4. 개발 재비교와 새 질문

기존60개는 이미 관찰한 개발 자료로만 재비교한다. 기존20개 original/working/부분464검토와40개 Claude/Gemini 표를 그대로 각각 사용한다. 부분 검토표와 AI Silver를 전체 사람 Gold로 부르지 않는다. 선택기의 기존60개 응답은 재사용한다.

모델·지시문·정책을 동결한 **뒤** Gemini3.1Pro/high에게 사례·이전 질문·실패·순위를 주지 않고 새 질문12개를 한 번 생성하게 한다. 설명한4개 업무의 각2개, 복수업무2개, 범위밖2개를 요청한다. 사례 맞춤 질문이 아니라 관점 범위를 고려한 AI 작성 시범 질문이다. 원문을 고치거나 성공 질문만 선별하지 않는다. 기존 질문과 문자 중복/유사도를 기록하고, 이 검사가 의미적 독립성을 보장하지 않음을 명시한다. 현재 버전 개발에 사용하지 않은12개로 분리하되 공식 최종 held-out 또는 실제 현업 질문이라고 부르지 않는다. 봉인 Test15는 열지 않는다.

새12개 선택에는 기존 관점 선택기/프롬프트를 그대로 호출한다. 검색·선별 출력과 벡터를 저장한 뒤, 별도의 ClaudeSonnet5.5/high와 Gemini3.1Pro/high가 질문과17개 원문을 보고 독립 요청으로 채점한다. 방법명·모델 예측·추천 순위·관점·기대 결과는 숨기고 사례 순서는 고정seed로 섞는다. grade>=2를 양성으로 고정하고 비교 가능한 실제 핵심 기능의 전이만 인정한다. 소스에 없는 핵심 능력·필수 조건을 추가해야 하면1이하다. 두 공급자가 같아질 때까지 반복하거나 타협 정답을 만들지 않는다.

Claude는 선별 모델과 공급자가 같고 Gemini는 질문 작성자와 공급자가 같으므로 완전 독립 인간 평가가 아니다. 공급자별·동일 양성 질문·양성 교집합/합집합 민감도를 각각 보고한다. AI 자체 판정 일치로 실제 정답 인증을 주장하지 않는다.

## 지표·비용·종료

기존 정의의 F1@5(실제출력수 분모), Recall@5, nDCG@5(grade>=2 gain), 슬롯P5, 제시 수·적중 수·양성인데 빈 답·음성 질문의 출력 수를 보고한다. 양성 없는 질문은 F1/nDCG 평균에서 NA이고 출력 회계에는 포함한다. 사전 비교 J−E/F−J/G−F/G−B/G−E/G−H의 질문별 bootstrap seed20261109/10000회와95%구간을 계산한다. 탐색·다중검정 보정 없는 개발 기술통계이며 작은 새12개도 확정적 검정으로 해석하지 않는다.

최대 호출은 작성1+새 선택12+fit72+새 채점24=109회이며, 실제 본문 UTF8바이트+8192 여유를 입력 토큰 상한으로 예약하고 출력 cap을 모두 예약한다. fit/채점/작성 출력 cap6144, 선택4096이다. 총 예약은$15 이하, 자동 재시도0이다. 단가 Claude 입력2/출력10, GeminiPro 입력2/출력12 달러/백만(200k미만), 생각 토큰 포함이다. 실패·불명확 전달은 보존하고 예약을 유지한다. 주어진 한도에 맞지 않으면 호출을 시작하지 않는다. 모델 추가 학습·새112라벨은 없다.

개선의 채택은 단순 검색 대비 성능·누락·조건 충족의 균형과 새 질문의 결과를 함께 보고 판단한다. G=H이면 이번 성능 이득을 관점의 추가 가치라고 주장하지 않는다. 유리한 공급자나 지표만 골라 결론내리지 않는다. 결과를 보고 프롬프트·기준·정답을 고쳐 반복하지 않고 원본·수치·실패·남은 가설을 보고한 뒤 종료한다.
